# Link

Компактный Windows desktop companion на C#/.NET 10 и WPF. Вы работаете в Unreal, Blender, IDE или браузере, а Link
висит маленьким overlay поверх: собирает нужный контекст — текст, голос, скриншоты, clipboard, текущее приложение —
отправляет его в связанную беседу ChatGPT и показывает ответ, не заставляя переключаться в окно чата.

**UI для пользователя — Link. Встроенная страница ChatGPT или API — внутренняя реализация.**

## Возможности

**Overlay**
- frosted-glass always-on-top: перетаскивание, ширина 320–1200 px, высота по содержимому; нижним краем задаётся
  предел роста (двойной клик по нему возвращает компактный режим); click-through, прозрачность;
- **Hide** — кнопка `—` в заголовке, двойной клик по заголовку или `Esc`, когда Link ничего не делает: Link прячется
  целиком, начатый ответ дописывается. Вернуть — hotkey показа (`Ctrl+Alt+Space`) или tray;
- **Expand** — кнопка панели в заголовке: рядом с карточкой открывается панель проекта (ниже). Она встаёт на ту
  сторону, где на мониторе больше места, ходит за карточкой и прячется вместе с ней; внешний край задаёт ширину;
- tray, один экземпляр, глобальные hotkeys (все меняются в Settings); позиция и размер сохраняются на нескольких
  мониторах;
- `Enter` отправляет, `Shift+Enter` — новая строка; во время ответа кнопка отправки и `Esc` останавливают запрос и
  генерацию в ChatGPT;
- иконка в tray показывает, что происходит: голубая точка — идёт запрос, красная — Link ждёт вас (вход в ChatGPT или
  запрос не удался, пока Link был скрыт), зелёная — ответ пришёл, пока Link был скрыт (гаснет, когда Link покажется);
  подсказка иконки — строка статуса. Если Link скрыт или неактивен, о готовом ответе ещё и сообщает уведомление
  Windows; клик открывает нужный проект;
- короткие звуки (до 150 мс): слушаю, отправлено, нужно ваше решение, готово, ошибка. Пока Link говорит, звучит
  только «нужно решение»; выключаются в Settings → Behavior.

**Agent**
- работу, а не ответ, делает CLI-агент на выбор: **Claude Code** или **Codex**. Link их не ставит и не входит в них:
  нужен `claude auth login` или `codex login` один раз. Settings → Agents показывает, найден ли агент, вошли ли вы и
  его версию; там же — агент по умолчанию и свой путь к exe;
- маршрут **Agent** в метке `[Chat ▾]` (метка показывает агента: `Claude · read`), `Ctrl+Enter` в поле или подсказка
  `↳ Agent?`, которая загорается на глаголах действия («исправь», «сделай», «fix»…) — всё открывает карточку в боковой
  панели: цель (правится), агент, доступ, проект и рабочая папка, «Сначала план», копия перед изменениями, вложения.
  Без Run ничего не запускается;
- доступ по умолчанию — **только чтение** (Claude `dontAsk`, Codex `read-only`); **изменения** выбираются для задачи
  (Claude `acceptEdits`, Codex `workspace-write`). `bypassPermissions` и `danger-full-access` не используются никогда;
- **Activity**: агент, доступ и время, текущий шаг, шаги, изменённые файлы («показать в Explorer»), итог, лог CLI;
  **■ Stop** виден всё время и останавливает агента со всеми его процессами; после выхода из Link их тоже нет;
- отказ Claude в инструменте → «Allow and retry» (продолжение той же сессии; «Always allow for this project»
  запоминает правило); Codex упёрся в read-only → «Retry with edits»; «Сначала план» → «Run the plan»;
- **откат**: в git — «Undo agent changes» только для файлов, которые до задачи были чистыми (ваши правки не
  трогаются); без git — копия рабочей папки перед изменениями (до 2 ГБ, без `bin`, `obj`, `node_modules` и т. п.) и
  «Restore the copy». Всё — после подтверждения;
- `↻ Agent` на ответе Chat — та же задача агенту из того же снимка; `↻ To chat` после агента кладёт итог и список
  файлов в context stack — следующий вопрос уходит в ChatGPT с ними;
- **харнесс всегда** — каждая новая сессия агента начинается с правил агента (`harness\agent-rules.md` рядом с
  `Link.exe`, правится без пересборки), что бы ни лежало в рабочей папке; `AGENTS.md` в папку класть не нужно.
  Claude Code там же получает список skills рабочей папки, Codex находит их сам;
- **цифры задачи** — строкой под итогом: ходы, вызовы инструментов, из них поиски (и сколько до первой правки),
  ошибки инструментов, токены (сколько из кэша) и стоимость по ценам API (Codex её не сообщает); те же числа — в
  строке `[Agent]` link.log. По ним видно, что из харнесса экономит. Codex, продолжая сессию, считает токены всей
  сессии — такие числа помечены «for the session»;
- **карта проекта** — Write map / Update map у рабочей папки: агент в режиме чтения осматривает папку и отвечает
  картой, Link пишет её в `docs/map.md` (до ~80 строк: что где лежит, как собрать и проверить, соглашения). Это
  единственное изменение, оно в Activity и откатывается как обычно; правила агента велят читать карту
  первой. Задание агенту — `harness\map-task.md` рядом с `Link.exe`, правится без пересборки;
- **проверка после изменений** — поле Check after edits у рабочей папки: своя команда (сборка, линтер,
  smoke-тесты). После задачи с изменениями Link запускает её как есть в рабочей папке (через cmd.exe, до 10 минут,
  Stop работает); красная — агент продолжает сессию с концом её вывода, не больше двух раз, и задача кончается
  «Check failed», а не «Done». Проверка — дело Link: карточка говорит, что она будет, и агенту в задаче сказано
  одной строкой, что Link запустит её сам, — гонять и менять её агенту не нужно (Codex в своей песочнице не может
  запустить, например, браузерную проверку). Вывод проверки в link.log не пишется;
- **петли** — Activity помечает «Looks like a loop: …»: тот же вызов 3 раза без правок между ними, та же ошибка
  3 раза подряд, 12 поисков подряд без правки (только с изменениями). Агент не останавливается — решаете вы;
- **Start over with a note** — рядом с меткой петли и после провала: агент (если работает — после Stop) пишет в пяти
  строках, что пробовал и почему не вышло, и новая сессия берёт исходную задачу с этой заметкой, тем же доступом и
  папкой, вместо продолжения замусоренной истории;
- голосом агент говорит только старт, нужное решение и итог в 1–2 фразы; скрытый Link сообщает о нём иконкой tray,
  звуком и уведомлением.

**Контекст**
- скриншоты: текущий монитор, весь рабочий стол, каждый монитор, активное окно, выбранная область (одна за раз);
  Auto active window в меню Screen делает свежий снимок рабочего окна для каждого запроса Chat;
- clipboard и данные текущего приложения в видимом context stack;
- проекты (по умолчанию General) и их панель: текущая задача (в карточке — чип), состояние проекта (цель, решения,
  факты, ссылки на беседы; дата — когда правили), связанная беседа, рабочая папка (выбирается явно, пригодится
  агенту) и 10 последних вопросов и ответов — клик показывает ответ в карточке. Состояние уходит в запрос чипом
  «Project state» в context stack: его можно убрать для одного запроса, после ответа он возвращается;
- рабочее приложение фиксируется в момент вызова Link: просмотр ChatGPT и скрытие Link при захвате экрана его не
  подменяют.

**Голос**
- push-to-talk: слова появляются в поле, пока вы говорите (локальный распознаватель, RU или EN), после отпускания
  Whisper заменяет черновик финальным текстом — large-v3-turbo на видеокарте, Base на CPU; запись без речи в Whisper
  не идёт;
- выбор и тест микрофона — Settings → Microphone;
- голосовой ответ на продиктованный вопрос: Link читает ответ по мере его прихода — первую фразу, пока ChatGPT
  пишет дальше; код и таблицы не читает («Код — на экране.»), длинный ответ обрывает примерно через минуту речи. При
  долгом ожидании говорит короткую фразу («Секунду.»). Push-to-talk во время речи перебивает; Esc и Stop сначала
  заглушают, повторно — останавливают запрос. Кнопка **Listen** на ответе читает его заново, во время речи она же —
  Stop; по желанию озвучиваются и ответы на набранные вопросы (Settings → Voice replies → «…and when I type»);
- голос ответа (Settings → Voice replies → Voice engine): **Gemini** 3.8 Flash-Lite TTS — естественный, нужен свой
  бесплатный ключ из aistudio.google.com/apikey (хранится зашифрованным для вашей учётной записи Windows); в Gemini
  уходят только слова, которые Link произносит, а на бесплатном тарифе Google может использовать их для улучшения
  своих продуктов. Звук Gemini бывает медленнее, чем играется, поэтому Link начинает говорить, накопив 2 с звука:
  первое слово на 2–3 с позже, зато без рывков. **Локальный голос** Supertonic 3 — офлайн, скачивается кнопкой
  (145 МБ); без ключа Gemini и без скачанной модели Link не говорит, ответ остаётся на экране. В режиме Auto, если
  Gemini недоступен (лимит, сеть, ключ), говорит локальный голос, а статус коротко сообщает почему;
- **Conversation** — разговор без рук: метка под полем, Settings → Voice или `Ctrl+Alt+Shift+Space`. Пока Link
  свободен, он слушает сам; пауза ~0,65 с после фразы — короткий сигнал «услышал», Whisper распознаёт только фразу, и
  она уходит выбранным маршрутом. Ответ звучит всегда (даже с выключенным Voice replies), в Chat — с просьбой начать
  коротко и разговорно; потом Link снова слушает. Пока идёт запрос и пока Link говорит, микрофон закрыт;
  push-to-talk перебивает ответ, работает и пока ChatGPT думает (новые слова уйдут после ответа) и может сам закончить
  фразу; Send заканчивает её сразу. Нажатая в поле ввода клавиша ставит прослушивание на паузу — можно печатать; Link
  слушает снова после отправки, очистки поля или ухода из него. Нераспознанную фразу просто повторите. Включённый режим
  остаётся включённым и после перезапуска Link; выключенный ничего не слушает.

**ChatGPT**
- ChatGPT живёт во встроенном окне Link (WebView2): браузер держать открытым не нужно, ответ печатается с полной
  скоростью — сотни символов в секунду, а не 3–5, как в фоновой вкладке. **Open chat** в панели показывает окно на
  связанной беседе; закрытое окно Link убирает за край экрана, и оно продолжает работать. Точка у названия проекта в
  заголовке — состояние ChatGPT: зелёная — на связи, красная — нужен вход или ChatGPT недоступен;
- под полем две метки — маршрут и уровень ответа. **Chat** добавляет к вопросу то, что знает Link: проект, задачу,
  состояние проекта, рабочее окно и его снимок (Auto active window), подсказку уровня. **Direct** отправляет только
  текст и то, что вы приложили сами, — так видно, помогает ли обвязка Link; чипы задачи и состояния в Direct скрыты.
  Уровень **Fast / Normal / Deep** переключает и режим ChatGPT: Fast ставит самый лёгкий, Normal возвращает ваш;
- ответ приходит потоково и восстанавливается как Markdown: код, списки, таблицы, ссылки; ссылки из ответа
  открываются в браузере по умолчанию;
- запрос не зависает: статус в шапке ответа (Sending, Waiting for response, Receiving, Reconnecting, Cancelled,
  Error) и понятные ошибки; после перезагрузки страницы ответ подхватывается без повторной отправки;
- **Check chat** забирает ответ прямо из чата, если он не дошёл; Link и сам проверяет чат после 20 с тишины;
- **↻ Deeper · ↻ Direct · ↻ Fresh screen** под ответом, ошибкой или Stop отправляют тот же вопрос ещё раз в ту же
  беседу: на Deep, через Direct или через Chat с новым снимком рабочего окна. Текст, вложения, clipboard и окно Link
  берёт из снимка ввода, сделанного при отправке: ничего не нужно набирать, диктовать или копировать заново. Снимки
  трёх последних вопросов каждого проекта Link держит вместе с их файлами. **✎ Edit** возвращает вопрос в поле —
  исправить, например, ослышку распознавания; Enter спрашивает исправленный текст с тем же снимком экрана и
  вложениями, Esc отменяет;
- **New chat** в панели (или в окне выбора беседы): следующее сообщение начинает новый чат — в том же проекте
  ChatGPT, что и текущий, — и Link сам связывает с ним проект. Вариант «with a summary of this one» сначала просит
  текущий чат написать краткую выжимку (цель, решения, состояние, следующий шаг); она ложится в context stack и уходит
  с первым сообщением, её можно убрать. Когда длинный чат начинает отвечать медленно, статус подсказывает начать
  новый.

## Запуск

Нужны Windows 11 и .NET 10 SDK:

```powershell
dotnet build Link.sln --configuration Release
dotnet run --project src/Link.Desktop/Link.Desktop.csproj
```

Проверки логики без микрофона и настоящего ChatGPT — консольный раннер, код выхода равен числу ошибок. Он же
прогоняет companion на мок-страницах ChatGPT в headless Edge или Chrome (без них эти проверки пропускаются).
CI запускает раннер после сборки.

```powershell
dotnet run --project tests/Link.Desktop.Tests
```

`Alt+F4` прячет Link в tray, завершить его — `Exit` в меню tray. Перед пересборкой в `bin\Release` завершите Link:
запущенный `Link.exe` блокирует файл, а второй запуск только покажет «Link is already running». Номер сборки — внизу
Settings.

### Подключение ChatGPT

1. Запустить Link, открыть панель (кнопка Expand в заголовке) и нажать **Open chat**.
2. В открывшемся окне войти в свой аккаунт ChatGPT — один раз: вход хранится в профиле `%LocalAppData%\Link\WebView2`.
3. Открыть нужную беседу в окне ChatGPT, закрыть окно, в панели нажать строку беседы, выбрать беседу и нажать
   **Link**. Или сразу нажать **New chat** — первое сообщение из Link создаст беседу и свяжет её с проектом.

Пока ChatGPT не вошёл в аккаунт, точка у проекта красная, а статус пишет «Sign in to ChatGPT». Проектам, связанным
раньше через браузерное расширение, заново связываться не нужно, а само расширение больше не нужно — его можно
удалить из браузера. Как companion работает со страницей и что пишет в диагностику —
[`companion/README.md`](companion/README.md).

### Hotkeys по умолчанию

| Действие | Hotkey |
|---|---|
| Показать/скрыть | `Ctrl+Alt+Space` |
| Push-to-talk | `Ctrl+Alt+V` |
| Отправить запрос | `Ctrl+Alt+Enter` |
| Весь desktop | `Ctrl+Alt+D` |
| Активное окно | `Ctrl+Alt+W` |
| Выбор области | `Ctrl+Alt+Shift+R` |
| Conversation вкл./выкл. | `Ctrl+Alt+Shift+Space` |

Совет: клавиши `F13`–`F24` работают как hotkey без модификаторов — удобно повесить push-to-talk на кнопку макропада
или педаль (назначьте им F13–F24 в их программе, затем запишите клавишу в Settings).

## Локальные данные

`%LocalAppData%\Link`:

- `settings.json` — UI, панель, hotkeys, голос и звуки;
- `projects.json` — проекты: задача, состояние, рабочая папка, связанная беседа и её последний ответ; `Projects\<id>\`
  — папка проекта, в ней `history.json` с 10 последними вопросами и ответами;
- `Screenshots\` — ограниченная история PNG; снимки рабочего окна для Auto active window живут, пока Link держит их
  вопрос для перенаправления, и удаляются при выходе; `Recordings\` — последние WAV;
- `Models\` — модели распознавания речи;
- `Backups\` — копии рабочих папок без git перед изменениями агента, 5 последних;
- `WebView2\` — профиль встроенного ChatGPT: вход и cookies; `companion-state.json` — режимы ChatGPT, которые
  выставил Link;
- `last-request.json` — последний запрос: текст, пути вложений, заголовок окна. Пишется только с диагностикой
  (Settings → Behavior → Diagnostics, по умолчанию выключена); без неё Link этот файл удаляет;
- `link.log` — неожиданные ошибки и диагностика ChatGPT (UTF-8, до 1 МБ); строка `[Chat]` на каждый запрос
  (маршрут и уровень, подготовка в Link, приём страницей, первый текст, скорость ответа), строки `[TTS]` — путь
  каждой фразы до звука, строки `[Voice]` — сколько микрофон слушал (с клавишей или hands-free), CPU Link за это время
  и как быстро фраза стала текстом; строка `[Agent]` на каждый прогон агента (агент, доступ, итог, session id, время
  до первого события и всего, число файлов, отказы; без текста задачи).

## Архитектура

```text
src/Link.Desktop/
├── Models/        settings, projects, context и PromptRequest
├── Services/      storage, запрос, chat integration, голосовая сессия, STT и TTS
├── Windows/       Win32: hotkeys, стили окон, GDI capture, waveIn + список устройств, tray
├── MainWindow*    overlay; части по темам: Chat, Capture, Voice, Sizing, Panel
├── SidePanelWindow*, ProjectPanel*  панель рядом с карточкой (своё окно) и её содержимое Project/Context
├── ChatPageWindow встроенная страница ChatGPT (WebView2) за краем экрана
├── SettingsWindow*, RegionSelectionWindow*, ...
companion/                  content.js работает с DOM ChatGPT во встроенной странице
tests/Link.Desktop.Tests/   проверки логики без тестового фреймворка
tests/companion/            проверки companion на мок-страницах ChatGPT
```

- Отправка: окно собирает `InputSnapshot` (текст, context stack, рабочее окно, его снимок), `AttemptCoordinator`
  строит из него `PromptRequest` по маршруту и уровню, отправляет, пишет строку `[Chat]` и хранит последний ответ
  проекта; перенаправление — новая попытка из того же снимка.
- `PromptRequest` и контекст принадлежат Link; `IChatIntegration` отделяет их от транспорта. Для ChatGPT это
  `EmbeddedChatIntegration`: страница ChatGPT в собственном окне Link, где `content.js` работает поверх
  `embedded-host.js` и говорит с Link через канал WebView2. Жизнь запроса (повторная выдача, тишина, Stop,
  Check chat) ведёт `ChatRequestBroker`.
- Окно страницы никогда не прячется и не сворачивается — иначе движок притормозит страницу, — а ждёт за краем экрана
  с флагами Chromium против фонового троттлинга.
- `VoiceSession` — единственный владелец голосового состояния (Idle → Listening → Finalizing → Sending → Waiting →
  Speaking); UI только отображает фазу и черновик. Один захват waveIn кормит и WAV для Whisper, и live-распознаватель.
  В Conversation окно открывает микрофон hands-free, когда Link свободен; конец фразы слышит Silero VAD.

## Ограничения

- **ChatGPT.** В очень длинной беседе ChatGPT сам отвечает медленно: первое слово через 15–25 с, дальше несколько
  символов в секунду — и в Link, и в самом ChatGPT. Новый чат отвечает за 2 с и печатает ~250 символов в секунду:
  когда беседа разрослась, начните новую (New chat, при нужде — с выжимкой). Выжимку пишет старый чат, поэтому в
  длинном она занимает пару минут. Встроенная страница — это процессы Edge WebView2: сразу после ответа 650–750 МБ
  памяти. Через полминуты без запросов она «отдыхает»: не рисуется, CPU почти ноль, память — около 450 МБ; к
  следующему запросу просыпается сразу. Раз в 6 часов простоя Link загружает её заново.
- **DOM ChatGPT.** Конец ответа companion узнаёт по нескольким признакам, а при смене разметки пишет в `link.log`, что
  видела страница. Переключение режима эвристическое: если не вышло, статус пишет «ChatGPT mode not switched (…)», а
  подсказка всё равно уходит в запрос.
- **Голос.** При первом использовании скачиваются модели (Whisper Base 148 МБ; turbo 574 МБ, если есть видеокарта с
  Vulkan; live-модели 30–45 МБ; всё проверяется по SHA-256). Нужен Microsoft Visual C++ Redistributable 2022 x64.
  Бесплатный тариф Gemini ограничен по запросам: при исчерпании Link минуту–час говорит локальным голосом.
  Локальный голос, пока говорит, держит ~300 МБ памяти и выгружается через 3 минуты тишины. В Conversation
  микрофон открыт, пока Link свободен: слушание (VAD и live-черновик) — 4–5 % одного ядра, столько же, сколько при
  удержании push-to-talk; разговор или видео рядом Link может принять за вопрос — тогда выключите режим. Эхоподавления
  нет: перебить ответ голосом нельзя, только push-to-talk.
- Чат — только ChatGPT; Claude и Codex появятся как агенты для действий, а не как чат.
- Защищённый (DRM/UAC) контент может захватиться пустым — ограничение Windows/GDI.
