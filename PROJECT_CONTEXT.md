# Link — Project Context

Продукт, принятые решения и открытые вопросы. Правила работы с кодом — `CLAUDE.md`; для пользователя — `README.md`;
ChatGPT-транспорт в деталях — `companion/README.md`; голос — `docs/VOICE_CONVERSATION_PLAN.md`.
История изменений — в `git log`.

## Что мы создаём

**Link** — персональный Windows desktop companion: маленький overlay поверх рабочего приложения (Unreal, Blender,
IDE, игра, браузер). Он знает активный проект и текущую задачу, по запросу берёт контекст экрана, clipboard, голоса и
текущего приложения, отправляет его в связанную AI-беседу и показывает ответ — без ухода в окно чата. Цель —
маленький персональный «Jarvis»; позже — память проектов, команды и локальные действия.

**UI для пользователя — Link. Встроенная страница чата (WebView2), API — внутренняя реализация, которую в обычном
сценарии не видно.**

```text
current app / screen / clipboard / voice → Link (Context Brain) → Chat Integration Layer
→ existing AI conversation → response → Link overlay / TTS / action
```

Название — «связь» и отсылка к Link из Zelda; визуальную айдентику Nintendo не копировать.

## Принципы

- Windows-first; быстрый старт и мало ресурсов: это приложение на весь день.
- Маленький floating companion, а не полноразмерный чат-клиент; пользователь остаётся в своём приложении.
- Local-first там, где разумно: настройки, память, скриншоты, голос, команды.
- Экран и микрофон — только по явному действию или режиму; что уходит в запрос, пользователь видит и может убрать.
- Транспорт заменяем (встроенная страница чата, API, локальная модель): `PromptRequest` и контекст
  принадлежат Link, транспорт — за `IChatIntegration`.
- По возможности — существующие чаты и подписка пользователя, а не обязательный API-бюджет.
- Простота важнее overengineering; фичи — этапами, зависимости — только под реализуемую фичу.

## Направления и статус

- **Overlay** — сделано: frosted-glass always-on-top, drag, ширина 320–1200 px, высота по содержимому до выбранного
  предела, collapse, click-through, прозрачность, tray, переназначаемые hotkeys.
- **Vision** — сделано: монитор, весь desktop, каждый монитор, активное окно, область (одна за раз), Auto active
  window на каждый Send. Позже, если понадобится, — Windows Graphics Capture.
- **Voice** — сделано: push-to-talk, live-черновик, финальный Whisper, голосовой ответ по мере прихода текста.
  Дальше: локальный TTS и Conversation Mode — `docs/VOICE_CONVERSATION_PLAN.md`.
- **Projects** — сделано: проекты (по умолчанию General), текущая задача, связанная беседа, последний ответ.
  Дальше: память проекта, решения, открытые вопросы, summaries, локальные файлы и папки.
- **Context Brain** — сделано: видимый context stack (скриншоты, clipboard, текущее приложение). Дальше: уровни
  GLOBAL → PROJECT → DECISIONS → CURRENT TASK → CHAT SUMMARIES → LIVE и context router по релевантности.
- **Chat bridge** — сделано: ChatGPT во встроенной странице WebView2; путь через браузерное расширение убран.
  Дальше: Claude-адаптер.
- **Handoff / compaction** — начато: New chat с необязательной краткой выжимкой старого чата (цель, решения,
  состояние, следующий шаг, вопросы). Дальше, если понадобится: варианты Full / Tiny и правила проекта.
- **Decision memory** — нет: решения отдельно от summaries (active/deprecated), отдельно open questions.
- **Commands** — нет: command palette, quicklinks, script commands (PowerShell/Python/EXE), локальные действия без AI.

## Стек

C#, .NET 10, WPF, Win32; один assembly (`Models`, `Services`, `Windows`, presentation) — отдельные assemblies не
заводить, пока размер не требует. Зависимости: `Whisper.net` (CPU и Vulkan runtime), `org.k2fsa.sherpa.onnx`
(live-черновик и VAD; сборка только win-x64), `System.Speech` (голоса Windows), `Microsoft.Web.WebView2`
(встроенный ChatGPT на Evergreen Runtime из Windows 11). Только под реальную фичу: SQLite для памяти, Windows Graphics
Capture.

## Принятые решения

- Ответ в overlay: длинный заполняет выбранную высоту и прокручивается, короткий остаётся компактным (не растягивать).
- Последний ответ хранится для каждого проекта (`LinkProject.LastResponse`). Синхронизации ответов, написанных прямо в
  ChatGPT, нет; если понадобится — pull «последний ответ» при переключении проекта, а не push в announce.
- Рабочее приложение (`CurrentApplicationService.WorkTarget`) фиксируется hotkey'ем или возвратом в Link после ≥ 2 с
  работы в приложении; окна ChatGPT и собственные hide/show Link его не подменяют.
- О готовом ответе, когда Link скрыт или неактивен, сообщает balloon через tray; сам Link не всплывает.
- Global Send во время записи или распознавания отправляет после транскрипта; во время запроса не работает как Stop.
- Голос: GPT остаётся мозгом; speech-слой local-first без поминутной оплаты; транскрипт — обычный текст пользователя,
  не context item.
- Fast / Normal / Deep: provider-neutral подсказка в запросе плюс переключение режима ChatGPT с проверкой; Normal
  возвращает режим, который был до LINK.
- ChatGPT — только встроенная страница WebView2 (2026-09-26). Расширение и loopback HTTP-мост удалены, когда
  встроенная страница прошла проверку с аккаунтом (решение пользователя); ссылки проектов из того времени
  (`browser-chatgpt`) работают как прежде.
- Окно встроенной страницы никогда не прячется и не сворачивается — движок сразу притормозил бы страницу; оно ждёт
  за краем экрана и не активируется. Open chat показывает его на мониторе оверлея, закрытие убирает обратно.
- Страница отдыхает (2026-09-26): через минуту без запросов LINK прячет её от движка (WebView2 `IsVisible` false) и
  просит меньше памяти (`MemoryUsageTargetLevel.Low`); перед запросом и в Open chat будит. За краем экрана страница
  рисуется с частотой монитора, и анимации ChatGPT с аккаунтом занимали в простое 10–18 % ядра. Таймеры отдыхающей
  страницы идут вовремя (флаг против фонового троттлинга), так что companion остаётся на связи.
- Новый чат (2026-09-26): проект получает ссылку «новый чат» (пустой id, адрес — страница проекта ChatGPT
  `/g/g-p-<id>/project` или главная); первое сообщение создаёт беседу, companion перенимает её id и LINK
  перелинковывает проект. Выжимка — только по желанию пользователя (галочка): её пишет старый чат коротким запросом
  Fast, она становится видимым context item и уходит с первым сообщением нового чата.

## ChatGPT-транспорт

- **Встроенная страница:** `EmbeddedChatIntegration` → `ChatPageHost` ↔ `ChatPageWindow` (WebView2,
  профиль `%LocalAppData%\Link\WebView2`, флаги против фонового троттлинга). В каждом новом документе
  `https://chatgpt.com` до скриптов страницы работает `content.js` поверх `embedded-host.js` — его конца канала
  `chrome.webview` (сообщения и хранилище); оба файла встроены в LINK. Сообщения несут сессионный
  токен, остальное LINK отбрасывает. Страница на другом чате сама переходит на связанный; вход не выполнен — статус
  «Sign in to ChatGPT» и быстрая ошибка. Ссылки из ответов — в браузер по умолчанию, окна входа — в том же профиле;
  упавшая страница перезагружается, простаивающая дольше 6 часов — загружается заново; минуту спустя после
  последнего запроса страница отдыхает.
- Жизнь запроса ведёт `ChatRequestBroker`: после 10 с тишины запрос предлагается снова (новой копии companion
  после перезагрузки страницы — сразу); 20 с без ответа или 45 с тишины — ошибка; отмена приходит на страницу с
  причиной; prompt не уходит второй раз.
- Companion знает три разметки ChatGPT (классическую, «octane» без логина, залогиненную конца сентября 2026),
  ползунок усилия и «Остановить». Check chat читает ответ прямо со страницы; LINK и сам проверяет чат после 20 с без
  новостей.
- Проверки: `tests/companion` (моки трёх разметок на фейковом канале WebView2, headless Edge),
  `EmbeddedChatTests` (хост с подставной страницей) и живые прогоны.

## Открытые проблемы и следующий шаг

1. **Медленная печать — длинные беседы на стороне ChatGPT.** Встроенная страница не тормозится: в окне за экраном
   кадры анимации идут 180 раз в секунду, таймеры — 62, `visibilityState` — `visible`. Вход через Google во встроенном
   окне работает. Замеры 2026-09-26 с аккаунтом пользователя, режим Instant:
   - в длинной беседе проекта («Стабилизация LINK Voice Settings») первый текст приходит через 16–23 с, дальше
     6–7 символов в секунду, одинаково через LINK и при вводе прямо в ChatGPT (companion не следит). Процесс страницы
     занят на 23 % одного ядра, GPU — на 11 %: браузер просто медленно получает текст;
   - в новом чате — и вне проекта, и в том же проекте — первый текст через 2 с, дальше ~250 символов в секунду.

   Значит, дело в размере беседы: ChatGPT каждый раз перечитывает всю историю. Выход — новый чат: New chat с
   необязательной выжимкой и подсказка в статусе при ответе медленнее 25 символов в секунду. Без входа, с `/uc/<id>`:
   ~520 символов в секунду, Stop, Check chat, переход на связанный чат, закрытие окна работают; в простое ~0,2 %
   одного ядра и ~375 МБ приватной памяти (6 процессов WebView2).
2. **Проверено вживую с аккаунтом (2026-09-26):** вход сохраняется между перезапусками; процесс страницы убит посреди
   ответа — страница перезагрузилась, ответ дописался; New chat с выжимкой в проекте — чат создан, проект связан с ним
   (ChatGPT сначала даёт новому чату временный id `local-chatgpt:…`, companion ждёт настоящий). После получаса простоя:
   Link.exe — 119 МБ приватной памяти, 6 процессов WebView2 — ~500 МБ, страница — 10–18 % одного ядра (потоки
   Compositor и VSync: идут кадры анимации). Отдых проверен без аккаунта, со страницей с бесконечной анимацией:
   23 % ядра и 249 МБ → 0,2 % и 187 МБ; companion на связи все 7 минут отдыха; запрос после отдыха — первый текст
   через 2,4 с, как и без отдыха. Старт до оверлея — 1,3 с, страница на связи — 3,2 с. Не проверено вживую:
   отдых с аккаунтом, скриншоты во встроенной странице, истёкшая сессия, перезагрузка после 6 часов простоя.
3. **Картинки в ChatGPT** — путь загрузки обновлён после ошибки `ChatGPT image input was not found`; нужна ручная
   проверка.
4. **Голос** — локальный TTS и Conversation Mode.
5. **Проекты и контекст** — память, решения, summaries, handoff, context router.

## Для AI-агентов

Дополнения к `CLAUDE.md`:

- Репозиторий `Vladlen626/LINK`, ветка `LeN`; перед работой проверить HEAD и чистоту дерева.
- Сборка в отдельный `OutputPath` годится для проверки, но пользователь запускает `bin\Release` — после проверки
  пересобрать его, попросив выйти из Link.
- Новый сценарий в `tests/companion` сначала прогнать против старого кода: он должен падать.
- Встроенную страницу можно гонять без данных пользователя: `ChatPageWindow` и `EmbeddedChatIntegration` берут пути
  профиля и состояния снаружи. На ChatGPT без входа companion беседы `/uc/<id>` не объявляет — для живого прогона
  без аккаунта это правится только в собранном скрипте прогона, не в `content.js`.
- Живая проверка: UI Automation запущенного Link (AutomationId `PromptBox`, `SendButton`, `ResponseStateText`,
  `StatusText`, `CheckChatButton`, `EffortButton`, `OpenChatButton`, `ChatConnectionText`, `ResponseDocument`;
  скрытый оверлей показывает hotkey ShowHide из
  `settings.json`). Разметку страницы ChatGPT можно снять диагностикой Check chat в `link.log` через временную версию
  companion. Сообщения в чат пользователя — только с его разрешения. Claude in Chrome в Opera GX не работает.
- Проверки, зависящие от десктопа или браузера пользователя, — не дольше ~10 минут; дальше дать точные шаги и
  попросить результат или лог.
