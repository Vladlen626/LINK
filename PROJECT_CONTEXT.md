# Link — Project Context

Продукт, принятые решения и открытые вопросы. Правила работы с кодом — `CLAUDE.md`; для пользователя — `README.md`;
ChatGPT-транспорт в деталях — `companion/README.md`; правила и задания агента — `docs/harness/`; текущий план —
`docs/WORKSPACE_PLAN.md` и этапы в `docs/stages/`. История изменений, прежние планы и замеры — в `git log`.

## Что мы создаём

**Link** — персональный Windows desktop companion: маленький overlay поверх рабочего приложения (Unreal, Blender,
IDE, игра, браузер). Он знает активный проект и текущую задачу, по запросу берёт контекст экрана, clipboard, голоса и
текущего приложения, отправляет его в связанную AI-беседу и показывает ответ — без ухода в окно чата. Цель —
маленький персональный «Jarvis»; позже — память проектов, команды и локальные действия.

**UI для пользователя — Link. Встроенная страница чата (WebView2), API — внутренняя реализация, которую в обычном
сценарии не видно.**

```text
current app / screen / clipboard / voice → Link (Context Brain) → Chat Integration Layer
→ existing AI conversation → response → Link overlay / TTS / action
```

Название — «связь» и отсылка к Link из Zelda; визуальную айдентику Nintendo не копировать.

## Принципы

- Windows-first; быстрый старт и мало ресурсов: это приложение на весь день.
- Маленький floating companion, а не полноразмерный чат-клиент; пользователь остаётся в своём приложении.
- Local-first там, где разумно: настройки, память, скриншоты, голос, команды.
- Экран и микрофон — только по явному действию или режиму; что уходит в запрос, пользователь видит и может убрать.
- Транспорт заменяем (встроенная страница чата, API, локальная модель): `PromptRequest` и контекст
  принадлежат Link, транспорт — за `IChatIntegration`.
- По возможности — существующие чаты и подписка пользователя, а не обязательный API-бюджет.
- Простота важнее overengineering; фичи — этапами, зависимости — только под реализуемую фичу.

## Направления и статус

- **Overlay** — сделано: frosted-glass always-on-top, drag, ширина 320–1200 px, высота по содержимому до выбранного
  предела, Hide (кнопка, двойной клик по заголовку, Esc в простое), боковая панель Expand, click-through,
  прозрачность, tray с иконкой по состоянию, короткие звуки, переназначаемые hotkeys.
- **Vision** — сделано: монитор, весь desktop, каждый монитор, рабочее окно, область (одна за раз), свежий кадр окна
  на каждый Send; Windows.Graphics.Capture с запасными путями, строка Sees, «Saw: …», вопрос про экран одной клавишей.
- **Voice** — сделано: push-to-talk, live-черновик, финальный Whisper, голосовой ответ по мере прихода текста
  (Gemini TTS → локальный Supertonic 3), кнопка Listen/Stop на ответе, озвучка набранных вопросов по желанию,
  Conversation Mode (hands-free разговор) и ✎ Edit для ослышек. Дальше — по живому использованию.
- **Projects** — сделано: проекты (по умолчанию General), панель Project/Context: текущая задача, состояние проекта,
  связанная беседа, рабочая папка, история 10 ответов; последний ответ. Дальше: память проекта, решения, открытые
  вопросы, summaries.
- **Context Brain** — сделано: видимый context stack (скриншоты, clipboard, текущее приложение). Дальше: уровни
  GLOBAL → PROJECT → DECISIONS → CURRENT TASK → CHAT SUMMARIES → LIVE и context router по релевантности.
- **Chat bridge** — сделано: ChatGPT во встроенной странице WebView2; путь через браузерное расширение убран.
  claude.ai для чата не подключаем (решение 2026-09-28). Маршруты Chat и Direct, перенаправление ответа из снимка
  ввода (↻ Deeper / Direct / Fresh screen).
- **Handoff / compaction** — начато: New chat с необязательной краткой выжимкой старого чата (цель, решения,
  состояние, следующий шаг, вопросы). Дальше, если понадобится: варианты Full / Tiny и правила проекта.
- **Decision memory** — нет: решения отдельно от summaries (active/deprecated), отдельно open questions.
- **Commands** — нет: command palette, quicklinks, script commands (PowerShell/Python/EXE), локальные действия без AI.
- **Agent** — сделано (2026-09-30, задача как единица — 2026-10-03): Claude Code или Codex CLI, карточка с брифом,
  вкладка Task — одна задача с историей, планом агента, What Link gave, usage и окнами лимитов; Correct / After this,
  Stop, Hand off ▾ (другой агент с брифом, другой уровень в той же сессии, возврат первого), Start over, Escalate,
  Finish; уровни Light / Standard / Deep; итог чипом в следующий вопрос, Discuss in chat с diff. Харнесс — всегда:
  правила агента в каждой новой сессии, цифры задачи, карта, skills, проверка после Do, метки петель.
- **Agent Studio** — сделано, ждёт проверки (2026-10-08): окно Studio с колонкой Harness, бюджет контекста и Compact,
  Effort Auto, специалисты и skills, своя модель (GLM, DeepSeek, OpenRouter, Ollama), план агента со статусами,
  статистика ролей и моделей, First Run, Team pack. Дальше — Remote.

## Стек

C#, .NET 10, WPF, Win32; один assembly (`Models`, `Services`, `Windows`, presentation) — отдельные assemblies не
заводить, пока размер не требует. Зависимости: `Whisper.net` (CPU и Vulkan runtime), `org.k2fsa.sherpa.onnx`
(live-черновик, VAD и локальный голос; сборка только win-x64), `Microsoft.Web.WebView2`
(встроенный ChatGPT на Evergreen Runtime из Windows 11); целевая платформа с Windows SDK
(`net10.0-windows10.0.22621.0`) — ради Windows.Graphics.Capture: проекция 26 МБ на диске, грузится при первом захвате,
папка вывода прежняя (`bin\Release\net10.0-windows`). Только под реальную фичу: SQLite для памяти.

## Принятые решения

- Ответ в overlay: длинный заполняет выбранную высоту и прокручивается, короткий остаётся компактным (не растягивать).
- Последний ответ хранится для каждого проекта (`LinkProject.LastResponse`). Синхронизации ответов, написанных прямо в
  ChatGPT, нет; если понадобится — pull «последний ответ» при переключении проекта, а не push в announce.
- Рабочее приложение (`CurrentApplicationService.WorkTarget`) фиксируется hotkey'ем или возвратом в Link после ≥ 2 с
  работы в приложении; окна ChatGPT и собственные hide/show Link его не подменяют.
- Экран (2026-10-03, план, этап 1). Захват — Windows.Graphics.Capture (кадр того, что рисует композитор: игры, видео,
  страницы на GPU; окно — целиком и под оверлеем), затем PrintWindow (`PW_RENDERFULLCONTENT`) для окна и снимок экрана
  для монитора; чёрный кадр (выборка 128×128 пикселей) не прикладывается — статус называет причину. Окно Link не
  прячет; монитор и область — прячет на 80 мс: `WDA_EXCLUDEFROMCAPTURE` не работает для окон WPF с
  `AllowsTransparency`. После захвата Link активен, только если был активен. Fullscreen: геометрия окна и
  `SHQueryUserNotificationState`; над borderless — без фокуса, над эксклюзивным — не показывается (уведомление и
  голос). Видимость: строка Sees (что увидит модель; миниатюра рабочего окна при авто-кадре — только в памяти),
  чип приложения и заголовка вместо молчаливых строк Application/Window, «Saw: …» над ответом из запроса как он ушёл,
  оранжевая рамка 0,6 с вокруг снятого окна (обычное окно с регионом-рамкой, не layered). «Ask about the screen»
  (`Ctrl+Alt+Shift+V`, держать) — вопрос сразу в Chat со свежим кадром; ответ голосом, как у продиктованного.
- О готовом ответе, когда Link скрыт или неактивен, сообщает balloon через tray; сам Link не всплывает.
- Окно (2026-09-29): Hide прячет Link целиком, капсулы Collapse больше нет (`IsCollapsed`
  убран в схеме 7 — Link всегда открывается целиком). Скрытый Link показывает состояние иконкой tray: работает (идёт
  запрос), нужно решение (вход в ChatGPT, запрос, упавший, пока Link был скрыт, или решение агента),
  готово (ответ пришёл, пока Link был скрыт, — до следующего показа); подсказка — строка статуса. Короткие звуки (до
  150 мс, тоны в коде) идут через общий waveOut-плеер голоса и молчат, пока Link говорит, кроме «нужно решение».
- Панель рядом с карточкой — отдельное owned-окно: layered-поверхность карточки не растёт. Встаёт на сторону с большим
  местом в рабочей области монитора карточки, держит её, пока влезает, и никогда не двигает карточку; одна панель за
  раз: проект или Agent/Activity. Задача, беседа (New chat, Open chat) и история переехали в неё; в карточке — чип
  задачи и точка ChatGPT у проекта.
- Состояние проекта: текст и дата правки в `projects.json`, правится в панели. В Chat уходит стоячим чипом
  `ProjectState` в context stack: убирается на один запрос и возвращается после ответа; маршрут Direct его не берёт. История проекта — `Projects\<id>\history.json`, 10 последних ответов. Рабочая папка — только явным
  выбором, по окну не угадывается.
- Global Send во время записи или распознавания отправляет после транскрипта; во время запроса не работает как Stop.
- Голос: GPT остаётся мозгом; speech-слой local-first без поминутной оплаты; транскрипт — обычный текст пользователя,
  не context item.
- Голос ответа (2026-09-26, решение пользователя): free-first. Основной — Gemini 3.8 Flash-Lite TTS (Interactions API,
  стрим PCM 24 кГц, `store: false`) на собственном бесплатном ключе пользователя; без ключа, при лимите, ошибке сети
  или ключа — локальный Supertonic 3 (sherpa-onnx, OpenRAIL-M, скачивается по кнопке). Оба голоса играют через один
  waveOut-плеер: часть говорится, пока делается следующая, Stop и push-to-talk глушат сразу. Читается весь ответ до
  ~900 символов (около минуты); код и таблицы — фразой «на экране».
- Голоса Windows (`System.Speech`) убраны (2026-09-29, решение пользователя): ключа Gemini нет, локальный голос его
  устраивает. Локальный голос теперь последний в цепочке: без ключа Gemini и без скачанной модели Link не говорит,
  ответ остаётся на экране, причина — в статусе. Сохранённое в `settings.json` значение «Windows» читается как Auto.
- Запас звука Gemini (2026-09-29, решение пользователя: Gemini «сильно человечнее», 2 с ожидания не жалко). У
  пользователя звук Gemini приходит медленнее, чем играется: первый звук через 0,9–3,5 с, 5 с речи — за 6–7 с, фраза шла
  рывками (соединение с Google при этом 6 мс: тормозит выдача, не сеть). Речь Gemini ждёт 2 с звука (`Prebuffer`
  провайдера, у локального — 120 мс плеера) перед стартом фразы и после «пересыхания» устройства. Проверено тихим звуком
  через настоящий плеер: 5 с при 0,7× — паузы 1,9 → 0 с, первый звук позже на ~2,5 с; фраза длиннее ~7 с — одна пауза
  посреди вместо серии рывков (12 с: 5,0 → 2,7 с). Дальше, если мешает: запас по длине текста или меньшие части.
- Conversation Mode (2026-09-30): явный переключатель (метка, Settings, `Ctrl+Alt+Shift+Space`),
  сохраняется между запусками. Пока Link свободен, микрофон слушает hands-free; конец фразы — 0,65 с тишины по Silero
  VAD (порог речи 0,5), сразу короткий сигнал, Whisper только по фразе (ожидание перед ней отрезается), отправка через
  координатор маршрутом Chat или Direct — Agent голосом не запускается. Пока идёт запрос и говорит Link, микрофон
  закрыт; push-to-talk перебивает. Ответ в Conversation звучит всегда; в Chat — подсказка `Interaction mode:
  Conversation` (коротко и разговорно, детали потом). Набор в поле, кнопки Link и Settings ставят слушание на
  паузу (фокус в поле — нет: после живой проверки 2026-09-30). Push-to-talk работает и пока чат думает. Ослышка
  исправляется ✎ Edit — новой попыткой из того же снимка; нераспознанную фразу просто повторяют.
- Agent (2026-09-30): общий раннер (`AgentProcess`: без окна, UTF-8, stdout/stderr параллельно, лог до
  256 КБ, Job Object с kill-on-close) и два тонких адаптера: Claude Code `-p --output-format stream-json`, Codex
  `exec --json`; задача — через stdin, продолжение — `--resume` / `exec resume` (у resume sandbox — через
  `-c sandbox_mode=…`). Stop — сразу kill дерева: штатного прерывания без консоли у обоих CLI нет. Процесс, оставленный
  агентом (сервер, watcher), держит stdout — через 2 с после выхода агента Job его завершает. Отказ read-only у Codex
  виден только в stderr («blocked by read-only sandbox»). Codex открывает картинку посреди работы (проверено: PNG в
  workspace прочитан верно) — кадры проверки подходят обоим. Карточка подтверждения и Activity — в боковой
  панели, а не в layered-карточке: поверхность overlay не растёт. Одна задача агента за раз. Изменённый файл
  открывается выделением в Explorer, не запуском. У проекта два списка правил Claude: «только чтение» (идёт и в
  Analyze) и «для Do»; «Always allow» кладёт в список текущего доступа.
- Харнесс агента (2026-09-30): слой остаётся, только если замер показал выигрыш. Цифры задачи считают парсеры по событиям: поиск — Grep, Glob, Read и shell-команда по первой программе
  после `cd` (`rg`, `grep`, `find`, `Get-ChildItem`, `Get-Content`…); usage — из `result` Claude Code (вход вместе с
  кэшем) и `turn.completed` Codex; стоимость сообщает только Claude. Карту `docs/map.md` пишет Link из ответа агента
  в режиме чтения: у обоих агентов запись одна и гарантирована кодом, без особых прав на файл. Проверка после Do —
  строка пользователя через `cmd.exe /d /s /c` как есть, одна оболочка; в лог — только исход и время. Детектор петель —
  чистый класс над событиями, пороги — константы; он только помечает (ложная остановка сильной модели дороже петли);
  правило «много правок одного файла» убрано после замера. С 2026-10-05 работой считаются и запуск кода (первая
  программа — интерпретатор, сборка, раннер), и вызов MCP: в редакторе игры «12 поисков без правки» и «тот же вызов
  трижды» срабатывали на нормальной работе. Карточка Start over — только после прогона (провал или Stop на метке),
  посреди прогона метка — строка Activity.
  «Start over» спрашивает заметку в той же сессии без инструментов (Analyze, до 3 ходов) и начинает новую без
  `--resume`; «до задачи» берётся от первой попытки, откат покрывает обе. По замеру проверка — дело Link: агенту в
  задаче сказано, что её запустит Link, иначе Codex гоняет её в своей песочнице. Codex при resume отдаёт токены всей
  сессии — Link их так и помечает.
- Агент — руки, и учится (2026-10-03, решение пользователя): Read only убран из выбора — задача пользователя идёт с
  Edit или Auto (по умолчанию Auto; старый `DefaultAccess: 0` загружается как Auto). Только чтение остаётся у Plan
  first и у ответов, которые Link пишет сам. Харнесс агента и вставки Link — по-английски, ответ пользователю —
  по-русски. Правила велят агенту сохранять доказанное задачей, сразу, а не в конце (прогон могут оборвать): факты
  проекта — в `docs/map.md`, повторяемую работу — в skill, повторные скрипты — в tools проекта; отказ инструмента —
  остановиться и спросить, не обходить. С 2026-10-05 (решение пользователя: агенты умнеют, не портя знание) —
  изменившееся переписывать на месте без противоречащих приписок, skill — как есть сейчас, до ~150 строк; удалять
  только доказанно неверное или заменённое (неиспользованный skill остаётся); называть сохранённое, переписанное и
  удалённое; ассет, сделанный пользователем вручную, не перезаписывать под его именем. Проверку после Do в игре
  пользователь не хочет: тратит токены, он тестирует сам.
- Харнесс всегда (2026-09-30, решение пользователя): задачи агента идут только с харнессом. Правила агента
  (`harness\agent-rules.md` рядом с `Link.exe`) Link отдаёт в начале каждой новой сессии перед задачей: сначала
  стабильное (правила, skills), потом задача — так начало запроса кэшируется от задачи к задаче; продолженная сессия
  их уже имеет. `AGENTS.md` в рабочую папку не кладётся. В правилах — только то, чего модель не знает сама (запуск
  без диалога, режим чтения, карта, skills, среда Windows), каждая строка — от поведения, замеченного в прогонах.
- Skills (2026-09-30): один источник — `.agents/skills/<имя>/SKILL.md` в рабочей папке. Codex читает его сам; Claude
  Code ищет только `.claude/skills`, поэтому Link перечисляет skills папки (путь и описание) в его правилах — без
  копий и симлинков. Skill появляется из работы (2026-10-08): кнопок «Save as skill» и «Update skill» нет — харнесс сам
  учится, агент по правилам («Get stronger with each task») ведёт skill или карту, когда задача что-то доказала, и называет
  в ответе, что сохранил; Link выбирает skills для задачи по роли и словам, колонка Harness в Studio их показывает.
- Codex из Link (2026-09-30, по разбору 14 прогонов): без добавок десктопного Codex — `features.plugins`, `apps`,
  `tool_suggest`, `computer_use`, `browser_use` выключены через `-c` и при resume тоже (сессия не меняет инструменты
  и кэш). Они шли в каждый запрос, а агент в 12 из 14 прогонов читал руководство computer-use (~10k токенов), однажды
  провёл в нём 33 минуты; управление мышью — только явно. MCP-серверы конфига (Blender) остаются. Песочница Codex
  запускает команды от своего пользователя, и git считал репозиторий «dubious ownership» (13 из 14): Link передаёт
  процессу `GIT_CONFIG_PARAMETERS` с `safe.directory` репозитория рабочей папки.
- Доступ, модель, effort (2026-09-30, запрос пользователя: «устал выдавать разрешения», Opus 5.5, без субагентов).
  Три уровня: Read only, Edit, Auto — правки и команды без вопросов, рискованное останавливает проверка самого агента
  (Claude `--permission-mode auto`; Codex `approval_policy=on-request` + `approvals_reviewer=auto_review`, через `-c`,
  чтобы работало и при resume). С чего начинается карточка — Settings (по умолчанию Read only). Read only у Claude
  держится запретом `Edit`/`Write`/`NotebookEdit` (запрет сильнее разрешений проекта): раньше «Always allow» в

  токен, остальное LINK отбрасывает. Страница на другом чате сама переходит на связанный; вход не выполнен — статус
  «Sign in to ChatGPT» и быстрая ошибка. Ссылки из ответов — в браузер по умолчанию, окна входа — в том же профиле;
  упавшая страница перезагружается, простаивающая дольше 6 часов — загружается заново; полминуты спустя после
  последнего запроса страница отдыхает.
- Жизнь запроса ведёт `ChatRequestBroker`: после 10 с тишины запрос предлагается снова (новой копии companion
