# LINK Agent Studio — план работ

Основа — концепт пользователя «LINK / Agent Studio» (октябрь 2026, PDF у пользователя) и его слова от 07.10: оценить,
доработать, где видно, как лучше, разбить на работы и делать. Прежний план (компаньон и рабочее место агента) —
[WORKSPACE_PLAN.md](WORKSPACE_PLAN.md): его этапы 1–5 сделаны и остаются основой; этот план идёт поверх.

## Коротко

- LINK — два равноправных режима: **Chat** (оверлей, чаты, голос, экран — как сейчас) и **Studio** (отдельное
  обычное окно для задач агентов: задача, специалист, контекст, harness, effort, проверка, статистика).
- Человек руководит, LINK ведёт механику: какой специалист, какой effort, что видит агент, сколько контекста занято,
  что делать дальше. Ничего дорогого и никакой смены модели без подтверждения.
- Модель — сменный исполнитель: Claude Code и Codex как сейчас, плюс **Custom** — любая модель с
  Anthropic-совместимым API (GLM, DeepSeek, OpenRouter, локальная Ollama) через тот же Claude Code: тот же harness,
  те же инструменты, MCP и поправки.

## 1. Оценка концепта

Посыл верный и совпадает с тем, куда LINK уже шёл: задача как единица, уровни, передача, «What Link gave», лимиты,
обучение агента. Примерно треть концепта уже есть (§3). Что доработано в этом плане:

1. **Context Engine.** Внутренности контекста Claude Code и Codex (повторные чтения, логи, схемы MCP) LINK не
   видит и не меняет — это делает сам CLI. LINK управляет тремя вещами, и этого достаточно:
   - тем, что он сам кладёт в сессию: правила, роль, skills, карта, бриф — коротко и один раз;
   - **бюджетом**: порог автосжатия самого CLI — `CLAUDE_CODE_AUTO_COMPACT_WINDOW` у Claude Code,
     `model_auto_compact_token_limit` у Codex; по умолчанию 400k (настройка), не больше окна модели;
   - **Compact** по кнопке: не пересказ моделью, а структурированное состояние задачи из её записи (Goal, Decisions,
     Current state, Files, Verified, Known problems, Next action, Pointers) — с превью, и новая сессия того же агента с
     ним. Не зависит от модели; полная история задачи остаётся.
   Программная уборка из концепта возможна только там, где LINK сам ведёт разговор с моделью, — это позже.
2. **Auto Effort — кто знает лучше.** Таблица по типам работ хороша как старт, но лучший судья следующего шага —
   агент, который только что работал: у него весь контекст. Три слоя, без человека:
   - **фаза, которую знает LINK:** план → high, исполнение принятого плана → medium, свои ответы LINK (карта, skill,
     состояние) и проверка → low, повторный провал → +1 уровень;
   - **слово агента:** правило harness — в конце ответа строка `link-next` (следующий шаг, effort, почему); LINK
     применяет её к следующему прогону сам и показывает причину;
   - **первый прогон новой задачи:** роль и эвристика по брифу (архитектура, новая механика, непонятный баг → high;
     rename, импорт, описание → low).
   Пользователь может закрепить effort — тогда авто молчит. Auto меняет только effort, никогда модель или агента.
   Внутри прогона модель и так думает адаптивно; effort — потолок на прогон.
3. **Роли — файлы, а не код.** Роль — короткий markdown (обязанности, skills, инструменты, effort по умолчанию,
   как проверять), как skill. Восемь игровых ролей поставляются рядом с Link.exe и правятся без сборки; проект может
   добавить или переопределить свои в `.agents/roles/`. Специалиста предлагает LINK по брифу, меняет пользователь.
   Передача между специалистами — в той же сессии, без перечитывания.
4. **Бесплатные модели — через Anthropic-совместимый API и тот же Claude Code.** Отдельный рантайм не нужен:
   Claude Code ходит в любой такой API по переменным окружения (`ANTHROPIC_BASE_URL`, `ANTHROPIC_AUTH_TOKEN`,
   модели). Выбор (§5): **GLM-4.7-Flash от Z.ai** — бесплатная, есть Anthropic-эндпоинт; **Ollama** — локально и
   приватно; DeepSeek и OpenRouter — пресеты. Где используются: исполнитель задачи по выбору пользователя и свои
   ответы LINK (карта, skill, заметки) — по желанию. Ключ — DPAPI, как ключ Gemini.
5. **Studio — обычное окно**, не layered: перерисовка дешёвая, можно развернуть на второй монитор, есть в панели
   задач. Оверлей остаётся лёгким.
6. **Remote** требует relay-сервера, авторизации и E2E — это отдельный сервис и деньги. Позже; до него задачи
   Claude можно смотреть с телефона через Remote Control самого Claude Code.
7. **Поправки без остановки** (Steer now) — этап 6 прежнего плана: hook Claude и app-server Codex сверяются только
   живыми прогонами. До них Steer now = остановить шаг и продолжить ту же сессию со словами (без нового брифа и
   перечитывания — история сессии сохраняется).

## 2. Неподвижные принципы (из концепта)

Human-directed · Quality first · Visible intelligence · No unnecessary rereads · Model independence · Verified
learning · Project-specific evidence · Subscription first · No silent model downgrade.

## 3. Что уже есть

Задача как единица с историей; карточка с брифом; Correct / After this / Stop; Hand off ▾ (другой агент, другой
уровень), Return, Escalate, Start over, Finish; уровни Light / Standard / Deep; Plan first на Deep; «What Link gave»
и Console; usage и окна лимитов; правила агента, карта, skills, проверка после Do, метки петель; Save as skill;
MCP только из `.mcp.json`; Perforce changelist.

## 4. Работы

Порядок — по ценности и риску: сначала рантайм без UI (проверяется тестами), потом окно Studio, потом остальное.
Каждая работа — коммит `[S.n] …`, сборка 0/0, тесты.

### S.1 Счётчик контекста и бюджет
- Claude Code: размер контекста — `usage` каждого `assistant` (input + cache read + cache creation), окно — из
  `modelUsage[*].contextWindow` в `result`; событие `system/compact_boundary` — запись «CLI сжал контекст».
- Codex: после прогона из журнала сессии (`token_count`: `last_token_usage`, `model_context_window`) — там же, где
  уже читаются лимиты.
- `AgentEventKind.Context`; в прогоне — последний размер и окно; в задаче — строка контекста.
- `AgentSettings.ContextBudget` (по умолчанию 400 000, 50k–2M); Claude: `CLAUDE_CODE_AUTO_COMPACT_WINDOW`;
  Codex: `-c model_auto_compact_token_limit=<90 % бюджета>`. Показ: `used / min(бюджет, окно)`.

### S.2 Auto Effort
- `AutoEffort.Choose(...)` — чистая функция: закреплённый → провал (+1 от прошлого) → `link-next` агента → фаза →
  эвристика брифа и роль → medium; ответ — effort из списка CLI и причина словами.
- Правило harness `link-next` (JSON: next, effort, why), разбор как у `link-ask`, блок не показывается в ответе.
- `AgentSettings.AutoEffort` (по умолчанию да); в задаче — `Effort: medium (auto — executing the approved plan)`;
  выбор effort вручную закрепляет его до конца задачи.

### S.3 Роли
- `docs/harness/roles/*.md` рядом с Link.exe; front matter: `name`, `description`, `keywords`, `skills`, `effort`.
  Тело — обязанности, как проверять. Проект: `.agents/roles/*.md` добавляет или заменяет по имени файла.
- `ProjectRoles`: чтение, `Suggest(brief)` по ключевым словам; роль в новой сессии после правил
  (`## Your role: …`); роль в записи задачи и прогона.
- Смена специалиста: продолжение той же сессии словами «дальше работаешь как …» с телом роли.

### S.4 Состояние задачи и Compact
- `TaskState.Build(record, numstat)` по образцу брифа передачи: Goal, Decisions (слова пользователя), Current state
  (план агента), Files touched, Verified facts (проверка), Known problems (провалы, петли), Next action, Pointers
  (карта, skills, журнал Console). Бюджет ~1,5k токенов.
- Compact: превью (правится) → новая сессия того же агента с состоянием; запись в истории; Task history не
  стирается. Тот же текст — [view] Task state в инспекторе.

### S.5 Custom-модель
- `AgentProviderKind.Custom`; провайдер — Claude Code с окружением: `ANTHROPIC_BASE_URL`, `ANTHROPIC_AUTH_TOKEN`,
  `ANTHROPIC_DEFAULT_{OPUS,SONNET,HAIKU}_MODEL` = выбранная модель, пустой `ANTHROPIC_API_KEY`,
  `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1`, длинный `API_TIMEOUT_MS`. Без окон подписки.
- Пресеты: Z.ai GLM (`https://api.z.ai/api/anthropic`, `glm-4.7-flash` бесплатно), DeepSeek
  (`https://api.deepseek.com/anthropic`), OpenRouter (`https://openrouter.ai/api`, модели `:free`), Ollama
  (`http://localhost:11434`, локально), Other. Модель — из списка пресета или своя строка.
- Возможности провайдера (`AgentCapabilities`): окно, картинки, effort, подписка или API, видит ли код чужой сервер —
  для инспектора и рекомендаций.
- Ключ — DPAPI (`custom-model.key`), общий код с ключом Gemini. Settings → Agents: пресет, адрес, модель, ключ.
- Свои ответы LINK (карта, skill, заметка Start over) — на Custom по желанию (`OwnAnswersOn`).
- Передача между тремя агентами: Hand off ▾ перечисляет всех, кроме текущего.

### S.6 Статистика
- `AgentStatsReport` по записям задач проекта: группы роль × агент × модель — задачи, done / failed, среднее время,
  токены, поправки, прогонов на задачу. В записи прогона — роль, effort и его причина, контекст.

### S.7–S.9 Studio
- `StudioWindow` — обычное окно (стиль окон Settings), запоминает размер и место; открывается пилюлей агента,
  `→ Agent task`, вкладкой Tasks панели и из tray. В центре — нынешняя `AgentPanel` (список, карточка, задача),
  справа — инспектор (сворачивается). Вкладка Tasks боковой панели уходит в Studio; Chat-панель — Chats и Project.
- Карточка: Specialist ▾ (предложен LINK), агент, модель, Effort (Auto ▾ с причиной), бюджет контекста, skills
  роли, MCP-серверы; кнопки Run, Harness.
- Steer now / After this step / Stop — прежние Correct / After this / Stop под понятными именами.

### S.10–S.12
- После Finish задачи, которая дошла до Done (проверка прошла или пользователь принял): строка «Keep what this task
  taught → Update skill» — Save as skill с подсказкой обновить skill роли, а не плодить новый.
- Рекомендация дешевле: при Run the plan или низком effort и настроенной Custom — подсказка с причиной; по
  статистике проекта — «GLM: 4 of 5 done for this role». Переключение — только кнопкой.
- First Run: окно при первом запуске (нет `settings.json`): агенты (найдены ли Claude Code и Codex, Custom по
  желанию), первая рабочая папка. Team Pack: экспорт `roles` и `skills` рабочей папки в `.linkpack` (zip) и импорт;
  ключи и данные пользователя не входят никогда.

## 5. Бесплатные модели: что подключаем

| Вариант | Цена | Где сильна | Риск |
|---|---|---|---|
| **GLM-4.7-Flash (Z.ai)** — выбрана первой | бесплатно, ~1 запрос/с | исполнение по плану, свои ответы LINK, описания | код уходит Z.ai; бесплатный ключ через Anthropic-эндпоинт сверить первым прогоном |
| Ollama локально (qwen3-coder, glm-4.7-flash) | бесплатно | приватный код, офлайн | видеопамять, качество ниже облака |
| OpenRouter `:free` | бесплатно: 20/мин, 50/день (1000 после $10 разово) | пробовать разные модели | лимиты малы для агента; список меняется |
| DeepSeek | дёшево, не бесплатно | недорогой исполнитель | код уходит DeepSeek |

Подписки Claude и Codex — первыми (Subscription first); Custom — по выбору пользователя или по рекомендации.

## 6. Риски

- Сборка и тесты идут и в облаке (Linux, `EnableWindowsTargeting`), но окна WPF там не запустить: UI проверяет
  пользователь по чеклисту; ключи ресурсов XAML проверяются скриптом до коммита.
- Форматы CLI меняются: разбор терпимый к пропускам, не нашлось — не показывать.
- Бесплатные эндпоинты меняют модели и лимиты: только пресеты-адреса и своя строка модели, ничего зашитого сверх
  значений по умолчанию.
- Окно Studio не должно утяжелить LINK в простое: создаётся при первом открытии, не держит таймеров закрытым.
