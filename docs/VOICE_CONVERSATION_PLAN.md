# LINK Voice & Conversation

Принятая архитектура голосового слоя (2026-09-24) и её статус.

## Решение

- **GPT остаётся мозгом.** Speech-слой отвечает только за слух, детекцию речи и голос. Reasoning, поиск, vision,
  память и история остаются в связанной беседе: голосовой вопрос — обычный `PromptRequest` со скриншотами, текущим
  приложением и проектом. ChatGPT Voice Mode не фундамент LINK.
- **Local-first без поминутной оплаты.** Облачные STT/TTS — только как опциональные адаптеры.
- **Транскрипт — обычный текст пользователя**: не `ContextItem`; сырое аудио в GPT не уходит.

```text
голос → live-черновик → финальный Whisper → PromptRequest + контекст → GPT
→ письменный ответ в overlay → голос → следующий ход
```

## Режимы

- **Text** — обычная работа, без голоса.
- **Voice Reply** — push-to-talk, отправка вручную, Link озвучивает короткую часть ответа; полный ответ остаётся в
  overlay. *Сделано.*
- **Conversation** — hands-free: Listening → конец фразы по VAD → финальный текст → auto Send → Waiting → Speaking →
  снова Listening. *Не сделано.*

## Что сделано

| Фаза | Что | Как |
|---|---|---|
| 0 | UX-фиксы | один Region, ответ на проект, global Send, вертикальный resize, уведомление, latched work target |
| 1 | общий поток звука | `IAudioRecorder.SamplesCaptured`: блоки по 50 мс, 16 kHz mono, тот же сеанс, что пишет WAV |
| 2 | финальный Whisper | large-v3-turbo q5_0 на GPU (Vulkan), Base на CPU |
| 3 | VAD и live-черновик | `org.k2fsa.sherpa.onnx` 1.13.8: Silero VAD v5, streaming Zipformer RU (Vosk small int8, 28 МБ) и EN (icefall 20M int8, 43 МБ) |
| 5, 7 | голосовой ответ | `ITextToSpeech` на голосах Windows (`System.Speech`); законченные предложения читаются по мере стриминга (`SpokenAnswerStream`) |

включён»):

| Модель | Где | Время | Результат |
|---|---|---|---|
| Base | CPU, 8 потоков | 0,85 с | «в анрилине светится, хотя и миссия» |
| small q5_1 | CPU | 3,0 с | «в Анриле не светится, хотя амисси» |
| GigaAM v3 (sherpa, RU) | CPU | 0,3 с | «в Ангеле не светится, хотя включён» — теряет английские термины |
| large-v3-turbo q5_0 | CPU | 13,7 с | лучший текст, но слишком медленно |
| large-v3-turbo q5_0 | GPU, Vulkan | 0,25 с + ~0,8 с загрузка | «в анреле не светится, хотя эмиссив включён» |

Детали:
- Turbo (574 МБ) скачивается после первой диктовки и прогревается (шейдеры ~10–15 с один раз). Включается, только
  если whisper.cpp подтвердил GPU; без GPU и при сбое — Base на CPU. Модели качает `SpeechModelManager` один раз
  (размер и SHA-256, закреплённые ревизии). Отдельной настройки качества нет.
- VAD пока только решает, запускать ли Whisper (сомнительное считается речью), и запись не обрезает: Silero местами
  недосчитывает речь, а `WithOffset/WithDuration` в Whisper.net аудио не обрезают.
- Live-распознаватель грузится ~2 с и держит 75–100 МБ, поэтому кэшируется и выгружается через 10 минут без голоса.
  Язык под Auto — язык прошлого транскрипта, в первый раз — язык Windows.
- Черновик идёт в конец поля (`PromptDraft`) и заменяется, а не дописывается; пока идёт диктовка, поле только для
  чтения.
- Голосовой ответ: первый абзац, не больше трёх предложений, без кода, таблиц, URL и разметки; остальное — «Подробности
  на экране.». Waiting cue — один раз после ~6 с тишины.
- `VoiceSession` — единственный владелец голосового состояния (Idle → Listening → Finalizing → Sending → Waiting →
  Speaking); `MainWindow` только отображает.

## Что осталось

1. **Локальный TTS (Phase 4).** Первый кандидат — `sherpa-onnx` + Supertonic 3 int8: offline, RU и EN, несколько
   голосов, callback во время генерации (звук можно подавать частями и прерывать). Воспроизведение — `waveOut`:
   очередь PCM, Play/Stop, мгновенное прерывание; WASAPI — только если понадобятся mixer или эхоподавление. Голоса
   Windows остаются запасными.
2. **Conversation Mode v1 (Phase 6).** Конец фразы по VAD после ~0,6–1,0 с тишины (вынести в настройки после первой
   версии), auto Send, waiting cues, TTS, снова Listening; push-to-talk всегда перебивает. В запрос — provider-neutral
   подсказка `Interaction mode: Conversation`: начать ответ коротко и разговорно, детали — после.
3. **Скриншоты в Conversation** — тот же `PromptRequest`; сначала уважать Auto active window, позже — захват по
   фразам вроде «посмотри экран», но явная настройка важнее эвристики.
4. **Polish (Phase 8, только после реального использования)** — speech enhancement (GTCRN/DPDFNet в sherpa-onnx,
   опционально: может испортить хороший микрофон), wake word, hands-free barge-in с эхоподавлением, кэш фраз ожидания,
   облачный TTS как адаптер, multilingual streaming ASR для Auto после замеров.

## Правила

- Один захват микрофона на всех потребителей; не гонять полный Whisper каждые 200 мс ради псевдо-стриминга.
- Вслух не читать код, таблицы, URL, длинные списки и Markdown слово в слово: письменный ответ — источник правды.
- Waiting cues: не сразу после Send, не чаще раза в 8–15 с, без «ищу в интернете», если транспорт этого не сообщил;
  ошибки не маскировать.
- Пока Link говорит, автоматический open-mic выключен; push-to-talk перебивает мгновенно.
- Если Link говорит в Conversation Mode, голос уже служит уведомлением — toast не нужен.
- Настройки не перегружать: Voice input (язык, микрофон, live-текст), Voice output (когда говорить, голос, скорость,
  тест), Conversation (вкл., auto-send, waiting cues); пороги VAD не показывать.
- Модели — в `%LocalAppData%\Link\Models`, скачиваются по необходимости, не в Git.

## Критерий Jarvis-like v1

Пользователь работает в Unreal, Blender или IDE и не трогает браузер: говорит вопрос → видит live-текст → Link
понимает конец фразы → прикладывает нужный контекст → GPT думает и ищет как обычно → Link сообщает, если ожидание
долгое → показывает полный ответ → произносит короткий ответ → push-to-talk его перебивает → Link снова слушает.
