Основа — бриф «Куда мы ведём LINK» (PDF от 28.09.2026, сверен с кодом на `ebec836`), пересказан в §4, чтобы работать
без PDF. Решения по нему пользователь принял 28.09 (§3). Работа идёт этапами из [`docs/stages/`](stages/) (§2); этот
файл — общий план и источник решений для агентов этапов. Текущее состояние — [PROJECT_CONTEXT.md](../PROJECT_CONTEXT.md);
голос — [VOICE_CONVERSATION_PLAN.md](VOICE_CONVERSATION_PLAN.md); скорость текущего пути — [QOL_ROADMAP.md](QOL_ROADMAP.md).
Внешние факты — на сентябрь 2026; перед этапом перепроверить по §12.

## Коротко

- База брифа уже сделана: чат ChatGPT во встроенной странице, голосовые ответы, новый дизайн, замеры задержек. Этапы
  покрывают только то, чего ещё нет (§1).
- Пять этапов по порядку брифа: **1 окно → 2 маршрут → 3 голос → 4 агент → 5 Нори**. Один этап — один новый чат с
  командой в одну строку; этот чат-координатор проверяет итог и говорит, можно ли дальше (§2).
- **Chat** остаётся на ChatGPT — подписка без трат токенов; claude.ai для чата не подключаем (§3).
- **Agent** — CLI-агент на выбор: Claude Code или Codex CLI, без терминала, события в JSON; по умолчанию только
  чтение, изменения — явно для задачи.
- Дополнения к брифу (§5–§6): уровни доступа — через штатные режимы провайдера; NeedsInput делается явно; снимок
  владеет своими вложениями; откат — git для кода и копия для `.blend`; Blender — готовый MCP, skills поверх него
  (скрипт `blender -b` — запасной), кадры для проверки — в любом случае.

**Почему так.** Порядок — как в брифе, с одной поправкой: Conversation Mode сам отправляет запросы, поэтому идёт после
координатора этапа 2 — иначе его пришлось бы писать дважды. Окно (1) и маршрут (2) не зависят друг от друга: первое
видно сразу, второе — фундамент для голоса и агента; агенту нужны оба (панель и рабочая папка из 1, маршрут и снимок из
2). Голос (3) можно поставить после агента (4), если агент важнее. Больших этапов пять, а не один: пользователь
проверяет UI, голос и ChatGPT после каждого, а огромный diff не проверить и не откатить.

**Перед этапом 1** закоммитить текущую работу в рабочем дереве (цепочка TTS, `RequestLatency`) — этапы трогают те же
файлы.

**Как вести этап.**
1. Новый чат, одна строка: «Выполни этап из docs/stages/<файл>». Этапы — по одному, не параллельно.
2. Пользователь разрешает коммиты шагов этапа, без push: после каждого шага — сборка, тесты и коммит с префиксом шага
   (`[2.3] Keep the snapshot's files`) только с файлами шага.
3. Чат кончился посреди этапа — новый чат с той же строкой: агент находит сделанные шаги по префиксам коммитов и
   продолжает с первого несделанного.
4. Проверочная сборка — в отдельный `OutputPath`; `bin\Release` — только когда пользователь вышел из Link.
5. ChatGPT агент этапа сам не гоняет: скорость проверяется так — пользователь работает с новой сборкой как обычно, а
   координатор сравнивает строки `[Chat]` в `link.log` до и после.
6. В конце — статус в таблице выше, README и PROJECT_CONTEXT для видимых изменений и отчёт последним сообщением:

   ```text
   Отчёт этапа N
   Коммиты: <sha> <сообщение> …
   Шаги: сделано / не сделано
   Отклонения от плана и почему:
   Сборка и тесты:
   Чеклист пользователю:
   Открытые вопросы:
   ```
7. Пользователь проходит чеклист и приносит отчёт в чат-координатор. Координатор смотрит коммиты этапа, собирает,
   гоняет тесты, сверяет с «Готово, когда» и отвечает: дальше или что доделать (в тот же чат этапа или новый:
   «Доделай этап N: …»).
8. После этапа 5 папку `docs/stages` удалить: история — в git, итог — в PROJECT_CONTEXT.

**Почему не claude.ai для чата (R8).**
- **Общий лимит.** Чат на claude.ai, Claude Code и Cowork расходуют одно окно на 5 часов и один недельный лимит:
  разговоры съедали бы запас агента. Когда лимит кончится, всё равно нужен ChatGPT — два companion вместо одного.
- **Условия.** Anthropic запрещает доступ к сервису скриптами без API-ключа; риск — для того же аккаунта, на котором
  работает агент.
- **Работа.** Второй companion под другую разметку (у ChatGPT ~1400 строк на три разметки) и его поддержка.
- **«Мало ест» не проверено.** Основную память берёт сам движок WebView2 (~375 МБ в простое даже без входа), разница
  между сайтами — в лучшем случае сотни мегабайт. Проверка за две минуты: оба сайта с входом в Edge, диспетчер задач
  браузера (Shift+Esc) в простое и во время ответа.
- **Нужен ответ Claude** — `↻ Агентом` в режиме чтения: официально и осознанно из лимита Claude.

## 4. Бриф в одном экране

**Идея.** LINK — голосовой компаньон в духе Jarvis и персональный интерфейс к компьютеру. Обычно пользователь
разговаривает с AI и показывает выбранный контекст; когда просит выполнить работу, LINK подключает агента. Один
небольшой интерфейс, сложность — по мере необходимости.

**Главный сценарий.**

| Фраза | Что происходит |
|---|---|
| «Что с этой позой?» | Chat отвечает по выбранному снимку Blender и состоянию проекта; файлы и сцена не меняются |
| «Как это улучшить?» | Разговор продолжается, можно выбрать ответ глубже; агент не запускается |
| «Исправь Land и экспортируй» | LINK явно показывает Agent, проект, рабочую область и доступные действия; видны ход, Stop, результат, изменения |
| «А почему так?» | Снова Chat — с контекстом выполненной работы |

**Принятые правила.** Голос — основной способ, всё работает и без микрофона. Chat — маршрут по умолчанию, агент — для
действий. Маршрут виден и исправим: LINK может предложить Agent, но не превращает вопрос в изменение тайно. Обвязка не
ухудшает модель: контекст, skills и tools — по делу; всегда есть Direct без добавок LINK.

**Модель.** Оси: исполнение Chat/Agent × глубина Fast/Normal/Deep. Доступ Ask (ответить) / Analyze (читать
разрешённый экран или проект) / Do (менять) — внутреннее правило, а не три больших переключателя. До отправки видны
маршрут, проект, контекст и область действия; обычный вопрос не ждёт классификатора.

**Пути.**
- *Снимок ввода* при Send: текст или финальный транскрипт, проект, Chat/Agent, глубина, текущая задача, вложения,
  разрешённый экран, work target. Перенаправление берёт снимок, а не перечитывает буфер и активное окно.
- *Chat*: `PromptRequest` → `IChatIntegration`; сохраняется всё работающее (связанная беседа, поток, Stop, Check
  chat, New chat, выжимка); никаких вызовов до Send.
- *Agent*: явный workspace root и цель; `AgentTask` = снимок + рабочий каталог + выбранные skills + доступные tools;
  `IAgentProvider` отдаёт session id и события status / tool / output / artifact / error / completed; связанная
  беседа ChatGPT не нужна.
- *Direct*: только текст и явно выбранные вложения, без добавок `ChatPrompt.Format` и подсказок LINK.
- *Состояния*: Chat — Sending → Waiting → Receiving → Completed / Error / Cancelled; Agent — Preparing → Running →
  NeedsInput → Completed / Error / Cancelled. Activity показывает только реальные события агента.
- *Change route*: новая попытка с новым id и тем же снимком; если файлы уже изменены — старт с текущего состояния,
  сначала показать список изменений; автоматический откат не обещать.

**UI.** Обычный вид: проект, поле/транскрипт, Chat/Agent, Fast/Normal/Deep, вложения, ответ, Hide. Collapse → полное
скрытие, общий хоткей возвращает. Expand — рабочая область: боковая панель Project/Context или Agent/Activity,
подробный лог снизу, у края монитора — свободная сторона; отдельное окно терминала — позже.

**Сохранить.** `ChatPageHost` / `ChatRequestBroker` (страница и защита от повторной отправки), `VoiceSession` (голос
и один микрофон), защита от второго Region в `MainWindow.Capture.cs`, окно ChatGPT за краем экрана — Hide оверлея на
WebView2 не переносить.

**Решать после прототипа.** Отдельное окно агента; ConPTY (только если CLI требует TTY) и MCP (после второго
потребителя); память и skills (граф связей не строить, если хватает состояния проекта и пары skills); польза обвязки
(сравнить с Direct на реальных задачах, убрать слой без выгоды).

## 5. Разбор брифа

### 5.1 Что сильное — не трогать

- **Chat по умолчанию, Agent явно.** Так же устроены VS Code (роли Ask / Agent / Plan, план передаётся агенту
  кнопкой) и Claude Code (plan mode). Без роутера нет лишней задержки — это совпадает с замерами QOL_ROADMAP.
- **Direct.** Вычитаемая обвязка — единственный честный способ проверить, помогает ли слой LINK.
- **Снимок ввода и перенаправление.** Ошибка маршрута стоит один клик, а не повторную диктовку.
- **Честное восстановление.** Эталон — список изменённых файлов с Keep / Undo по каждому в VS Code: видно, что
  изменено, откат — явный.
- **Вертикальные этапы и замеры** на каждом шаге.

### 5.2 Пробелы и как их закрыть

1. **Analyze не разложен по путям.**

   | Доступ | Chat | Agent |
   |---|---|---|
   | Ask | текст + явно выбранные вложения | — |
   | Analyze | + разрешённый экран и состояние проекта | чтение workspace без изменений (режимы §6.3) |
   | Do | недоступно → предложить Agent | изменения в workspace (режимы §6.3) |

   Agent по умолчанию стартует в Analyze; Do включается явно для этой задачи — «исправь» не становится изменением без
   видимого решения.
2. **NeedsInput сам не появится.** Без терминала Claude Code не спрашивает: вызовы, которые требуют разрешения и не
   покрыты правилами, отклоняются (`permission_denied`) или уходят в `--permission-prompt-tool`. v1: Do идёт с
   allowlist проекта; отказ — карточка «Разрешить и повторить» (resume той же сессии с расширенным allowlist). Для
   крупных задач — галочка «Сначала план»: план в режиме только чтения → «Выполнить». Живые вопросы через
   `--permission-prompt-tool` требуют MCP-сервера в LINK — после v1 и отдельного решения.
3. **Возможности провайдера** брать у самого провайдера: у Claude Code — событие `system/init` (модель, инструменты,
   MCP-серверы со статусом, плагины), у Codex — sandbox и конфиг. LINK показывает их и ничего не дублирует.
4. **Восстановление для не-git.** `.blend` и `.uasset` бинарные, diff по ним бесполезен. Перед Do в workspace без git —
   явная копия файлов из области задачи (галочка включена по умолчанию); в git — список изменений и «Отменить
   изменения агента» только после подтверждения.
5. **Снимок должен владеть вложениями.** Сейчас скриншот Auto active window удаляется в `finally` у `SendAsync`
   (`DeleteTransientContext`) — перенаправлять будет нечего. Файлы снимка живут, пока жив он сам (три последних снимка
   проекта), и защищаются от чистки истории через `ScreenshotHistoryService.Prune(additionallyProtected)`.
6. **Голос и Agent.** Conversation Mode и голосовой Send — только Chat. В Agent голосом — только через карточку
   подтверждения (маршрут, проект, workspace, доступ, вложения); там же правится ошибка распознавания.
7. **Подсказка Agent** — локальная, без модели: глаголы действия («исправь», «сделай», «экспортируй») подсвечивают
   кнопку «Агентом», маршрут сам не меняется.
8. **Цена агента видна.** Агент тратит лимиты подписки провайдера; в Activity — провайдер, время и число ходов;
   предохранитель `--max-turns`.
9. **Одновременность.** v1: одна задача агента на проект; Chat работает, пока агент идёт; ответ Chat и Activity —
   разные области.
10. **Проверка результата.** «Исправь Land» без взгляда на результат — гадание. Skill сценария рендерит несколько кадров
    в PNG (`blender -b`), LINK показывает их в Activity. Claude Code смотрит их сам (Read читает изображения); для
    Codex — проверить, умеет ли он открыть картинку посреди работы, иначе кадры смотрит пользователь. Это принцип
    «проверяй как пользователь» из статьи Anthropic о harness для долгих задач.
11. **`last-request.json`.** `BuildAndLog` на UI-потоке сериализует запрос дважды и пишет файл с текстом, путями и
    заголовком окна (там бывает личное). Писать только при включённой диагностике, одной сериализацией.
12. **«MCP позже»** — это «не строить свой MCP-слой». Готовый сервер, который приложение ставит само (Unreal 5.8 пишет
    `.mcp.json` в корень проекта), подключается к агенту почти бесплатно — это адаптер, а не стандартизация.

## 6. Контракты и техника

Минимум классов — по брифу: вводить только то, что нужно текущему этапу.

### 6.1 Снимок и попытка

- `InputSnapshot` (неизменяемый): id, время, текст или финальный транскрипт, project id, текущая задача, вложения
  (`ContextItem` с файлами, которыми снимок владеет), work target (процесс и окно), разрешённый экран.
- Попытка: id, снимок, маршрут (Chat / Direct / Agent), глубина, доступ, состояние. Перенаправление = новая попытка с
  тем же снимком.
- UI собирает снимок (поле, вложения, work target, авто-скриншот) → координатор в `Services` ведёт попытку
  (`PromptRequest`, отправка, `RequestLatency`, `LastResponse`, отмена) → UI рисует, озвучивает и уведомляет.
- Проверка «нужна связанная беседа» — только в Chat-пути: Agent без неё не падает.

### 6.2 `IAgentProvider`

Один метод запуска с `AgentTask`, `IProgress<AgentEvent>` и `CancellationToken` (Stop); resume — через session id в
задаче; плюс «установлен / вошёл» для Settings. Общий раннер процесса (§6.4) и два тонких адаптера: аргументы и разбор
событий. События — из брифа (status, tool, output, artifact, error, completed) плюс needs-input:

| Событие | Claude Code (`stream-json`) | Codex CLI (`--json`) |
|---|---|---|
| status | `system/init` (session id, модель, tools, MCP) | `thread.started`, `turn.started` |
| tool | `tool_use` | `item.*`: command execution, MCP tool call |
| output | текст `assistant` (с `--include-partial-messages` — по частям) | `item.*`: agent message |
| artifact | правки файлов (`Edit` / `Write` в `tool_use`), git-список после хода | `item.*`: file change |
| needs-input | `permission_denied` | отказ sandbox → предложить Do |
| completed / error | `result` (текст, session id, стоимость — оценка клиента) | `turn.completed` / `turn.failed`, `error` |

Неизвестные события пропускать; разбор проверять на фикстурах из живого прогона.

### 6.3 Доступ → режимы провайдеров

| Доступ | Claude Code (`claude -p`) | Codex CLI (`codex exec`) |
|---|---|---|
| Analyze | `--permission-mode dontAsk` + список проекта «только чтение» в `--allowedTools` (например, инструменты осмотра Blender без выполнения кода): чтение и read-only команды идут, остальное отклоняется; для плана — `plan` | `--sandbox read-only` (по умолчанию) |
| Do | `--permission-mode acceptEdits` + `--allowedTools`: список «только чтение» и список для Do (сборка, экспорт, выполнение кода) | `--sandbox workspace-write` |
| Никогда | `bypassPermissions` | `danger-full-access` |

Поток: `--output-format stream-json --verbose` у Claude Code, `--json` у Codex; продолжение — `--resume <id>` /
`codex exec resume <id>`. Оба входят в подписку (Claude / ChatGPT) и тратят её лимиты; API-ключ не нужен. У Codex
проверить (этап 4), как режимы sandbox действуют на вызовы MCP-инструментов: если чтение и запись там не разделить,
инструмент выполнения кода в Analyze не подключать.

### 6.4 Процесс агента на Windows

- `ProcessStartInfo`: `UseShellExecute = false`, `CreateNoWindow = true`, перенаправить stdin/stdout/stderr, UTF-8
  для потоков, `WorkingDirectory` = workspace root. Секреты LINK в окружение не передавать.
- stdout и stderr читать асинхронно и параллельно: по документации .NET синхронное чтение двух потоков может
  зависнуть. JSONL — построчно; объём сохранённого лога ограничить.
- Запускать настоящий исполняемый файл: `claude.exe` (штатная установка кладёт его в `%USERPROFILE%\.local\bin`, есть
  WinGet); у Codex — найти его exe. `.cmd`-обёртки напрямую не запускать.
- Job Object с `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE` (P/Invoke в `NativeMethods`): агент и его дочерние процессы не
  переживут LINK. Stop — штатное прерывание провайдера, если оно есть; иначе `Process.Kill(entireProcessTree: true)`
  и показать изменённые файлы.
- ConPTY не нужен: у обоих CLI есть режим без терминала с JSON.
- Activity обновлять пачками, не чаще 10 раз в секунду: overlay — layered-окно, каждая перерисовка отдаёт всю
  поверхность.
- Список изменений в git — `git status --porcelain` до и после задачи.

### 6.5 Direct

`ChatPrompt.Format` вызывает сам транспорт (`EmbeddedChatIntegration` → `ChatPrompt.CreateAsync`), поэтому Direct —
это явное намерение в `PromptRequest` (новое поле; `SchemaVersion` запроса поднять), а не отдельная сборка текста в UI.
В Direct формат — текст и явно выбранные вложения; без строк Project / Application / Window / Current task и без
текстовой подсказки глубины. Переключение режима ChatGPT в companion остаётся — это штатная функция провайдера.

### 6.6 Состояние проекта

Короткий подтверждённый текст: задача, решения, важные факты, ссылки на беседы, дата актуальности. Живёт в данных
LINK, правится в панели Project/Context, уходит в Chat видимым чипом (в Direct — нет), в Agent — частью задачи. В
workspace (`CLAUDE.md`, `AGENTS.md`) — только явной кнопкой.

### 6.7 Skills и адаптеры

- Skill — папка `SKILL.md` + references + scripts (открытый стандарт Agent Skills). Claude Code и Codex подгружают
  skills по описанию сами, поэтому LINK не выбирает их за модель: показывает доступные в workspace и даёт закрепить
  нужный на задачу.
- **Где живут (решение этапа 7, 30.09).** Один источник — `.agents/skills/<имя>/SKILL.md` в рабочей папке. Codex
  0.154 читает его сам (от рабочей папки до корня репозитория). Claude Code ищет только `.claude/skills`, поэтому
  Link перечисляет skills папки (путь и описание) в правилах, с которыми начинает каждую новую сессию Claude; тело
  skill агент читает сам, когда работа совпала с описанием. Ни копии в `.claude/skills`, ни симлинка (на Windows
  нужен режим разработчика).
- **Харнесс всегда (решение пользователя 30.09).** Задачи агента идут только с харнессом: правила агента
  (`harness\agent-rules.md` рядом с `Link.exe`) Link отдаёт в начале каждой новой сессии, перед задачей; продолженная
  сессия их уже имеет. `AGENTS.md` в рабочую папку не кладётся, стенд без харнесса (`plain`) убран.
- Доступ агента к Blender — свой код в LINK не нужен. Решение пользователя 30.09: основной путь — MCP, skills пишем
  поверх MCP (MCP даёт инструменты, skill — знания проекта); скрипт — запасной:
  - **официальный Blender Lab MCP** (нужен Blender 5.1+): аддон в запущенном Blender и сервер `blender-mcp` для
    агента; инструменты осмотра (сводки сцены и файла, скриншоты и рендер вьюпорта) и выполнение Python. Работает на
    живой открытой сцене; часть инструментов (`_for_cli`) — по сохранённому файлу без аддона. Выполнение кода в нём идёт
    без защиты: только в Do (§6.3);
  - **скрипт**: `blender -b Nori.blend --python fix_land.py -- <аргументы>` из skill; экспорт —
    `bpy.ops.export_scene.fbx` или `gltf`. Работает по сохранённому файлу в любой версии Blender; откат — копия файла.

  Кадры проверки (§5.2, п. 10) нужны при любом пути. MCP, в отличие от скрипта, меняет живую сцену: «изменённых
  файлов» до сохранения нет, поэтому перед правками — `Save Copy` рядом с файлом.
- Правила рабочего агента и инструкции для чата — коротко и без запретов в тексте, границы в коде: `docs/harness/`.
- Unreal — Python-скрипты редактора и commandlets; экспериментальный MCP-плагин 5.8 — готовый адаптер, когда дойдёт
  до Unreal.
- Управление мышью (Windows-MCP) — последний вариант и только явно.

## 7. UI

### 7.1 Обычный вид и маршрут

- Под полем — две маленькие метки, по одной на ось: `[Chat ▾]` (Chat / Direct / Agent) и `[Normal ▾]`. Для Agent
  метка показывает провайдера и доступ: `Claude · чтение`, `Codex · изменения`.
- Подсказка «Агентом» — по глаголам действия (§5.2, п. 7); маршрут сам не меняется.
- Enter — отправить выбранным маршрутом; «Агентом» — кнопка или `Ctrl+Enter` (сейчас `Ctrl+Enter` тоже отправляет в
  Chat) — открывает карточку подтверждения.
- Hide — кнопка в заголовке вместо Collapse, двойной клик по заголовку и Esc в простое (сейчас `OnPreviewKeyDown` в
  простое ничего не делает). После миграции `IsCollapsed` первый запуск видимый.

### 7.2 Перенаправление

На ответе и в Activity: `↻ Глубже` · `↻ Direct` · `↻ Свежий экран` · `↻ Агентом` / `↻ В чат` — новая попытка из того же
снимка («Свежий экран» заменяет в нём скриншот рабочего окна). «В чат» после агента кладёт в контекст итог работы и
список изменённых файлов, а не diff.

### 7.3 Карточка подтверждения Agent

Провайдер, проект, workspace, доступ (чтение / изменения), «Сначала план», копия перед Do, вложения, цель (текст или
транскрипт — правится). [Запустить] [Изменить] [Отмена]. Не модальная — внутри overlay.

### 7.4 Рабочая область (Expand)

- Боковая панель: Project/Context или Agent/Activity, одна за раз, на свободной стороне (к центру рабочей области
  монитора); подробный лог — раскрытием снизу.
- Activity: строка состояния (провайдер, время, текущий реальный шаг) · события (инструмент, файл, команда) ·
  изменённые файлы с «Открыть» · кадры проверки · итог · Stop всегда виден · stdout/stderr по запросу.
- NeedsInput — карточка в Activity; при скрытом LINK — balloon в tray. Pop-up — только когда решение действительно
  нужно.
- Панель — отдельное owned-окно рядом с карточкой: layered-поверхность карточки не растёт.

### 7.5 Скрыт, но работает

Бриф требует полного Hide — пилюли нет. Состояние — иконкой в tray (простой / работает / нужно решение / готово) и
короткими звуковыми сигналами; balloon — как сейчас. Пока LINK говорит, сигналы молчат, кроме «нужно решение».

### 7.6 Голос

- Conversation Mode (по VOICE_CONVERSATION_PLAN) — только Chat. Конец фразы по VAD прибавляется к ощутимой задержке:
  паузы дольше ~0,8 с уже заметны, поэтому порог — 0,6–0,7 с, а короткий сигнал «услышал» — сразу после конца фразы.
- Агент говорит только старт, нужное решение и итог в 1–2 фразы; код, пути и логи не читает.

## 8. Позже, не в этапах

- Отдельное окно Activity или терминал (`claude --resume <id>`) — если боковой панели не хватит (решать после этапа 4).
- Текстовый файл проекта — вложением в Chat (вставкой текста, с лимитом размера).
- Push-to-talk на боковых кнопках мыши (`WH_MOUSE_LL`).
- MCP-сервер в LINK для живых вопросов агента; MCP Unreal — когда дойдёт до Unreal (Blender — этап 5).

## 9. Правила для агентов этапов

- CLAUDE.md и память проекта важнее этого плана. Одна подзадача за раз, в конце — короткий чеклист пользователю.
- Не писать свой агентный цикл, инструменты правки файлов, MCP-клиент и ConPTY: всё это есть у провайдеров.
- Простой Chat не должен стать медленнее: никаких вызовов до Send, роутера и поиска по истории.
- Ничего не менять в проекте пользователя без видимого Do; `bypassPermissions` и `danger-full-access` — никогда.
- Не читать, не хранить и не передавать токены Claude и ChatGPT; вход — только штатный в самих CLI.
- Новые зависимости — только после «да» пользователя.
- Не трогать запущенный Link пользователя и `%LocalAppData%\Link` без бэкапа; живые проверки — на тестовой копии.
- В git — только явные пути: репозиторий правят параллельные сессии.

## 10. Риски

1. **Транспорт Chat.** Условия OpenAI запрещают программно извлекать ответы из сервиса вне API; путь держится на
   разметке страницы (`content.js` ~1400 строк). Пользователь это принимает ради работы без токенов; транспорт
   изолирован за `IChatIntegration`.
2. **Лимиты агента.** Claude Code и Codex тратят лимиты подписки; правила Anthropic для `claude -p` и сторонних
   инструментов в 2026 менялись несколько раз. Два провайдера за одним контрактом — страховка.
3. **Большие игроки делают похожее:** ChatGPT desktop (Chat + Work + Codex, голос управляет агентами), Claude Desktop
   для Windows (Cowork, MCP; Quick Entry — только на macOS), Copilot в Windows (Actions, Agent Workspace). LINK
   выигрывает личной подгонкой (§11).
4. **Бинарные ассеты** (`.blend`, `.uasset`): откат только копией; diff не показать.
5. **Ошибка голоса → неверное действие:** закрыто карточкой подтверждения и Analyze по умолчанию.
6. **Разрастание UI и перерисовки:** одна панель, пачки обновлений, замеры на каждом этапе.
7. **Выполнение кода в Blender через MCP идёт без защиты** (по описанию сервера): только в Do и на проекте с копией; в
   Analyze — инструменты только чтения.

## 11. Оценка

**Бриф.** Сильный: сверен с кодом, держится принципов (Direct, никакого обязательного роутера, видимый маршрут),
измерим и режется на вертикальные этапы. Пробелы — в деталях исполнения (§5.2): Analyze по путям, NeedsInput без
терминала, восстановление бинарных файлов, жизнь вложений снимка, проверка результата агентом.

**Жизнеспособность — высокая.** Тяжёлое уже готово: у Claude Code и Codex официальные режимы без терминала с JSON, у
Blender — фоновый режим с Python, у Unreal 5.8 — MCP в редакторе, skills — открытый стандарт. Своё у LINK — пульт,
снимок, маршрут, Activity и голос. Главный технический риск — сценарий «исправь Land»: агенту нужен способ видеть
результат, иначе он будет гадать (§5.2, п. 10).

**Стоит ли свеч — да.** База уже работает (§1); впереди одна развилка, одна панель и один раннер процесса. Польза
конкретная: не уходя из Blender, голосом спросить или поручить и видеть, что происходит. Общий «голос + чат + агент»
большие приложения уже делают; своя ценность LINK — контекст текущего окна одним хоткеем, проекты пользователя,
маршрут под его контролем, чат без токенов и свобода выбора агента.

**Что поменяли в брифе:**
1. Агент по умолчанию — Analyze; Do — явно для задачи.
2. Conversation Mode — после координатора, чтобы не писать отправку дважды.
3. Снимок владеет вложениями — иначе перенаправление теряет авто-скриншот.
4. Скрытый LINK сообщает о работе иконкой tray и звуком, не пилюлей.
5. Доступ к Blender — готовый MCP (решение пользователя), скрипт `blender -b` — запасной; кадры для проверки — в любом
   случае. Условие брифа «MCP, когда tools нужны двум агентам» выполнено решением R1 (два провайдера); свой адаптер и
   свой MCP-слой в LINK не пишем.
6. Два провайдера агента с первого дня: общий раннер и два тонких адаптера.
7. Польза обвязки проверяется набором из пяти настоящих вопросов, чтобы сравнение с Direct было повторяемым.
