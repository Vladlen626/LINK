Команда для нового чата: «Выполни этап из docs/stages/2-route.md».

- **Зачем:** пункт брифа «разделить пути»: один ввод можно отправить разными маршрутами и перенаправить без повторной
  диктовки; Direct проверяет, помогает ли обвязка LINK. Координатор — фундамент для голоса (этап 3) и агента (этап 4).

  приложение, окно, задачу и подсказку глубины; строки `[Chat]` с задержками в `link.log`.
- **Зависит от:** ничего (по порядку идёт после этапа 1). Прочитать: `CLAUDE.md`, память проекта,
  [план](../AGENT_HARNESS_PLAN.md) §2, §5.2 (п. 5, 11), §6.1, §6.5, §7.1–§7.2, §9.

## Шаги

- **2.1 База замеров.** Из `%LocalAppData%\Link\link.log` — последние строки `[Chat]` для короткого и длинного чата
  (подготовка в LINK, приём страницей, первый текст, скорость) — в отчёт. Данные пользователя только читать.
- **2.2 Координатор без изменения поведения.** `InputSnapshot` в `Models` (план §6.1); чистая функция «снимок +
  маршрут + глубина → `PromptRequest`» без WPF, с тестами в `tests/Link.Desktop.Tests`; координатор попытки в
  `Services` (`PromptRequest`, `IChatIntegration.SendAsync`, `RequestLatency`, `LastResponse`, отмена). `SendAsync`
  становится тонким: собрать снимок → координатор → нарисовать, озвучить, уведомить. Проверка «нужна связанная
  беседа» — только для Chat. Запрос выжимки New chat (`SummaryPrompt`) тоже собирается новой функцией, без второго
  пути.
- **2.3 Снимок владеет вложениями.** Авто-скриншот рабочего окна не удаляется в `finally`, а живёт со снимком; хранить
  три последних снимка проекта, файлы старых удалять; файлы живых снимков защищать через
  `ScreenshotHistoryService.Prune(additionallyProtected)`.
- **2.4 Direct.** Явное намерение в `PromptRequest` (поднять его `SchemaVersion`); `ChatPrompt.Format` в Direct — текст
  и явно выбранные вложения: без строк Project / Application / Window / Current task, без подсказки глубины и без
  автоматически добавленных элементов (чип состояния проекта этапа 1). Переключение режима ChatGPT остаётся. Тесты
  на оба формата.
- **2.5 Метки маршрута и глубины** под полем: `[Chat ▾]` (Chat / Direct) и `[Normal ▾]` — сюда переезжает текущая
  кнопка глубины. `x:Name` из списка живых проверок в PROJECT_CONTEXT сохранить или обновить там.
- **2.6 Перенаправление на ответе:** `↻ Глубже`, `↻ Direct`, `↻ Свежий экран` (тот же снимок с новым скриншотом рабочего
  окна) — новая попытка в той же связанной беседе; работает и после Error / Cancelled; буфер и активное окно заново не
  читаются.
- **2.7 `last-request.json` и документы.** Файл — только при включённой настройке диагностики (по умолчанию выключена),
  одной сериализацией. README (Direct, перенаправление, диагностика), PROJECT_CONTEXT, статус этапа в плане §2.

## Не делать

- Agent, Conversation Mode, автоматический выбор маршрута, поиск по истории до Send, правки `companion/`, новые
  зависимости.

## Готово, когда

- Обычный Send (текст, голос, скриншот, Auto active window) ведёт себя как раньше.
- Direct уходит без контекста LINK; перенаправление работает после ответа, ошибки и отмены без повторного ввода.
- Сборка Release — 0 warnings, тесты зелёные. Скорость сравнит координатор по строкам `[Chat]` после обычной работы
  пользователя с новой сборкой.

## Чеклист пользователю

1. Обычный вопрос текстом и голосом — как раньше, та же скорость.
2. Скриншот + вопрос → ответ → `↻ Глубже`: ушёл тот же скриншот, нового захвата не было.
3. `↻ Direct`: в ChatGPT видно, что ушли только текст и вложения, без проекта, окна и задачи.
4. Auto active window включён → ответ → `↻ Глубже` — скриншот тот же; `↻ Свежий экран` — новый.
5. Stop посреди ответа → `↻ Глубже` работает.
6. Поработать с новой сборкой как обычно и принести координатору отчёт — он сравнит скорость по `link.log`.
