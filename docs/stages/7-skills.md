# Этап 7 — skills: повторяемое действие записывается один раз и дальше не собирается заново

Команда для нового чата: «Выполни план из md файла: docs/stages/7-skills.md».

Микроэтап харнесса: только механизм skills в LINK и замер его пользы. Сами skills под Нори и Unreal (Blender MCP,
экспорт, сборка) — в [этапе 5](5-nori.md), не здесь.

## Цель

Агент не тратит ходы и токены на то, что уже делал в этом проекте:

1. **Skill появляется из работы, а не заранее.** После задачи, где агент собрал и отладил последовательность действий,
   пользователь одной кнопкой сохраняет её как skill в рабочей папке. Агент пишет `SKILL.md`, LINK записывает файл
   (как карту): это единственное изменение, оно видно в Activity и откатывается.
2. **Оба агента его находят.** Один источник skills в рабочей папке; Claude Code и Codex подхватывают его сами, по
   описанию. LINK не выбирает skill за модель.
3. **Видно, что есть.** Панель проекта показывает skills рабочей папки: имя и строку «когда применять».
4. **Экономия измерена.** Повторная задача того же рода со skill — меньше вызовов, поисков и токенов, чем без него.

## Откуда это

Замер этапа 6 (PROJECT_CONTEXT, «Замер харнесса»): оба агента в каждой задаче игры Nori заново собирали проверку в
браузере — свой CDP-скрипт, headless Chrome, `tools/check-controls.ps1` — и по 5–15 минут бились о песочницу, пока
она не заработала. Это повторяющееся действие, которое skill делает один раз.

Уровни знаний проекта (разбор с пользователем 30.09):
- `docs/map.md` — куда смотреть вообще (уже есть, этап 6);
- skill — как выполнить повторяемую работу: `SKILL.md` + scripts;
- domain (`domains/<область>.md`) — знания одной области. Делать только когда карта разрастётся (больше ~150 строк) и
  агенту не нужен весь проект для каждой задачи; в этом этапе — нет.

## Как думаем

- Skill — по факту повтора: последовательность уже прошла в задаче и пригодится снова. Не писать skills заранее.
- Skill короткий: когда применять, шаги, готовые команды или скрипты рядом, подводные камни. Длинный skill хуже.
- Записывает только пользователь, явной кнопкой. Никаких молча созданных skills, хуков или правил.
- Тот же приём, что у карты: агент в режиме чтения отвечает текстом, LINK пишет файл. Граница — в коде, не в тексте.

## Не делаем

- Каталог skills заранее, свой формат skills, выбор skill за модель в LINK.
- Domains и дробление карты — пока карта маленькая.
- Автоматические «уроки» после каждой задачи, хуки, MCP-серверы, новые зависимости.
- Две расходящиеся копии одного skill для двух агентов.

## Что нужно получить

Шаги — для коммитов `[7.1]`…; порядок и детали решаешь сам. Каждый шаг — отдельный коммит, сборка зелёная.

1. **Где живут skills.** Сверить с документацией установленных версий, где Claude Code и Codex ищут skills проекта
   (у Claude Code — `.claude/skills/<имя>/SKILL.md`; у Codex — проверить) и выбрать один источник в рабочей папке,
   который находят оба (при необходимости — строка-указатель, не копия). Записать решение в план §6.7 и одной строкой в
   `agent-rules.md`, где искать skills.
2. **Кнопка «Save as skill».** В Activity после успешной задачи. LINK продолжает сессию агента одним запросом только на
   чтение: описать сделанное как skill — задание файлом `docs/harness/skill-task.md` (как `map-task.md`): имя,
   описание «когда применять», шаги, команды и скрипты, подводные камни, до ~60 строк. LINK пишет ответ в
   `<источник>/<имя>/SKILL.md`; скрипты, которые агент уже положил в проект, — ссылками, не копиями. Имя проверить
   (латиница, цифры, дефис), существующий skill не перезаписывать без подтверждения.
3. **Skills в панели проекта.** Под картой — список skills рабочей папки: имя и описание из `SKILL.md`, клик — открыть
   в Explorer. Пусто — строка «No skills yet».
4. **Замер.** На игре Nori: одна и та же повторяемая работа (например, «проверь игру в браузере: движение, камера,
   кадр») — дважды без skill и дважды после «Save as skill» из первого удачного прогона. Цифры — в таблицу
   PROJECT_CONTEXT; что не помогло — убрать из кода и плана.

## Не очевидно, но важно

- Codex в песочнице не может то же, что LINK: skill, которому нужны браузер или сервер, должен говорить, как это
  делать в песочнице, иначе агент повторит получасовую борьбу из этапа 6.
- Skill — такое же изменение рабочей папки, как карта: `AnswerFile`, Activity, откат. Не писать его в данные LINK.
- Счётчики этапа 6 — единственная мера пользы. Если skill не сокращает вызовы и токены на повторе — убрать кнопку.
- Пользователь сам тестирует UI и живых агентов; свои проверки — на фикстурах, сборке и стенде Nori.
- В рабочем дереве могут быть правки параллельных сессий: добавлять файлы явными путями.
