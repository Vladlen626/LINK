# Этап 4 — агент: Claude Code или Codex

Команда для нового чата: «Выполни этап из docs/stages/4-agent.md».

- **Зачем:** пункт брифа «первый Agent»: работу, а не ответ, выполняет CLI-агент на выбор пользователя, а LINK
  показывает маршрут, ход, изменения и даёт остановить и откатить.
- **Уже есть:** хост боковой панели, рабочая папка проекта, иконка tray и звуки (этап 1); снимок, координатор,
  метка маршрута и перенаправление (этап 2).
- **Зависит от:** этапы 1 и 2. Прочитать: `CLAUDE.md`, память проекта, [план](../AGENT_HARNESS_PLAN.md) §2, §3, §4,
  §5.2, §6 целиком, §7, §9.

## Перед началом

- `git status`, `git log --oneline -20`: шаги с коммитами `[4.x]` уже сделаны — продолжить с первого несделанного.
- Спросить пользователя, какие CLI установлены и выполнен ли в них вход (`claude`, `codex`). Устанавливать, входить и
  читать их токены — не нам. Живые прогоны тратят лимиты подписки: 1–2 коротких запроса на провайдера для фикстур.
- Тестовый workspace — отдельный `git worktree` репозитория LINK вне основной папки; основной checkout агенту не давать.

## Шаги

Ядро — 4.1–4.5, интерфейс — 4.6–4.10. Если чат кончается, остановиться на границе шага.

- **4.1 Контракты** (план §6.2): `AgentTask`, `AgentEvent`, `IAgentProvider` (+ «установлен / вошёл», версия);
  `AgentSettings`: пути к исполняемым файлам (поиск в PATH и стандартных местах), провайдер по умолчанию; у проекта —
  свой провайдер и allowlist. Defaults + `Normalize()`, старые JSON грузятся.
- **4.2 Раннер CLI** (план §6.4): процесс без окна, UTF-8, асинхронные stdout и stderr, JSONL построчно, лимит лога;
  Job Object через `NativeMethods`; Stop — штатное прерывание, иначе kill дерева; строка `[Agent]` в `link.log`
  (провайдер, session id, время до первого события, длительность, итог, отказы; без текста задачи).
- **4.3 Адаптер Claude Code:** аргументы по доступу (план §6.3), `--resume`, разбор событий; фикстуры — из живого
  прогона в тестовом worktree, без личных данных.
- **4.4 Адаптер Codex CLI:** `codex exec --json`, `--sandbox`, `codex exec resume`, разбор событий; фикстуры так же.
  Найти настоящий exe; если есть только `.cmd`-обёртка — запуск через `cmd.exe /d /c` с аккуратным экранированием и
  пометкой в отчёте. Проверить, может ли Codex открыть картинку посреди работы (нужно этапу 5).
- **4.5 Тесты:** разбор фикстур обоих провайдеров; фейковый CLI в `tests` (поток событий, задержка, обрыв, мусорная
  строка, ненулевой код) — Stop, ошибки и отсутствие процессов-сирот.
- **4.6 Маршрут:** в `[Chat ▾]` появляется Agent с провайдером и доступом; подсказка «Агентом» по глаголам действия
  (без модели); кнопка «Агентом» и `Ctrl+Enter` (сейчас он отправляет в Chat) открывают карточку подтверждения
  (план §7.3): провайдер, проект, workspace, доступ, «Сначала план», копия перед Do, вложения, цель (правится).
- **4.7 Activity** в хосте панели (план §7.4): строка состояния (провайдер, время, реальный текущий шаг), события
  пачками ≤ 10/с, изменённые файлы с «Открыть», итог, Stop всегда виден, stdout/stderr по запросу; иконка tray и звуки;
  голос — только старт, нужное решение и итог в 1–2 фразы.
- **4.8 Изменения и откат:** git — `git status --porcelain` до и после задачи; «Отменить изменения агента» — только для
  файлов, которые до задачи были чистыми, и только после подтверждения. Без git — копия файлов области задачи в
  `%LocalAppData%\Link\Backups\<задача>` перед Do и «Восстановить копию» с подтверждением; хранить 5 последних копий.
- **4.9 NeedsInput v1** (план §5.2, п. 2): Claude — `permission_denied` → карточка «Разрешить и повторить» (resume с
  расширенным allowlist; «всегда для проекта» — в профиль); Codex — отказ sandbox → предложить повтор в Do после
  подтверждения; «Сначала план» — план в режиме только чтения, затем «Выполнить».
- **4.10 Перенаправление и документы:** `↻ Агентом` на ответе Chat (карточка с тем же снимком), `↻ В чат` после агента
  (итог и список файлов — чипом в контекст); README, PROJECT_CONTEXT, статус этапа в плане §2.

## Не делать

- Свой агентный цикл, MCP-сервер в LINK, ConPTY, `bypassPermissions` и `danger-full-access`.
- Агент на основном checkout LINK; чтение или копирование токенов CLI; новые зависимости.

## Готово, когда

- В тестовом worktree с каждым установленным провайдером: вопрос в режиме чтения ничего не меняет; небольшая правка с
  тестом в режиме изменений показывает шаги, файлы и итог.
- Stop срабатывает сразу; после выхода из Link процессов `claude` и `codex` нет.
- Простой Chat ведёт себя как раньше; сборка Release — 0 warnings, тесты зелёные.

## Чеклист пользователю

1. Settings: видны оба провайдера и их статус «установлен / вошёл».
2. «Объясни, как устроен VoiceSession» агентом в режиме чтения — ответ есть, файлы не изменены.
3. Небольшая правка с тестом в режиме изменений — карточка, шаги, файлы, итог голосом; то же с другим провайдером.
4. Stop посреди работы — останавливается и показывает, что уже изменено.
5. «Отменить изменения агента» возвращает файлы.
6. `↻ В чат` после агента: вопрос «почему так?» уходит в ChatGPT с итогом работы.
7. Выйти из Link во время работы агента — в диспетчере задач не остаётся `claude` и `codex`.
