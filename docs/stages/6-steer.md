# Этап 6 (по желанию) — поправки без остановки

Команда для нового чата: «Выполни этап из docs/stages/6-steer.md».

- **Зачем:** поправка во время работы доходит до агента на границе шага, не обрывая долгую сборку или вызов редактора
  через MCP; Stop останавливает штатно, а не только убийством процесса.
- **Уже есть:** Correct = Stop и продолжение той же сессии со словами, After this = очередь до конца прогона (этап 3);
  Claude Code в `-p --output-format stream-json`, Codex в `exec --json` (`ClaudeCodeProvider`, `CodexProvider` поверх
  `CliAgentProvider` и `AgentProcess`); Console.
- **Зависит от:** этап 3. Прочитать: `CLAUDE.md`, [план](../WORKSPACE_PLAN.md) §4.4, §6.9, §8, §9.

## Перед началом

- `git status`, `git log --oneline -20`: шаги с коммитами `[6.x]` уже сделаны — продолжить с первого несделанного.
- Живые прогоны обоих CLI нужны (протоколы и hooks сверяются только вживую): получить разрешение пользователя.
- Сверить версии CLI и документацию app-server и hooks по §10 плана: протоколы меняются.

## Шаги

- **6.1 Claude: hook PostToolUse.** Прогон LINK получает `--settings` с hook `PostToolUse`, который печатает
  `additionalContext` из файла поправки этого прогона и удаляет файл (§6.9 плана). Проверить: какой оболочкой Claude
  Code на Windows запускает hooks, стоимость на вызов инструмента (цель — до ~50 мс), что пользовательские hooks не
  ломаются. Поправка, не дошедшая до конца прогона, продолжает сессию, как сейчас.
- **6.2 Codex: app-server.** Новый путь `CodexProvider` поверх `codex app-server` (JSON-RPC по stdio):
  `thread/start` / `thread/resume`, `turn/start`, события → те же `AgentEvent` (фикстуры из живого прогона),
  `turn/steer` для поправки, `turn/interrupt` для Stop (kill через ~2 с — запасной), лимиты из уведомлений вместо
  журнала. Доступ, MCP-серверы и `safe.directory` — как в `exec`. Путь `exec` остаётся за настройкой.
- **6.3 Интерфейс.** Поле во время работы: `Enter` — `Correct: delivered at the next step`, отдельная кнопка
  `Stop and say` — нынешнее поведение для срочного. Строка `Correction` в ленте отмечает, когда поправка дошла.
- **6.4 Тесты и документы.** Фейковый app-server и фейковый hook в тестах; README, PROJECT_CONTEXT (решение и цифры:
  задержка доставки поправки, стоимость hook).

## Не делать

- Отказ от пути `exec` до проверки app-server на реальных задачах пользователя.
- Hooks в настройках пользователя Claude Code: только `--settings` прогона LINK.

## Готово, когда

- У обоих агентов поправка во время долгой команды доходит после неё, без остановки; Stop — штатный и сразу.
- Запасные пути работают; сборка 0/0, тесты зелёные.

## Чеклист пользователю

1. Задача с долгой сборкой: поправка во время сборки — сборка не обрывается, агент учитывает поправку.
2. То же на Codex.
3. `Stop and say` — останавливает сразу.
4. Задача в Unreal через MCP: поправка не обрывает вызов редактора.
