# Этап 5 — сценарий Нори

Команда для нового чата: «Выполни этап из docs/stages/5-nori.md».

- **Зачем:** пункт брифа «проектные tools»: главный сценарий брифа проходит на настоящем проекте — вопросы через Chat
  без изменений в Blender, «исправь и экспортируй» через агента с копией, кадрами проверки и итогом.
- **Уже есть:** всё из этапов 1–4: панель, состояние и рабочая папка проекта, маршруты, агент на выбор, откат.
- **Зависит от:** этап 4. Прочитать: `CLAUDE.md`, память проекта, [план](../AGENT_HARNESS_PLAN.md) §2, §4 (главный
  сценарий), §5.2 (п. 4, 10), §6.6–§6.7, §9.

## Перед началом

- `git status`, `git log --oneline -20`: шаги с коммитами `[5.x]` уже сделаны — продолжить с первого несделанного.
- Спросить пользователя: путь к проекту Нори; что такое Land (анимация, поза, объект) и что значит «исправить»; формат
  и путь экспорта, нужен ли импорт в Unreal; путь и версия Blender; есть ли в проекте git; какой провайдер агента.

## Шаги

- **5.1 Проект «Нори» в LINK:** рабочая папка, состояние проекта (персонаж, пайплайн Blender → экспорт → Unreal,
  правила имён — коротко и подтверждённое пользователем), провайдер по умолчанию.
- **5.2 Skill `land-fix-export`** в рабочей папке: `SKILL.md` (когда применять, шаги, проверки) и scripts —
  исправление (по договорённости с пользователем), экспорт (`bpy.ops.export_scene.fbx` или `gltf`), рендер 3–5
  кадров проверки в PNG быстрым движком. Где skills ищут Claude Code (`.claude/skills/`) и Codex — сверить с
  документацией; один источник, без двух расходящихся копий.
- **5.3 Blender без UI:** `blender -b <файл> --python <скрипт> -- <аргументы>`; путь к Blender — в профиле проекта;
  эти команды — в allowlist проекта (Claude) или режим изменений (Codex).
- **5.4 Кадры проверки** — в Activity; агент смотрит их перед итогом, если провайдер умеет (этап 4 это проверил),
  иначе их смотрит пользователь.
- **5.5 Прогон четырёх фраз главного сценария;** записать маршрут, время, что изменилось.
- **5.6 Польза обвязки:** 5 настоящих вопросов про проект — Chat с контекстом против Direct, оценка «помогло / нет /
  хуже»; вывод — оставлять ли состояние проекта в Chat по умолчанию.
- **5.7 Документы:** PROJECT_CONTEXT (результаты и решения), статус этапа в плане §2; предложить пользователю удалить
  `docs/stages`.

## Не делать

- MCP Blender, управление мышью, правки `.blend` без копии, экспорт поверх существующего файла без подтверждения.

## Готово, когда

- Четыре фразы проходят, как в брифе; на вопросах файлы Blender не меняются (время изменения и хэш те же).
- После «Исправь Land и экспортируй» есть копия, кадры проверки, экспорт и итог голосом.

## Чеклист пользователю

1. «Что с этой позой?» со скриншотом Blender — ответ Chat, файлы не тронуты.
2. «Как это улучшить?», затем `↻ Глубже`.
3. «Исправь Land и экспортируй» → Agent → карточка → кадры → экспорт → итог голосом.
4. «А почему так?» — ответ Chat с итогом работы агента.
5. Экспорт открывается там, куда нужно (Blender или Unreal).
