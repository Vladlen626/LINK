# Этап 4 — Chat ↔ Agent: из обсуждения в работу и обратно

Команда для нового чата: «Выполни этап из docs/stages/4-chat-agent.md».

- **Зачем:** решение, к которому пришли с ChatGPT, становится задачей агента в два клика, и пользователь видит и правит
  бриф до запуска; итог задачи сам возвращается в обсуждение чипом. ChatGPT в подписке обсуждает и проверяет, агент
  работает руками по точному брифу — меньше токенов агента уходит на то, чтобы заново разбираться в проекте.
- **Уже есть:** `→ Agent task` под ответом (тот же снимок — уходит вопрос, а не ответ), карточка задачи с целью,
  To chat (итог и файлы чипом `AgentResult`), рендерер ответа (Markdown, блоки — `MainWindow.Chat.cs`), инструкции
  ChatGPT `docs/harness/chat-instructions.md`, запись задачи и вкладка Task (этап 3).
- **Зависит от:** этап 3. Прочитать: `CLAUDE.md`, [план](../WORKSPACE_PLAN.md) §1, §3, §4.4, §6.8, §8.

## Перед началом

- `git status`, `git log --oneline -20`: шаги с коммитами `[4.x]` уже сделаны — продолжить с первого несделанного.
- Отправлять сообщения в ChatGPT пользователя — только с его разрешения; блок `link-task` проверять моками ответа.

## Шаги

- **4.1 Бриф из ответа.** `→ Agent task` на ответе ChatGPT: бриф = выделенный в ответе текст, иначе блок `link-task`,
  иначе весь ответ; плюс «From the discussion: <вопрос>» и чипы снимка. Цель — первая строка брифа (или Title блока),
  правится. Чистая функция сборки брифа с тестами.
- **4.2 Карточка показывает бриф.** Карточка задачи: цель, бриф целиком (правится), чипы того, что уйдёт с ним
  (снимки, заметка проекта, буфер) с ×, агент, уровень, доступ, Plan first, Run. В записи задачи бриф — строка
  `Brief` ленты; What Link gave показывает его.
- **4.3 Блок `link-task`.** Инструкции ChatGPT (по-английски, как сейчас): когда обсуждение пришло к работе для
  агента, ответ кончается fenced-блоком `link-task` — Title, Goal, Decisions, Done when, Where (если известно).
  Рендерер рисует такой блок карточкой с кнопкой `Give to agent` (открывает карточку задачи с этим брифом); разбор
  терпим к пропущенным полям. README — как обновить инструкции проекта ChatGPT.
- **4.4 Итог — в обсуждение.** Задача кончилась (`Done`, `CheckFailed`, `Stopped`): чип `Task result` сам ложится в
  context stack следующего вопроса Chat — цель, итог, файлы с `+/-`, проверка, что осталось (из последних слов
  агента); × убирает, после отправки чип уходит. To chat заменяется на `Discuss in chat` в ⋯ Task: карточка, адресат
  ChatGPT, чип и фокус в поле.
- **4.5 Diff для ревью.** В чипе `Task result` — `with diff`: diff изменённых файлов от «до задачи» до ~30 КБ, больше —
  `--stat` и пометка; без git — список. Чип показывает размер. Тест на обрезку.
- **4.6 Документы и тесты.** README (путь «обсудил → бриф → задача → поправки → итог в чат», схема mermaid вместо
  нынешней), PROJECT_CONTEXT (решения: бриф из ответа, `link-task`, итог чипом, diff по желанию),
  `chat-instructions.md`, тесты сборки брифа, разбора блока и чипа итога.

## Не делать

- Писать в ChatGPT без отправки пользователем; посылать diff без его выбора.
- Бриф передачи между агентами (этап 5); новые окна.

## Готово, когда

- Ответ ChatGPT (целиком, выделение или блок `link-task`) → карточка с брифом → Run: в Task бриф и What Link gave
  совпадают с тем, что ушло.
- После задачи следующий вопрос в Chat несёт `Task result` (с diff по желанию), × убирает его.
- Сборка 0/0, тесты зелёные.

## Чеклист пользователю

1. Обсудить с ChatGPT небольшую правку, выделить нужную часть ответа → `→ Agent task`: бриф в карточке, его можно
   поправить.
2. Обновить инструкции проекта ChatGPT из `chat-instructions.md`; попросить «оформи задачу» → блок с `Give to agent`.
3. После задачи спросить ChatGPT «проверь, что сделал агент» — уходит `Task result`; с `with diff` — и diff.
4. × на `Task result` — следующий вопрос уходит без него.
