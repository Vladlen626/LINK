# Этап 1 — экран и контекст: что видит модель

Команда для нового чата: «Выполни этап из docs/stages/1-screen.md».

- **Зачем:** захват окна и монитора работает в играх и fullscreen; LINK не мигает и не отнимает фокус; пользователь до
  отправки видит, что увидит модель, а в ответе — что она увидела.
- **Уже есть:** GDI-захват (`Windows/ScreenCaptureService.cs`), закреплённое рабочее окно
  (`Windows/CurrentApplicationService.cs`), Auto active window on send, выбор области, панель превью и чипы context
  stack (`MainWindow.Capture.cs`, `MainWindow.xaml`), показ без активации (`ShowPassive`).
- **Зависит от:** ничего. Прочитать: `CLAUDE.md`, [план](../WORKSPACE_PLAN.md) §1, §3, §4.1, §4.5, §5, §6.1, §6.2,
  §8, §9.

## Перед началом

- `git status`, `git log --oneline -20`: шаги с коммитами `[1.x]` уже сделаны — продолжить с первого несделанного.
- Спросить пользователя: в каких играх и приложениях захват ошибался и как (чёрный кадр, LINK пропадает, игра
  сворачивается, не тот кадр); какая клавиша удобна для «Ask about the screen (hold)» (F13–F24 тоже подходят).
- Игр у агента нет: проверка на играх — в чеклисте пользователя. Своё — окна браузера с аппаратным видео, WPF,
  Explorer; строки `[Capture]` в `link.log` тестовой копии.

## Шаги

Ядро — 1.1–1.4, интерфейс — 1.5–1.8. Если чат кончается, остановиться на границе шага.

- **1.1 Строки `[Capture]` и проверка чёрного кадра.** До смены захвата: в `link.log` — способ, что снималось, размер,
  мс, чёрный ли кадр (выборка пикселей, чистая функция с тестом); без заголовков окон. Чёрный кадр не прикладывается
  молча: статус с причиной (§6.1 плана).
- **1.2 Windows.Graphics.Capture.** Целевая платформа `net10.0-windows10.0.22621.0` (проверить: сборка 0/0, CI,
  размер вывода, время старта — проекция грузится только при захвате). Окно и монитор через WGC (§6.1): D3D11 и interop
  — P/Invoke в `NativeMethods`, один кадр с таймаутом, без курсора и без жёлтой рамки, где можно; кадр — в
  `ScreenshotHistoryService` как сейчас. Цепочка: WGC → `PrintWindow(PW_RENDERFULLCONTENT)` для окна, нынешний
  `CopyFromScreen` для монитора → проверка чёрного кадра. Устройство и сессия освобождаются после кадра; замерить
  память и мс.
- **1.3 Без мигания и без кражи фокуса.** Окно (Active window, авто-кадр при отправке, Fresh screen) снимается WGC без
  `Hide`/`Show` LINK. Монитор, весь экран и область — LINK прячется, как сейчас. После любого захвата LINK
  активируется, только если был активен до него (сейчас `PresentAfterCapture` активирует видимый LINK). Тест на
  решение «показать / активировать» как чистую функцию.
- **1.4 Fullscreen.** Определение: `SHQueryUserNotificationState` (P/Invoke в `NativeMethods`) и геометрия рабочего
  окна — чистая функция с тестами. Над fullscreen: hotkeys захвата, push-to-talk и отправки показывают LINK без
  активации; поверх эксклюзивного fullscreen карточка не показывается — статус в tray и уведомление «LINK can't draw
  over exclusive fullscreen: ask by voice, or switch the game to borderless»; ответ, если вопрос голосовой, звучит.
- **1.5 Строка Sees.** Вместо кнопки Screen с точкой и панели превью: одна строка под полем — миниатюра и цель
  (`Blender · window · fresh frame on send`, `Monitor 2`, `Region`, `Nothing`), ▾ — бывшее меню Screen (This window
  now, Fresh window on every send, Current monitor, All monitors, Full desktop, Select region, Nothing). При авто-кадре
  миниатюра — кадр рабочего окна в памяти при показе LINK (не сохраняется и не уходит; клик — обновить). Direct прячет
  строку, как сейчас прячет авто-кадр.
- **1.6 Чип приложения.** Строки «Application» и «Window» Chat-запроса — видимый чип `Blender · <заголовок>` с × на
  один вопрос (общий механизм, который сейчас есть у состояния проекта); полный заголовок — в подсказке.
- **1.7 «saw: …» в ответе.** Шапка ответа перечисляет, что ушло: миниатюра кадра (клик открывает PNG) и метки чипов —
  из снимка ввода, а не из текущей карточки. Короткая оранжевая рамка (~0,5 с, без анимации, click-through, без
  активации) вокруг снятого окна в момент авто-кадра — как у Copilot Vision; над fullscreen не показывается;
  выключается в Settings → Behavior.
- **1.8 Вопрос голосом про экран.** Hotkey «Ask about the screen (hold)» в Settings → Global hotkeys (низкоуровневый
  hook, как у push-to-talk): держишь — говоришь — отпускаешь → вопрос уходит в Chat со свежим кадром рабочего окна,
  ответ звучит голосом; LINK — без активации, над эксклюзивным fullscreen — только голос и уведомление. Это явное
  действие; Conversation Mode не трогается.
- **1.9 Документы и тесты.** README (контекст, hotkeys, ограничения про эксклюзивный fullscreen, рисунок карточки),
  PROJECT_CONTEXT (решения: WGC, без мигания, Sees, fullscreen, вопрос про экран), тесты шагов 1.1–1.8.

## Не делать

- Хуки и внедрение в процессы игр (как Game Capture в OBS — античиты), DXGI Desktop Duplication — только если WGC
  массово не справится и пользователь согласится.
- Постоянный захват или запись видео; захват без действия пользователя или включённого режима.
- Новые зависимости, кроме проекции Windows SDK; переделку маршрутов и чипов проекта (этап 2).

## Готово, когда

- Окно в браузере с аппаратным видео, WPF и Explorer снимаются верно, LINK не мигает и не уводит фокус; монитор и
  область — как раньше.
- Чёрный кадр не уходит молча; строки `[Capture]` объясняют путь.
- Строка Sees до отправки и «saw: …» после совпадают с тем, что ушло (снимок ввода).
- Старт по-прежнему ~1 с, память в простое — в пределах нескольких МБ от прежней; сборка 0/0, тесты зелёные.

## Чеклист пользователю

1. Игра в borderless: `Ctrl+Alt+W` — кадр игры, игра не теряет фокус, LINK не мигает.
2. Та же игра в эксклюзивном fullscreen: понятное сообщение вместо чёрного кадра; вопрос голосом про экран работает.
3. Unreal или Blender с Auto active window: строка Sees показывает окно до отправки, «saw: …» — после.
4. Видео в браузере на весь экран — кадр не чёрный.
5. Чип `Blender · <заголовок>`: × убирает его из одного вопроса.
6. Монитор и область — снимаются как раньше.
7. Hotkey «Ask about the screen»: держать — сказать — отпустить: ответ голосом, без переключения окна.
