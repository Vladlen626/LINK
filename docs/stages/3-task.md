# Этап 3 — задача агента: одна история

Команда для нового чата: «Выполни этап из docs/stages/3-task.md».

- **Зачем:** вместо россыпи запусков — одна задача с непрерывной историей. Всегда видно: кто работает, над чем, что
  сделал, что делает сейчас, что LINK ему передал, куда уйдёт следующий комментарий, сколько usage потрачено.
  Stop, поправка, «после этого», Start over, Hand off, Finish — разные действия с разными словами.
- **Уже есть:** вкладка Task и пилюля агента (этап 2); прогоны и их «до задачи» (`AgentRun`, `AgentCoordinator`),
  продолжение, слова во время работы (Stop и продолжение той же сессии), Start over, передача v1, проверка после Do,
  откат, Save as skill, цифры прогона (`AgentStats`), Console; сессии в `Projects\<id>\agent-sessions.json`
  (`ProjectService`, `AgentSessionRecord`); состояние окна — в `MainWindow.Agent.cs`.
- **Зависит от:** этап 2. Прочитать: `CLAUDE.md`, [план](../WORKSPACE_PLAN.md) §3, §4.2–§4.4, §5, §6.3, §6.4, §6.6,
  §8, §9.

## Перед началом

- `git status`, `git log --oneline -20`: шаги с коммитами `[3.x]` уже сделаны — продолжить с первого несделанного.
- Спросить пользователя про живые прогоны для фикстур: 1–2 коротких на агента (тратят лимиты) — нужны строки плана
  (`TodoWrite` или `TaskCreate` у Claude, `todo_list` у Codex) и `rate_limit_event` Claude. Без разрешения — фикстуры
  по схемам из плана с пометкой «не сверено вживую» в отчёте.

## Шаги

Ядро — 3.1–3.4, интерфейс — 3.5–3.8.

- **3.1 Запись задачи.** `AgentTaskRecord` и лента (§6.3 плана) в `Projects\<id>\agent-tasks.json`, 20 последних,
  через `AtomicJsonFile`; defaults и `Normalize()`. Чтение `agent-sessions.json` — задачами из одного прогона.
  Тесты: запись, чтение старых сессий, обрезка.
- **3.2 Все прогоны — в задачу.** Run открывает задачу; Reply, слова во время работы, Start over, Plan → Run the plan,
  возвраты проверки, Allow and retry, Retry with edits и передача v1 пишут в ту же запись (прогон и строки ленты).
  Новая задача — только Run из карточки; открытая задача при этом сначала закрывается (Finish) — с вопросом, если
  агент работает. Состояние окна (`_lastRun`, `_agentOrigin`, `_earlierSession`, `_taskSteps`…) сводится к текущей
  задаче, где это упрощает код.
- **3.3 План агента.** `AgentEventKind.Plan`: Claude — `TodoWrite` и, если встретится, `TaskCreate` / `TaskUpdate`;
  Codex — `todo_list` (§6.4 плана). Последний план — в записи задачи. Тесты по фикстурам.
- **3.4 Usage и окна лимитов.** Суммы токенов задачи по агентам; для Codex — разница с прошлым итогом сессии.
  Claude — разбор `rate_limit_event`; Codex — после прогона последняя строка `rate_limits` из журнала его сессии
  (только числа). Последнее известное — `agent-limits.json` с временем (§6.6 плана). Тесты разбора и разницы.
- **3.5 Вкладка Task.** Сверху: цель; `Claude Code · Opus 5.5 · high · Auto`; состояние, время и текущий шаг. Ниже:
  Plan (отметки и «2/4»); History задачи (бриф, поправки, прогоны, проверки, передачи — коротко, раскрываются);
  Changed за всю задачу (`+/-` из `git diff --numstat` от «до задачи», без git — список; клик — в Explorer, как
  сейчас); What Link gave — читаемый текст, который LINK отдал первым, и каждая добавка (поправка, бриф передачи) —
  Console остаётся для сырого; Usage — токены задачи, окна `Claude: 5 h 82% (resets 15:45) · week 31%` и то же у
  Codex, время данных; $ — только в подсказке «≈ API prices». Шаги Activity — в раскрываемом блоке, как сейчас.
- **3.6 Действия.** Поле ответа говорит, куда уйдут слова: во время работы — `Correct Claude: Enter stops the step and
  goes on with your words · Tab: after this`; после — `Reply to Claude: the same session goes on`. `Tab` ставит слова в
  очередь: после прогона та же сессия продолжается ими (строка `Queued` в ленте, × — отменить). Кнопки: Stop (пока
  работает), Start over, Hand off ▾ (пока — передача v1), Finish; в ⋯ — Undo changes, Save as skill, To chat,
  Console. Подписи и подсказки — по §4.4 плана.
- **3.7 Лимит.** Прогон кончился на лимите (`rate_limit_event` со статусом отказа или нынешний `LimitReached`): строка
  `Limit` в ленте и `Claude hit its 5-hour limit, resets 15:45` с кнопками Hand off to Codex и Continue at 15:45
  (таймер до сброса +1 мин, отменяемый, виден в Task и пилюле).
- **3.8 History и пилюля.** Лента проекта (этап 2) показывает задачи вместо сессий; клик открывает задачу во вкладке
  Task (прошлая — только чтение ленты, Reply продолжает её последнюю сессию в её папке, как сейчас). Пилюля и строка
  состояния — по задаче. Строка `[Agent]` в `link.log` получает id задачи.
- **3.9 Документы и тесты.** README (раздел 3 заново: одна задача, действия, usage; рисунок `agent.svg`),
  PROJECT_CONTEXT (решения: задача как единица, план агента, окна лимитов, Correct / After this). UI-проход — фейковым
  `.cmd` CLI с фикстурой в тестовой копии.

## Не делать

- Параллельные задачи, worktree на задачу, новые окна кроме Console.
- Смену протоколов CLI (этап 6), уровни моделей и бриф передачи v2 (этап 5).
- Живые прогоны без слова пользователя; чтение журналов CLI сверх строк `rate_limits` своей сессии.

## Готово, когда

- Задача с поправкой во время работы, красной проверкой, Start over и передачей v1 — одна задача с одной лентой.
- План агента, изменения за всю задачу, What Link gave и Usage видны; окна лимитов — у Codex по журналу, у Claude —
  после прогона с `rate_limit_event` (или пометка «не сверено вживую»).
- Correct и After this ведут себя по подписям; Stop, Start over, Hand off, Finish различимы.
- Старые сессии открываются задачами; сборка 0/0, тесты зелёные.

## Чеклист пользователю

1. Задача на Claude: в Task видны агент, модель, шаг, план «x/y», что LINK передал.
2. Во время работы `Enter` с поправкой — агент продолжает с ней, в ленте строка поправки; `Tab` — слова ждут конца.
3. Красная проверка и Start over — всё в той же задаче.
4. Usage: токены задачи и окна 5 h / week у Claude и Codex с временем сброса.
5. Finish → History показывает задачу; клик открывает её ленту, Reply продолжает.
6. Старая сессия из AGENT SESSIONS видна задачей.
7. На лимите (если случится): Hand off to Codex и Continue at … предложены.
