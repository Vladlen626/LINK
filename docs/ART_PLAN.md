# LINK Art — художник игры в её стиле

Основа — два PDF пользователя (09.10: «LINK × DREDGE-style: production pipeline» и «DREDGE Asset Pipeline») и
источники из них: разбор DREDGE от Black Salt Games (Unity), Blender Agent Studio, Infinigen 2.0. Цель: 3D Artist
LINK делает ассеты игры в её стиле — сейчас DREDGE-like, потом любой другой — а повторяющиеся классы ассетов
генерирует, а не моделит каждый. Идёт поверх [TRAINING_PLAN.md](TRAINING_PLAN.md) и [TEAM_PLAN.md](TEAM_PLAN.md) и
закрывает там TR.5 (Visual Critic, Reference Board) и TR.6 (sweep).

## Решения пользователя (09.10)

1. **Движок — Unity**, сетап на ПК пользователя (раздел «Локально на ПК»).
2. **Общее — в общем LINK, всё про стиль — в проекте.** Пакет `blender` держит только ремесло: как строить, снимать,
   красить палитрой, генерировать и судить по любому профилю. Как выглядит эта игра (палитра, камера, приём «тень
   гранью», пропорции, бюджеты, запреты) — только в её `docs/art/`. Общего skill-архетипа `style-faceted` нет.
3. **Кто критик, а кто работает — решает LINK.** Критик — другой агент, чем у художника (Codex судит Claude и
   наоборот), иначе новая сессия того же; LINK учится по оценкам пользователя, кто из них судит как он.
4. **Генераторы — Python (bmesh) первым,** Geometry Nodes — для scatter и инстансов; главное — контракт.

## Как устроено

| Слой | Где | Что |
|---|---|---|
| Ремесло, все игры | пакет `blender` (`%USERPROFILE%\LinkPacks`): `blender-live` (`shots.py`, `sheet.py`), `blender-model` (+`palette.py`, `vehicle.md`), `blender-procedural` (`gen.py`, `example_crate.py`), `art-style`; роли `3d-artist`, `art-critic` | Стадии, кадры как видит игрок, палитра-атлас, генераторы, критика по ledger — без вкуса |
| Стиль игры | проект: `docs/art/STYLE.md` (front matter с цифрами для скриптов + стиль словами + `## Rubric`), `docs/art/REFERENCES.md` (роль каждого референса), `Art/Approved/<asset>/` (линейка одобренных), `tools/blender/generators/`, `.agents/skills/blender-project/` | Палитра, игровая камера, фон, размер миниатюры, finish, бюджеты по классам, словарь форм, запреты |

- **Стиль судят там, где его видит игрок:** `shots.py` с `style=docs/art/STYLE.md` — вид `game` (игровая камера),
  `thumb` (объект мелко на экране), look `flat` (одни цветовые зоны); `sheet.py` склеивает кадр с `gamecam.png`
  одобренных ассетов класса в одну линейку. Отдельного `lookdev.blend` нет: камера и фон из профиля, финальное слово —
  кадр из движка (позже).
- **Палитра:** `palette.py` красит грани по материалам-зонам (`rust`, `hull`) в один атлас и материал; атлас — в Unity
  без фильтрации и mipmaps.
- **Генератор** — файл с `PARAMS`, `BUDGET`, `build(p, rng)`, `check()`, `PRESETS`; `gen.py <генератор> test` —
  контракт (default, min/max каждого параметра, seeds, детерминизм), `1-12` — sweep с игровой камеры в один лист,
  `<seed> <preset>` — сборка с записью `.gen.json` (генератор, версия, seed, параметры, хэш), чтобы собрать снова.
- **Критик** — роль LINK `art-critic`, только чтение и вслепую: видит задачу, переданное (`Handed over`), сохранённые
  файлы, референсы пользователя и кадры, которые назвал художник (первые 6 — картинками), но не рассказ художника.
  Ответ — ledger (pass / fail / unclear с кадром), 1–3 худших дефекта с конкретным действием, `link-review` с
  вердиктом и оценкой 1–5. Чего профиль не решает — вопрос пользователю в замечаниях.

### Ассет в команде (Team)
```
бриф ─► ведущий: шаг asset (уникальная модель или новый генератор, Strong) или instance (у проекта есть генератор, Standard)
     ─► художник (3D Artist + art-style, видит референсы задачи): кадры game / thumb / flat + линейка, пути в ответе
     ─► критик (другой агент на Deep, effort роли): accept ─► дальше (или OK пользователя, если шаг «на вкус»)
                                                  redo ─► в сессию художника с дефектами, не больше двух раз
                                                  stop / два круга ─► OK пользователя с замечаниями критика
```
- Шаг арта идёт только агенту, который видит картинки, и не ниже Standard; своя модель (GLM) не рисует и не судит.
- Критик заменяет у шагов арта ревью ведущего; ведущий не планирует для него шагов и не видит его среди специалистов.
- Ваши слова после вердикта идут художнику вместе с замечаниями критика (критик говорил их в своей сессии).
- «Сделай 20 скал»: есть `tools/blender/generators/rock.py` — шаг instance: sweep seeds → линейка → лучшие → сборка с
  `.gen.json` → критик судит семейство (seed не к месту — дефект генератора, а не seed); нет — шаг asset: генератор
  с тестом контракта, когда класс повторился (2–3 одобренных или просят много).
- Hero (лодка, маяк, существо) — `unique`: стадии `blender-model`; ведущий может разбить его на шаги (blockout, формы,
  детали), тогда критик судит каждый.

### Обучение (Train)
- Учёба: урок о том, как выглядит игра, — `"skill": "style"`, проектный; после сданного экзамена он идёт в
  `docs/art/STYLE.md`, ремесло — в копию skill пакета, приёмы игры — в `blender-project`.
- Экзамен специалиста со стилем: до оценки пользователя его кадры (`sheet` экзамена) судит критик; оценка критика и
  дефекты видны рядом с кнопками оценки. Оценка пользователя засчитывается критику в `workers.json` (вид `Critique`):
  согласие — обе ≥4 или обе ≤3. Критик, который не согласился 2 раза и больше и чаще, чем согласился, в проекте
  больше не судит; доказанный (3 согласия и больше, расхождений не больше четверти) идёт первым.
- Сданный ассет сессия экзамена кладёт в линейку `Art/Approved/<asset>/` (`gamecam.png`, `.gen.json`).
- Лестница экзаменов (реальные ассеты игры): простой проп (ящик, буй) → семейство окружения (скала, док) через
  генератор → постройка (сарай) → hero (лодка).

## Развить, урезать, выкинуть (относительно PDF)

- **Развито:** игровая камера и линейка с одобренными как главная проверка стиля; ledger и действия вместо «сделай
  красивее»; калибровка критика оценками пользователя; генератор как контракт с seed и записью; роли референсов
  (STYLE, SHAPE, MATERIAL, FUNCTION).
- **Урезано:** оценка 1–5 — для порога и калибровки, решают ledger и дефекты; полная проверка в движке — на генератор
  и hero; review sheet на 24 кадра — только где нужна конструкция; таблица семейств — когда класс повторился.
- **Выкинуто:** общий архетип стиля (решение 2); `lookdev.blend` и отдельный `sweep.py` (камера из профиля, sweep в
  `gen.py`); поле `route` в плане (виды шагов asset / instance); DRAFT image→mesh, отдельный Asset Studio, база
  ассетов, Reference Board как UI (файлы `docs/art/` и `Art/Approved/`).

## Локально на ПК — что доделать

1. **Обновить Link:** забрать ветку, собрать и перезапустить (`rebuild-link`); тесты — на Windows
   (`Link.Desktop.Tests.exe`), сначала проверить строку сборки «Ошибок: 0».
2. **Пакет blender в `%USERPROFILE%\LinkPacks`:** новые файлы (`art-style`, `blender-procedural`, `palette.py`,
   `vehicle.md`, роль `art-critic`) Link положит сам. Изменённые здесь `shots.py`, `sheet.py`, `blender_mcp.py`,
   `blender-live/SKILL.md`, `blender-model/SKILL.md`, роль `3d-artist` он обновит, только если вы их не меняли;
   если меняли — свести вручную с `docs/harness/packs/blender`.
3. **Unity (сетап игры):**
   - атлас палитры: Filter Mode Point, Generate Mip Maps off, Compression None, sRGB on;
   - FBX из Blender: Apply Scalings FBX All, Forward −Z, Up Y, Apply Transform; в Unity у корня rotation 0 и scale 1,
     иначе Bake Axis Conversion;
   - материал проекта под атлас (`M_Palette` на шейдере игры) и его remap в импортёре FBX;
   - мост `unity-editor` (Unity CLI) к открытому редактору — проверить на проекте игры;
   - цифры игровой камеры (наклон, FOV, дистанция, поворот) — из Camera сцены, для `camera:` в `STYLE.md`.
4. **Арт-профиль игры:** задача 3D Artist «Набросай арт-профиль игры» с референсами (скриншоты DREDGE, концепты) →
   `docs/art/STYLE.md` и `REFERENCES.md`; палитру, камеру и бюджеты подтвердить самому. Папки `Art/Approved/` и
   `tools/blender/generators/` создаст работа.
5. **Blender вживую через MCP:** `gen.py example_crate.py test` (скопировав пример в `tools/blender/generators/`),
   `shots.py … "style=docs/art/STYLE.md"`, `palette.py`, `sheet.py` с линейкой — один раз на живом мосте.
6. **Первый генератор игры** (скалы или ящики): Team «сделай генератор скал», потом «сделай 20 скал».
7. **Критик в команде:** строка выбора критика в ленте, что Codex видит кадры, круг redo, карточка OK с замечаниями,
   ваши слова художнику с замечаниями, Settings → Agents → Art critic (вёрстка галки на узком окне).
8. **Train на источниках PDF** (Unity, 80.lv, Game Developer из облака закрыты): учёба → лестница экзаменов → оценка
   критика рядом с вашей → запись `Critique` у критика в `workers.json` проекта (её видит и ведущий).
9. **Одобренное в команде:** после OK шага арта Link сам не кладёт ассет в `Art/Approved/` — скажите художнику
   «одобряю, положи в Approved» (сданный экзамен делает это сам).

## Дальше — после живых прогонов

- Если «положи в Approved» повторяется — Link сам копирует `gamecam.png` и `.gen.json` на OK шага арта.
- Кадр ассета из движка (Game view Unity через `unity-editor`) как финальное доказательство стиля.
- Недостающие виды концепта — через встроенную страницу ChatGPT (гипотеза, не геометрия).
- Где критик не согласен с пользователем — Train самого критика: уроки в `art-critic` и rubric профиля.

## Риски

- Вид в Blender ≠ вид в игре (шейдер, туман, пост): камера и фон из профиля приближают, решает кадр из движка.
- Картинки дорогие: критику — не больше 6 кадров картинками, остальные путями; линейка — один лист.
- Визуальный выигрыш непостоянен даже у хороших skills (замеры Blender Agent Studio): решает оценка пользователя,
  критик калибруется по ней, уроки доказываются экзаменами.
- Генератор переобучается на одну форму: тест default / min / max и нескольких seeds, линейка с одобренными.
