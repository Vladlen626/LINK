## Коротко

- **Ничего нового там, где Link уже умеет.** Общее = пакет `blender` в `LinkPacks` и встроенные роли; проектное = один
  арт-профиль `.agents/art/` в папке игры; критик = ещё один специалист и ревью шага команды; роутер ассетов = поле шага
  в плане ведущего; обучение стилю = обычный Train, только у уроков появляется третья цель — профиль.
- **Скрытность — правило Link, а не просьба к агенту.** Харнесс проекта не уходит в VCS игры, Link сам проверяет
  изменённые файлы на запрещённые слова проекта, агенты работу не подписывают.
- **Генераторы вместо сотни моделей.** Со 2–3-го ассета одного класса — генератор с контрактом; дальше ассет — это
  параметры и seed, их делает дешёвый работник, а критик отбраковывает слабые варианты по одному листу.

## 2. Скрытность (требование пользователя, 09.10)

В игре — в файлах, именах, метаданных, коммитах и сборке — нет ни названия игры-референса, ни следов агента.

- **Харнесс не в VCS игры.** Link при подключении проекта дописывает `.agents/` и `docs/map.md` в локальное исключение:
  git — `.git/info/exclude` (не коммитится, коллеги не видят), Perforce — локальный `P4IGNORE`-файл. Агенту — правило:
  эти пути не добавлять в VCS.
- **Запрещённые слова проекта** — в `projects.json` Link (не в репо: сам список называет референс). По умолчанию —
  названия референсов, которые укажет пользователь, плюс `claude`, `codex`, `anthropic`, `openai`, `chatgpt`,
  `ai-generated`, `generated by`. После каждого прогона с изменениями Link ищет их в изменённых файлах (текст, а в
  бинарных .blend/.fbx/.uasset — ASCII и UTF-16 строки имён) и в сообщении коммита, кроме путей харнесса. Нашёл —
  шаг не Done, а «Leak: слово в файле» и ждёт правки или OK, как UNVERIFIED.
- **Агенты не подписывают работу.** Правило в `agent-rules.md`: ни имени инструмента или модели в коде, ассетах,
  метаданных и коммитах. Claude Code — настройкой без co-author в коммитах через `--settings` (точный ключ сверить с
  установленной версией).
- **Стиль описывается своими словами.** STYLE.md, уроки и имена ассетов — язык арт-дирекции («крупные планарные грани,
  ограниченная палитра»), без названий игр и студий; refs не загружаются в .blend проекта (пути картинок остаются в
  файле), сравнение — на листе вне проекта. Это же — в промптах учёбы и Promote.

## 4. Как это ложится на то, что уже есть

- **Train.** Урок получает цель `skill`: пакетный skill (общее), `blender-project` (как строить здесь) или `style`
  (→ `.agents/art/STYLE.md`). `training-learn.md` и `training-promote.md` учат различать три цели и писать без
  названий. Экзамен: перед оценкой пользователя — прогон критика, его оценка видна рядом с самооценкой; решает всё так
  же пользователь (4–5 Pass). Rubric экзамена = rubric роли + `## Rubric` из STYLE.md.
- **Team и effort.** `link-plan` для шага `asset` получает `route`: `instance` (параметры существующего генератора) →
  Standard; `generator` (новый генератор) и `unique` (hero) → Strong. Ревью шага Asset делает не ведущий, а критик
  (новая сессия, read only, Strong, effort high), вслепую к ответу художника; `redo` → ремонт в сессии художника, не
  больше двух кругов, дальше — пользователь. `check: true` (OK пользователя) остаётся для итога партии, а не для
  каждого варианта. Auto effort не меняется: провал поднимает уровень, `link-next` художника работает как раньше.
- **UNVERIFIED** остаётся; шаг Asset без листа ревью критик возвращает `redo` «сделай лист».
- **Что упрощается.** Rubric 3D Artist оставляет только общие шкалы (форма, пропорции, game-ready), стилевые уходят в
  STYLE.md. Из TRAINING_PLAN убираются TR.5 «Visual Critic / Reference Board» и TR.6 «sweep» — они здесь.

### «Сделай 20 скал»
```
бриф ─► ведущий: есть generators/rock.py?
   нет ─► шаг asset/generator (Strong): генератор по контракту + 3 seeds ─► критик ─► OK пользователя
   да  ─► шаг asset/instance (Standard): sweep 30 seeds одним вызовом ─► один лист gamecam + цифры
          ─► критик: лучшие 20 и 1–3 дефекта ─► redo с параметрами ─► OK пользователя ─► экспорт и fresh-import
```
Hero (лодка, маяк): шаг `unique` — полный staged-workflow `blender-model`, критик на каждой стадии с формой.

## 7. Риски
- Критик на картинках стоит дорого: один лист на прогон, не больше двух кругов ремонта, sweep — одним скриптом, не
  по сессии на вариант.
- Критик тоже завышает или придирается: решает оценка пользователя, критик калибруется по ней на первых экзаменах.
- Проверка слов в бинарниках может шуметь: исключения для путей харнесса, находка — предупреждение с OK, а не стоп.
