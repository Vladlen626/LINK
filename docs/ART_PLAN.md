# LINK Art — план работ (черновик, ждёт решений пользователя)

Основа — PDF пользователя «LINK × DREDGE-style: production pipeline» (09.10) и источники из него: разбор DREDGE от
Black Salt Games (Unity), Blender Agent Studio, Infinigen 2.0. Цель: 3D Artist LINK делает ассеты игры в её стиле —
сейчас DREDGE-like, потом любой другой — и на масштабе генерирует их, а не моделит каждый. Идёт поверх
[TRAINING_PLAN.md](TRAINING_PLAN.md) (TR.1–TR.4 сделаны) и [TEAM_PLAN.md](TEAM_PLAN.md); заменяет там TR.5 (Visual
Critic, Reference Board) и TR.6 (sweep).

## Коротко

- **Стиль = профиль проекта + архетип.** Ремесло (стадии, генераторы, проверки, метод критики) — общее. Приёмы
  семейства стилей (у DREDGE: цвет и тень вырезаны геометрией) — общий skill-архетип `style-faceted`. Цифры и вкус
  конкретной игры (палитра, камера, пропорции, плотность, запреты) — `STYLE.md` проекта. Следующей игре в другом стиле
  нужен другой архетип и свой профиль, ремесло остаётся.
- **Стиль судят там, где его видит игрок.** Look-dev сцена проекта: игровая камера на трёх дистанциях, свет и туман
  как в игре, рядом — уже одобренные ассеты (lineup). Это главный лист для художника, критика и пользователя.
- **Критик — отдельная сессия с ledger, а не балл.** Требования pass / fail / unclear с видом-доказательством, 1–3
  худших дефекта, один точечный ремонт в исходнике, та же проверка, оставить ремонт или откатить.
- **Генераторы — композиция маленьких блоков с seed.** Ассет = генератор + версия + seed + параметры в sidecar-файле;
  «20 скал» — один sweep и один лист, критик отбирает.
- **Учится постепенно, через Train.** Источники → уроки-кандидаты → экзамены на реальных ассетах игры по лестнице →
  только доказанное в skills; одобренные ассеты копятся и становятся эталоном lineup; оценки критика сверяются с
  оценками пользователя.

## 1. Что дали источники

| Источник | Находка | Что делает LINK |

Часть ошибок рендера оставили: они работали на арт-дирекцию. Полигоны — на читаемую форму и рисунок тени (уточняет PDF «deceptively high-poly») |

| Blender Agent Studio | Модель = Python-исходник + .blend + экспорт; fresh-import в новом Blender; стадии с exit-критериями; контракт ассета; **finish profile** (по умолчанию «polished smooth», low-poly и faceted — только если заказаны) | Finish profile — поле STYLE.md: в faceted-проекте умолчание «сгладь всё» не протекает |
| Blender Agent Studio, refinement | Заморозить кандидата → ledger pass/fail/unclear с видом → один ремонт исходника → та же проверка → `retain_repair` / `retain_candidate`; приоритеты дефектов; критик не видит оправданий; «эстетического балла нет» | Протокол критика и ремонта (ART.4) |

| Blender Agent Studio, reference modeling | Камера по референсу, overlay силуэта, landmarks; структура отдельно от стиля; концепт задаёт силуэт, палитру и камеру, но не геометрию | Два вида референсов: style и construction (ART.2) |
| Blender Agent Studio, замеры | Skills почти всегда чинят технику (5/5 против 0/5), а визуальный выигрыш непостоянен (4/5) и стоит больше токенов | Технику закрывают skills и проверки Link, вид — критик, lineup и оценка пользователя; без них не будет стиля |
| Infinigen 2.0 (procfunc) | Генераторы из маленьких рандомизируемых блоков; `*_rand` — сэмплеры параметров; цепочки (материал из шага → вход следующего); seed на прогон, папка на seed; trace параметров; один материал на разных базовых формах | Генератор = блоки + сэмплер + цепочка «форма → палитра → экспорт»; sidecar с параметрами; палитру проверяют на нескольких формах |

выдержек. Полностью их прочитает учёба (Train) на ПК пользователя.

## 2. Где что живёт

| Слой | Где | Что |
|---|---|---|
| Ремесло (все игры) | пакет `blender`: `blender-live`, `blender-model` (стадии, finish profile), `blender-procedural` (новый, с библиотекой блоков); роли `3d-artist`, `level-artist`, `art-critic` (новая) | Как строить, проверять, генерировать и критиковать — без вкуса |
| Архетип (семейство стилей) | пакет `blender`: `style-faceted` (новый); позже `style-hand-painted`, `style-pbr`… | Приёмы и скрипты внешнего вида: как вырезать тень гранью, палитра-атлас, плотность граней по дистанции |
| Проект (эта игра) | `.agents/art/STYLE.md`, `references.md`, `refs/`, `approved/`, `lookdev.blend`; `.agents/skills/blender-project/`; генераторы в `tools/blender/gen/` | Палитра, камера, пропорции, словарь форм, плотность hero/interactive/background, запреты, rubric; генераторы и пресеты игры |

- `STYLE.md` — front matter (`skills: style-faceted`, `finish: faceted`, палитра, камера: высота, FOV, дистанции;
  бюджеты) и разделы: словарь форм, цвет и материал, иерархия деталей по важности объекта, запреты, `## Rubric`.
- Link для ролей арта в проекте с `STYLE.md` всегда добавляет его `skills:` к выбранным skills и говорит прочитать
  STYLE.md первым. Проект без профиля получает только ремесло — стиль прошлой игры не протекает.
- `references.md`: **style refs** (кадры игры-референса, концепты) — что берём (силуэт, палитра, грани, плотность) и
  чему не верим; **construction refs** (фото настоящих лодок, доков, маяков) — размеры и конструкция. Style ref
  никогда не задаёт конструкцию; AI-концепт не задаёт ни размеры, ни невидимые стороны.

### «Сделай 20 скал»
```

   нет ─► asset/generator (Strong): блоки + сэмплер + контракт, default/min/max + 3 seeds в lineup ─► критик ─► OK пользователя
```

## 4. Постепенное обучение стилю

1. **Профиль.** Задача «Art profile» (как Map): агент читает refs, источники и 2–3 существующих ассета игры, пишет
   черновик STYLE.md и references.md; пользователь правит. Это стартовые гипотезы, не доказанные правила.
2. **Учёба (Train).** Источники — разборы разработчиков, refs, одобренные ассеты. У урока три цели: ремесло (skill
   пакета), архетип (`style-faceted`), проект (STYLE.md или `blender-project`). Promote различает их.
3. **Лестница экзаменов** (все — реальные ассеты игры): простой проп (ящик, буй) — силуэт, палитра, грани → семейство
   окружения (скала, док) — генератор и seeds → постройка (сарай) — primary/secondary → hero (лодка) — весь конвейер.
   4–5 — уроки доказаны, 1–3 — остаются кандидатами (как сейчас).
4. **Калибровка критика.** На экзамене критик ставит оценку до пользователя; Link хранит обе. Где они сходятся,
   пользователь со временем смотрит только итог партии; где нет — ledger показывает, чему критик не научен (урок
   для `art-critic`).
5. **Накопление.** Каждый одобренный ассет — в lineup; повторный класс (2–3 одобренных) → художник предлагает
   генератор в `link-next`; удачные параметры — пресеты генератора.

## 5. Развить, урезать, выкинуть

- **Развить:** «false shadows» как главный приём архетипа; finish profile в профиле; lineup с одобренными как главная
  проверка стиля; калибровка критика по оценкам пользователя; композиция генераторов из блоков (Infinigen); style vs
  construction refs.
- **Урезать:** балл критика 1–5 — только для калибровки, решают ledger и дефекты; полная проверка в движке — на
  генератор и hero, не на каждый экземпляр; лист ревью по умолчанию — гейм-камера ×3, matcap силуэта, lineup (24 кадра
  `shots.py` — только для hero на game-ready: картинки дорогие); таблица семейств ассетов — не заранее, а когда класс
  повторился.
- **Выкинуть:** DRAFT image→mesh; отдельный Asset Studio; отдельная библиотека-БД (папка `approved/` и запись задачи);
  Reference Board как UI (файл `references.md`).
- **Упростить в LINK:** из `blender-model` машинная специфика (булевы корпуса, двери, стёкла, размеры авто) уходит в
  `references/vehicle.md` рядом — skill короче для каждого ассета; rubric 3D Artist — только общие шкалы, стилевые — в
  STYLE.md; TR.5/TR.6 из TRAINING_PLAN закрываются этим планом.

## 8. Риски
- Вид в Blender ≠ вид в игре (шейдер, туман, пост): look-dev приближает, финальное слово — кадр из движка (ART.8).
- Картинки дорогие: критик видит один лист; ремонт — два вида малого размера, полный лист — один раз в конце.
- Визуальный выигрыш непостоянен даже у хороших skills (замеры Blender Agent Studio): решает оценка пользователя,
  критик калибруется по ней, уроки доказываются экзаменами.
- Генератор переобучается на одну форму: тест default/min/max и нескольких seeds, lineup с одобренными.
