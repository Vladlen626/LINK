# LINK Training — план работ

Основа — PDF пользователя «LINK Agent Training» (09.10): специалист учится по материалам, сдаёт практический
экзамен по референсам, и только доказанное попадает в skill. Идёт поверх [TEAM_PLAN.md](TEAM_PLAN.md) (T.0–T.6
сделаны) и пакетов инструментов. Из assets_studio (`docs/guides/3d.md`, `process.md`) взято: оценка по шкале, работы на
4–5 разбирают и переносят приёмы в шаблон, на 1–2 — переделывают по названной причине; стадии и проверки формы.

## Коротко

- **Учёба — режим задачи, не второй харнесс.** На карточке задачи галочка **Train**: выбранный специалист изучает
  источники (ссылки в тексте, PDF и картинки во вложениях) и пишет короткие **уроки-кандидаты**. Лекции в рабочие
  промпты не попадают никогда.
- **Экзамен — настоящая задача пользователя.** «Ready for exam» → следующие слова пользователя (задача + референсы)
  идут в новую сессию специалиста, где есть только уроки-кандидаты и rubric — так проверяется, что урок работает
  сам по себе. Сдача: файл-источник, review sheet, технические проверки, самокритика по rubric.
- **Оценка — пользователя, 1–5.** 4–5 — Pass: уроки, применённые на экзамене, становятся доказанными и записываются
  в skill пакета (общие) или `<pack>-project` (проектные); дальше обычный «Share with all games». 1–3 — Fail: уроки
  остаются кандидатами. Экзамен без изменённых файлов — **UNVERIFIED**, пройти не может.
- **UNVERIFIED и в команде.** Шаг вида Asset, «сделанный» без единого изменённого файла, не идёт в `workers.json` как
  успех и ждёт OK пользователя.

## 1. Решения по открытым деталям (09.10)

| Вопрос | Решение |
|---|---|
| Где Train | Галочка на карточке задачи, рядом с Team (не отдельное окно и не кнопка). Специалист — обычный чип; тема и источники — текст цели и вложения |
| Training Library | Сама учебная задача в истории проекта: источники, уроки, экзамены и оценки хранятся на её записи. Второй памяти нет; сводный Skill Library — V2 |
| Кто учится | Агент и модель с карточки (стартовая гипотеза PDF: лекции и арт — Opus) |
| Learn | Только чтение, плюс WebFetch/WebSearch без вопросов. Уроки — блок `link-lessons`. До «Ready for exam» слова идут ученику (обсудить, добавить источник); новый блок заменяет кандидатов |
| Экзамен | Новая сессия специалиста: роль, skills, уроки-кандидаты, rubric, задача и референсы — без лекции. Доступ Do. Слова до оценки — правка в той же сессии (Revise) |
| Rubric | Секция `## Rubric` файла роли (у 3D Artist — форма: силуэт, пропорции, переходы, «примитивность», иерархия деталей, соответствие референсам, engine-ready). Без секции — общая: Technical, Fidelity, Result, Engine-ready |
| Оценки | Самооценка агента по rubric (блок `link-exam`) — критика перед сдачей; решает оценка пользователя 1–5: 4–5 Pass, 1–3 Fail |
| UNVERIFIED | Экзамен без изменённых файлов не проходит при любой оценке; шаг Asset без файлов не засчитывается работнику |
| Promote | В сессии экзамена, effort low: общий урок — в общую копию skill пакета (`.agents/skills/<skill>/`), проектный — в `.agents/skills/<pack>-project/`; затем «Share with all games» и `share-packs` |
| Не в MVP | Skill Evidence по поднавыкам, Visual Critic, Reference Board, A/B — V2; генерация видов и библиотека ассетов — V3 |

## 2. Как устроено

```
карточка: специалист + Train + тема/ссылки/PDF ──► Learn (только чтение, WebFetch)
      └─► блок link-lessons ──► карточка Lessons: ○ кандидаты · ✓ доказанные   (слова → ученику)
                 ▼ Ready for exam
      слова пользователя = экзамен (задача + refs) ──► новая сессия специалиста: уроки + rubric + stage-gates, Do
                 ▼ блок link-exam: применённые уроки, самооценка, review sheet
      оценка 1–5 (слова до неё → Revise в той же сессии)
         0 файлов ─► UNVERIFIED     1–3 ─► Fail: уроки остаются кандидатами
         4–5 ─► Pass: применённые уроки ✓ ─► Promote (та же сессия, low) ─► Share with all games
                 ▼
      кандидаты остались ─► следующий экзамен; нет ─► Finish
```

## 3. Работы

| # | Работа | Что получает пользователь |
|---|---|---|
| TR.0 | Этот план | Решения и этапы |
| TR.1 | Модель и разбор | Учебная задача хранит источники, уроки, экзамены, оценки; блоки `link-lessons`, `link-exam` |
| TR.2 | Поток в Studio | Train на карточке, Lessons вместо Plan, Ready for exam, оценка 1–5, Promote |
| TR.3 | UNVERIFIED | Ложный «Done» шага Asset не портит статистику работников |
| TR.4 | Blender-художник | Stage-gates, обязательный review sheet одной командой, rubric 3D Artist |
| TR.5 | V2: качество и роутинг | Skill Evidence, Visual Critic, Reference Board, A/B exam |
| TR.6 | V3: фабрика ассетов | Генерация недостающих видов, библиотека ассетов и оценок, sweep вариантов |

### TR.1 Модель и разбор
- `TrainingCourse` на `AgentTaskRecord` (режим `TaskMode.Training`): тема, источники, уроки
  (текст, skill, общий/проектный, статус, экзамены/проходы), экзамены (бриф, работник, применённые уроки, самооценка,
  review sheet, файлы, оценка, итог), стадия.
- `Training`: промпты из `harness/training-learn.md`, `training-exam.md`, `training-promote.md` (правятся без
  пересборки), разбор блоков, rubric из роли, итог оценки.

### TR.2 Поток в Studio
- Галочка «Train the specialist» на карточке (взаимоисключающая с Team, нужен специалист).
- Learn: доступ Analyze, WebFetch/WebSearch разрешены. Уроки — в карточке Lessons; «Ready for exam» — в карточке
  решения; подсказка в поле ответа говорит, что следующие слова — экзамен.
- Экзамен: новая сессия, роль и skills задачи, вложения — картинками. После прогона — карточка оценки 1–5.
- Promote после Pass; затем обычное предложение «Share with all games».

### TR.3 UNVERIFIED
- `TeamRunner.After`: шаг Asset «Done» без изменённых файлов → `Unverified`, не пишется в `workers.json`, ждёт OK.

### TR.4 Blender-художник
- `blender-model`: стадии с проверкой перед переходом (reference analysis → blockout → primary → secondary →
  tertiary → game-ready), критика формы, а не наличия деталей.
- `blender-live/shots.py`: вид `34r` (rear 3/4) и look `lit|matcap|wire|uv` — review sheet одной командой.
- Роль 3D Artist: секция `## Rubric`.

### TR.5 V2 (после проверки MVP пользователем)
- Skill Evidence: `skills.json` проекта и общий — skill × работник → экзамены, проходы, средние по измерениям;
  статус Learning / Proven (3–5 подтверждённых успехов), понижение после повторных провалов.
- Visual Critic: шаг ревью Opus «Senior Art Critic» по review sheet и референсам, вслепую к работнику.
- Reference Board: вложения раскладываются по STYLE / SHAPE / DETAILS / MATERIALS / FUNCTION, агент пишет, что
  берёт из каждого — это часть брифа и критериев.
- A/B exam: один spec двум работникам, слепой выбор A/B или 1–5, победитель — по skill, не глобально.
- Карточка специалиста: уровень, последний экзамен, слабые места; Skill Library.

### TR.6 V3
- Генерация недостающих видов концепта/референсов; общая библиотека ассетов с оценками; sweep вариантов, где
  вариативность дешевле ручной итерации; image→3D как blockout и пропсы, не замена Blender-агента для hero-ассетов.

## 4. Риски
- Экзамен на арт стоит дорого (Opus, долгий прогон): экзамен — настоящая задача проекта, а не учебная, чтобы работа
  не пропадала.
- Самооценка агента завышена — поэтому решает только оценка пользователя; самооценка видна рядом, для калибровки V2.
- Уроки размножаются: не больше 8 за учёбу, только то, что исправляет реальные ошибки и проверяемо на практике.
