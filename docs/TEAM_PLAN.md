# LINK Team и пакеты инструментов — план работ

Основа — PDF пользователя «LINK Agent Studio: оставшиеся улучшения и стратегия моделей» (08.10, ревью ветки
`claude/relaxed-mayer-pauwsg`) и его ответы от 08.10. План идёт поверх [STUDIO_PLAN.md](STUDIO_PLAN.md): S.1–S.13
сделаны; облачная сессия добавила `[O.A]` Team core, `[U]` Studio redesign и `[B]` Agent wiring.

## Коротко

- **Команда.** Большую задачу ведущий (Opus) раскладывает на шаги, Link отдаёт каждый шаг своему работнику и
  показывает, кто что делает и почему. Шаги — обычные сессии Claude Code или Codex, по очереди, не встроенные
  субагенты: Link видит каждый прогон (токены, время, diff), а работа делится между двумя подписками.
- **Модели.** Strong — Claude Opus 5.5, Standard — Codex GPT-6-Astra, Light — Claude Haiku 5.5; на лимите — другая
  подписка того же уровня (Light: GPT-5.6-Luna). Версии Claude не зашиты: семейство + фактическая модель из прогона.
- **Пакеты инструментов.** Ядро Link (правила, команда, роли-профессии без движка) → пакеты инструментов, общие для
  всех игр (unreal, unity, godot, blender, cascadeur, …) → проект (папка игры: свои skills, тесты, проверка, MCP).
  Задача видит ядро, пакеты своего проекта и только свою папку.

## 1. Решения пользователя (08.10)

| Вопрос | Решение |
|---|---|
| Когда команда | Link решает сам по брифу: маленькая задача — один агент; большая — сначала план ведущего, пользователь видит шаги и жмёт Run team. На карточке можно переключить Solo / Team |
| Модели уровней | Opus / Codex Astra / Haiku 5.5; Luna — подмена Haiku, когда лимит Claude исчерпан |
| Бесплатный облачный работник | Не нужен (Antigravity не делаем). Custom (GLM и т. п.) остаётся выбором на карточке, но не в цепочке по умолчанию |
| Где общие пакеты | Своя папка пакетов (по умолчанию `%USERPROFILE%\LinkPacks`, меняется в Settings; может быть git-репо). Link кладёт туда встроенные пакеты, не перезаписывая правки |
| Урок про инструмент | Сначала в skills проекта; в общий пакет — только после OK пользователя (Link показывает разницу) |
| Арт | Внутри папки игры: одна рабочая папка на проект, мульти-workspace из PDF не нужен |
| Несколько инструментов одного вида | Проект включает несколько пакетов; skills по брифу и роли, как сейчас; на карточке видно и снимается |

Из PDF не берём: Antigravity и Provider Registry вместо enum (нового провайдера нет), Project → много Workspace
(арт в папке игры), A/B-набор из 15–30 эталонных задач (статистика копится в `workers.json` на живых задачах),
Remote и live steer — как и раньше, после проверки Studio.

## 2. Как устроена команда

```
бриф ──► Link: маленькая? ──да──► один агент (как сейчас)
             │нет
             ▼
   Strong, только чтение: harness/team-task.md + сводка workers.json ──► блок link-plan (2–8 шагов)
             ▼
   WorkerRouting: шаг → уровень → работник + причина словами
             ▼
   План в Studio: шаг · роль · работник · почему; работника можно сменить, шаг убрать ──► Run team
             ▼
   по шагу за раз: новая сессия работника = состояние задачи + шаг + «Handed over» прошлого шага,
   роль и skills шага, доступ Do ──► проверка проекта ──► Done
     check: true (вид модели, анимация) ──► ждёт OK пользователя
     провал ──► один повтор с причиной ──► уровень выше ──► Strong провалил ──► стоп, решает пользователь
             ▼
   итог задачи; workers.json: done/failed по виду шага и работнику
```

Почему по очереди: шаги правят одно дерево и один редактор; параллельно — позже и только для чтения.

### T.0 Доделать облачное
- Пересобрать Link (`rebuild-link`), когда в нём не работает агент; до того — тесты в scratchpad.
- `drive-link/newtask.ps1` ищет `TaskTabButton`, которой больше нет: открывать Studio через `StudioButton`, как
  `handoff.ps1`.
- Тесты 08.10 под нагрузкой (Unreal + Codex, CPU 96 %): agent-проверки дольше 20 с, companion (headless Edge) — «no
  results». Повторить в тишине; если agent-проверки и там дольше 20 с — найти медленный тест, не поднимать таймаут.
- Пользователь смотрит Studio и называет правки (→ T.5).

### T.1 Модели без зашитых версий
- `ClaudeCodeProvider.Models`: семейства `opus`, `sonnet`, `haiku`, `fable` («Opus — latest») первыми, затем полные
  id для закрепления. Claude Code 2.1.286 знает алиасы, но в нём нет `claude-haiku-5-5`: алиас `haiku` у него — 4.5.
  Поэтому Haiku 5.5 — полным id, пока CLI не догонит; Light по умолчанию — `claude-haiku-5-5`.
- Фактическая модель — из `system/init` (`model`, уже читается): в строке прогона и в Harness. Если для семейства она
  сменилась с прошлого раза — одна строка в задаче «Haiku latest: claude-haiku-5-5 → …». Последняя увиденная —
  в `settings.json` (по семейству).
- Сохранённый `claude-haiku-4-5-20251001` → `claude-haiku-5-5` в `Normalize()`.
- Бюджет контекста в показе и в Harness: `min(бюджет, окно модели)`; окно Codex — `context_window` из
  `models_cache.json` (272k у текущих моделей при бюджете 450k).

### T.2 Распределение команды
- `WorkerRouting.Workers` по умолчанию: Strong — Claude Code Deep (Opus; effort от Auto Effort: medium для обычной
  задачи — опыт пользователя и знакомых 08.10: Opus medium дёшев и силён; high/xhigh — дизайн, неясный баг, провал),
  Standard — Codex Standard (модель
  конфига Codex, medium), Light — Claude Code Light (`ClaudeLight` = Haiku 5.5, low; старое умолчание Sonnet
  переезжает, выбранное пользователем — нет). Custom из цепочки убрать.
- Подмена на лимите или «не настроен» — в том же уровне другой подпиской (сейчас так только у Strong): Light Claude ↔
  Codex Light (`CodexLight` = `gpt-5.6-luna`), Standard Codex ↔ Claude Sonnet. Подъём уровня — только после провала.
- Quality First (по умолчанию): статистика проекта не понижает уровень сама, только подсказка в плане «Haiku: 9 of 10
  code steps here». `TeamSettings.AutoLower` (выкл.) — понижать доказанное автоматически. Asset и Design не ниже
  Standard (уже есть).
- Повтор: один тем же работником с причиной провала, затем уровень выше.

### T.3 Запуск команды
- Когда: `StepKinds`/`ProjectRoles.SuggestAll` по брифу — два и больше специалиста или видов работы, или явное «и
  потом» → карточка ставит **Team** (чип, переключается на Solo). `TeamSettings.Enabled` выключает предложение.
- План: прогон Strong в режиме чтения с `team-task.md` и `WorkerEvidence.Summary` → `TeamPlan.Split` → шаги через
  `WorkerRouting.Route` → `AgentTaskRecord.Team`, `Mode = Team`.
- Показ: список шагов в треде (как план S.13): номер, медуза роли, текст, работник и причина, статус; у шага —
  смена работника (выпадающий) и ×; кнопки **Run team** и **Solo instead**.
- Исполнитель — новый `Services/TeamRunner` (логика без UI): шаг → `AgentCoordinator.RunAsync` с задачей шага
  (`TaskState` + текст шага + `HandedOver` прошлого, роль и skills шага, Do). После шага с кодом — проверка
  проекта; `TeamPlan.HandedOver` из ответа; статусы и `WorkerEvidence` записываются. `check: true` → `AwaitsOk`:
  **OK** / **Redo** со словами. Stop останавливает шаг и команду; открытая заново задача продолжает с первого
  незавершённого шага.
- В строке задачи — расход по шагам и итог «team: 5 steps, Claude 38 %, Codex 12 %» (`TaskMetrics` уже считает).

### T.4 Пакеты и роли без движка
- Папка пакетов: `AgentSettings.PacksFolder` (по умолчанию `%USERPROFILE%\LinkPacks`). Встроенные пакеты лежат в
  `docs/harness/packs` и копируются к Link.exe; при старте Link досылает в папку только отсутствующие файлы.
- Пакет: `<pack>/pack.md` (name, description, detect — признаки в папке), `skills/<name>/SKILL.md`,
  `roles/<role>.md` — добавка к телу роли для этого стека.
- Признаки: `*.uproject` → unreal; `ProjectSettings/ProjectVersion.txt` → unity; `project.godot` → godot; `*.blend` →
  blender; `*.casc` → cascadeur; `.git` → git; `P4CONFIG`/`.p4config` → perforce.
- Стек проекта: `LinkProject.Packs` (null — автоопределение по папке); в заголовке Studio «BigSteps · Unreal +
  Blender + Perforce», чипы включения в настройках проекта.
- Роли: тело встроенных ролей — без движка; строки про Unreal/Blender уходят в `packs/unreal/roles/*.md` и
  `packs/blender/roles/*.md`. `unreal-developer` → `gameplay-developer` (старый id в старых задачах читается).
  `skills:` роли — без префикса движка или с несколькими вариантами; берутся те, что есть.
- Skills задачи: skills включённых пакетов + skills проекта; одноимённый skill проекта перекрывает пакетный.
  Пакетные skills вне рабочей папки: Claude Code — `--add-dir <PacksFolder>` (чтение), Codex читает вне папки сам;
  сверить в первом живом прогоне.
- Урок про инструмент: правила агента — менять skill пакета копией в проект (`.agents/skills/<name>`), не саму
  папку пакетов. После задачи, дошедшей до Done, Harness показывает «blender-anim: the project's copy differs — Share
  with all games» → diff → по OK Link пишет копию в пакет и убирает её из проекта.
- MCP — по-прежнему только `.mcp.json` проекта; пакет может нести шаблон, Link предлагает добавить (позже).
- BigSteps: его общие Unreal/Blender skills переносятся в пакеты только с OK пользователя (Perforce, его changelists).

### T.5 Studio UI
- По словам пользователя после T.0. Направление прежнее: как приложение Claude — сайдбар задач, колонка чтения,

## 4. Риски

- Haiku и Codex на Light могут чаще проваливаться в Unreal и Blender — поэтому Asset/Design не ниже Standard, один
  повтор и эскалация, а понижение по статистике только подсказкой.
- Шаг без памяти прошлых шагов теряет мелочи: `TaskState` и строка «Handed over» обязательны; ведущий пишет шаги
  самодостаточными (`team-task.md`).
- Пакеты вне папки проекта: права чтения у CLI проверить вживую до переноса skills BigSteps.
