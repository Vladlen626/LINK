# LINK — компаньон и рабочее место агента: план работ

Основа — запрос пользователя от 03.10.2026 (пересказан в §1, чтобы работать без того чата) и его решения (§3). Работа
идёт этапами из [`docs/stages/`](stages/) (§2); этот файл — общий план и источник решений для агентов этапов. Текущее
состояние — [PROJECT_CONTEXT.md](../PROJECT_CONTEXT.md), база плана — коммит `910e2af`. Внешние факты — на 03.10.2026,
перед этапом перепроверить по §10.

## Коротко

- LINK остаётся маленьким компаньоном поверх любого приложения и по нужде раскрывается в рабочее место агента — в той
  же боковой панели, без отдельного тяжёлого окна.
- Для пользователя три слова: **Проект** (где), **Разговор** (ChatGPT — голова, входит в подписку), **Задача** (агент —
  руки, тратит лимиты). Каждая кнопка называет, куда уйдёт и что произойдёт.
- Шесть этапов: **1 экран → 2 карточка → 3 задача → 4 чат ↔ агент → 5 модели и передача → 6 поправки без остановки**
  (по желанию). Один этап — один новый чат; чат-координатор проверяет итог и говорит, можно ли дальше.
- Приоритеты пользователя: простота и лёгкость → понятный UI → надёжный экран → контроль над агентом → Chat ↔ Agent →
  передача Claude ↔ Codex → экономия usage.

## 1. Запрос пользователя (03.10)

- Быстрый ненавязчивый помощник поверх игр, Unreal, Blender, браузера, видео или просто разговора: быстро понимает
  контекст, экран и вопрос, не уводя в отдельную тяжёлую среду.
- Пересмотреть весь UI/UX, не только Agent: проще и предсказуемее, меньше неочевидных стрелок и скрытых действий,
  ясные состояния; всегда понятно, куда уйдёт сообщение, что сейчас видит LINK и что будет после нажатия.
- Надёжный захват текущего экрана, окна, монитора — и в fullscreen-приложениях и играх, где LINK сейчас иногда
  ошибается; пользователь всегда понимает, что увидит модель.
- Agent: одна понятная задача с непрерывной историей вместо россыпи запусков Claude и Codex. Всегда видно: кто
  работает, над чем, что уже сделал, что делает сейчас, какой контекст LINK ему передал, куда уйдёт следующий
  комментарий, сколько usage потрачено.
- Сообщение во время работы агента — по умолчанию поправка текущей задачи, а не неожиданный новый запуск. Stop,
  Continue, New task, Restart и Hand off — очевидно разные действия.
- Плавная передача между Claude и Codex одной понятной командой почти с того же места: новый агент получает цель,
  состояние проекта, изменения, проверки и компактный handoff, а не изучает всё заново. Передача и между моделями —
  ради экономии токенов (добавлено в ответе на план).
- Естественный путь: обсудил идею с ChatGPT → сформировал решение, дизайн или документ → посмотрел, что LINK
  собирается передать → отправил агенту → наблюдаю и поправляю → при нужде передаю другому → результат возвращается в
  обсуждение. Chat и Agent — не два изолированных мира; передаваемый контекст контролирует пользователь.
- Использовать то, что есть (состояние проекта, карта, skills, обучение агента, проверки, история сессий, цифры
  usage, харнесс), но не считать неприкосновенным: упрощать, объединять, переделывать, где это заметно лучше.
- Не swarm и не максимальная автономность: на подписках Claude и ChatGPT по ~$20 важнее один хорошо управляемый агент,
  хороший контекст, минимум лишнего перечитывания и лёгкое продолжение другим агентом.

## 3. Решения (03.10)

- Всё из §1 принимается, с уточнениями:
  - «Рабочее место» — вкладка Task боковой панели, не IDE: без дерева файлов, редактора, diff-вьюера и терминала;
    файлы открываются в редакторе пользователя или в Explorer. Окно Console остаётся для сырого вывода CLI.
  - Передача — одной командой, но никогда сама: другой агент тратит другую подписку. LINK только предлагает.
  - Итог задачи возвращается в обсуждение готовым чипом, который можно убрать; сам в ChatGPT LINK не пишет.
  - Usage для подписки — проценты окон 5 часов и недели и токены задачи; $ по ценам API — только в подсказке. Цифр
    ChatGPT взять негде.
  - Одна задача агента за раз; субагенты выключены, как сейчас.
- Windows.Graphics.Capture — да: целевая платформа с Windows SDK (проекция ~25 МБ на диске, грузится при первом
  захвате). Других новых зависимостей нет.
- Маршрут Direct уходит из выбора: всё, что LINK добавляет к вопросу, — видимые чипы с ×; «Only my text» отправляет
  без них (то же, что сегодняшний Direct). Адресатов два: ChatGPT и агент.
- «Текущая задача» и «Состояние проекта» — одна заметка проекта; её первая строка — фокус, он виден в карточке.
- Незакоммиченная работа (передача v1, Console, MCP для Codex, путь к `claude.exe`) проверена — сборка 0/0, 589
  проверок — и закоммичена: `910e2af`.
- Модели: уровни Light / Standard / Deep у каждого агента, смена модели в той же сессии, план сильной моделью и работа
  обычной, «Escalate» после провала, свои ответы LINK (карта, skill, заметка Start over) — на Light (§6.5).

## 4. Как это выглядит

### 4.1 Карточка (сверху вниз)

1. Заголовок: LINK, проект ▾ и точка ChatGPT; **пилюля агента**, пока есть задача (`Claude · 4:12`, `Claude needs
   you`, `Claude done`) — клик открывает вкладку Task; панель; Hide.
2. **Чип проекта** — первая строка заметки (фокус); × убирает заметку из одного вопроса, клик правит её в панели.
3. Поле вопроса и кнопка, которая называет адресата: `→ ChatGPT` или `→ Claude task` (второе открывает карточку
   задачи, ничего не запуская).
4. Строка выбора: `To: ChatGPT ▾` (ChatGPT или агент проекта), уровень `Normal ▾`, `Conversation`.
5. **Строка Sees** — что увидит модель: миниатюра и цель (`Blender · window · fresh frame on send`, `Monitor 2`,
   `Region`, `Nothing`); ▾ — бывшее меню Screen. Заменяет кнопку Screen с точкой и панель превью.
6. **Чипы** того, что уйдёт: `Blender · <title>` (приложение и окно), `Clipboard · 12 lines`, `Task result` и т. п.;
   × — убрать из одного вопроса; `Only my text` — отправить без всего, что добавляет LINK.
7. Кнопки Voice и Clipboard.
8. Ответ: в шапке — состояние, время и **«saw: …»** (миниатюра отправленного кадра и чипы); под текстом —
   `Ask again ▾` (Deeper · With a fresh screen · Only my text · Edit the question) и `→ Agent task`; Listen, Copy.
9. Строка состояния с подлежащим (§4.3).

### 4.2 Панель: вкладки Project | Task

- **Project:** заметка проекта, беседа ChatGPT (New chat, Open chat), рабочая папка (карта, skills, проверка),
  **History** — одна лента ответов и задач по времени.
- **Task:** цель; агент · модель · уровень · доступ; состояние, время и текущий шаг; **Plan** агента (2/4);
  **History** задачи (бриф, поправки, прогоны, проверки, передачи); **Changed** за всю задачу; **What Link gave**
  (читаемый бриф, Console — сырое); **Usage** (токены задачи, окна лимитов); поле ответа; действия (§4.4).
- Пусто: «No task. Ctrl+Enter in the question, or → Agent task under an answer».

### 4.3 Состояния и слова

Одна строка состояния и иконка tray говорят одно и то же, с подлежащим: `ChatGPT is answering · 12 s`,
`Claude is working · Edit src/CameraFollow.cs · 4:12`, `Claude needs you: allow npm test`,
`Claude hit its 5-hour limit, resets 15:45`, `Done`. Никаких «Working…» без того, кто работает.

### 4.4 Действия

| Действие | Где | Что происходит | Сессия |
|---|---|---|---|
| Send to ChatGPT | карточка | вопрос с видимыми чипами — в связанную беседу | — |
| → Agent task | под ответом, `Ctrl+Enter` | карточка задачи с брифом; ничего не запускается | — |
| Run | карточка задачи | новая задача, новая сессия | новая |
| Correct (`Enter` во время работы) | поле в Task | этап 3: агент останавливает шаг и продолжает с поправкой; этап 6: поправка доходит на границе шага | та же |
| After this (`Tab` во время работы) | поле в Task | слова ждут конца прогона и продолжают ту же сессию | та же |
| Reply (`Enter` после прогона) | поле в Task | та же сессия продолжается словами | та же |
| Stop | Task | сразу; сделанное остаётся, задача открыта | — |
| Start over | Task | новая сессия того же агента с заметкой, что пробовал | новая, та же задача |
| Hand off ▾ | Task | другой агент — новая сессия с брифом (превью); другая модель того же агента — та же сессия | по пункту |
| Escalate | Task, после провала | та же сессия на уровне Deep | та же |
| Return to Claude | Task, после передачи | сессия первого агента со сводкой того, что сделал второй | первая |
| Continue at 15:45 | Task, на лимите | та же сессия продолжится после сброса окна | та же |
| Finish | Task | задача закрыта и остаётся в History | — |
| Undo changes | Task ⋯ | откат всей задачи (git или копия), после подтверждения | — |
| Save as skill, Discuss in chat, Console | Task ⋯ | как сейчас; Discuss in chat — итог чипом в карточку | — |

### 4.5 Что видит модель

- Всё, что уходит с вопросом, видно до отправки: строка Sees и чипы. Строки «Application» и «Window» больше не
  уходят молча — это чип.
- Ответ показывает, что ушло на самом деле («saw: …», миниатюра — клик открывает PNG).
- Задача показывает, что LINK отдал агенту (What Link gave); Console — сырой stdin и вывод.
- Захват — только по действию или включённому режиму, как сейчас. Миниатюра в Sees при авто-кадре — кадр в памяти,
  не сохраняется и никуда не уходит; при отправке снимается свежий.

## 5. Практики, на которые опираемся

- **Видимый индикатор того, что видит ИИ.** Copilot Vision в Windows обводит общее окно оранжевой рамкой; ChatGPT
  desktop пишет над полем, с каким приложением работает. → Строка Sees, чип приложения, «saw: …», короткая оранжевая
  рамка вокруг снятого окна (§6.1).
- **Оверлей в игре не мешает.** Виджеты Xbox Game Bar закрепляются поверх игры и пропускают клики; компактно, без
  фокуса. → Окно без активации над fullscreen, голос вместо набора, click-through уже есть.
- **План до действия, живой список шагов, diff первым, стоп, который действительно стоит, честный счётчик токенов** —
  общие паттерны агентных интерфейсов 2026 (Claude Code plan mode и todo, Devin и Jules — правка плана, Cursor — diff
  как разговор). → Plan агента в Task, изменения со счётом строк, Stop, токены и окна лимитов.
- **Steer и queue — разные намерения.** Codex CLI: `Enter` вклинивает слова в текущий ход, `Tab` ставит их после.
  → Correct и After this (§4.4).
- **Лимиты подписки на виду.** `/usage` в Claude Code и CodexBar показывают окно 5 часов и неделю с временем сброса.
  → Usage в Task, подсказка пилюли, Settings.
- **Передача — целевая выжимка, а не пересказ всего.** Handoff в Amp: цель новой нити, выжимка нужного из старой и
  список файлов (позже Amp вернулся к автосжатию внутри одной нити — модели хорошо его держат; передача между разными
  агентами — другая задача). → Бриф из истории задачи с превью (§6.7); внутри одного агента сжатие делает сам CLI.
- **Модели по фазам и каскад.** `opusplan` в Claude Code: Opus планирует, Sonnet пишет код. Каскад «дешёвая модель,
  потом сильная» выгоден, только пока эскалаций мало. → План на Deep, работа на Standard; Escalate после провала;
  уровень задачи выбирает пользователь, LINK не начинает дёшево сам.

## 6. Контракты и техника

### 6.1 Захват

- `Windows/WindowCapture` (Win32 и WinRT — в `Windows/`): окно (`IGraphicsCaptureItemInterop.CreateForWindow`) и
  монитор (`CreateForMonitor`) через Windows.Graphics.Capture; D3D11-устройство и
  `CreateDirect3D11DeviceFromDXGIDevice` — P/Invoke в `NativeMethods`; `Direct3D11CaptureFramePool.CreateFreeThreaded`,
  один кадр с таймаутом ~1 с, `IsCursorCaptureEnabled = false`, `IsBorderRequired = false`, где свойство есть
  (`ApiInformation`; по отчётам, на Windows 11 26200+ работает и без пакета MSIX — проверить). Кадр → `Bitmap` для
  `ScreenshotHistoryService`. Ни постоянной сессии захвата, ни устройства на весь день, если замер не покажет нужды.
- Цепочка: WGC → для окна `PrintWindow(PW_RENDERFULLCONTENT)`, для монитора — нынешний `CopyFromScreen` → кадр почти
  весь чёрный (проверка по выборке пикселей) — не прикладывать молча: статус «The game draws in exclusive fullscreen:
  switch it to borderless, or ask by voice».
- Окно снимается WGC без того, чтобы прятать LINK: оверлей в кадр окна не попадает. `WDA_EXCLUDEFROMCAPTURE` не
  работает для окон WPF с `AllowsTransparency` (`UpdateLayeredWindow`), поэтому для монитора, всего экрана и области
  LINK по-прежнему прячется на миг. После захвата LINK активируется, только если был активен до него (сейчас
  `PresentAfterCapture` активирует видимый LINK и уводит фокус у игры).
- Fullscreen: `SHQueryUserNotificationState` (`QUNS_RUNNING_D3D_FULL_SCREEN` — эксклюзивный, `QUNS_BUSY`) и геометрия
  рабочего окна (покрывает монитор, без рамки). Над fullscreen LINK показывается без активации там, где набор не
  нужен (захват, push-to-talk, отправка); поверх эксклюзивного fullscreen карточку не показывать вовсе — ответ голосом
  и уведомлением.
- `[Capture]` в `link.log`: способ, что (окно, монитор, область), размер, мс, чёрный ли кадр, причина запасного пути;
  без заголовков окон.
- Новая настройка-hotkey «Ask about the screen (hold)»: держишь — говоришь — отпускаешь → вопрос уходит в Chat со
  свежим кадром рабочего окна, ответ звучит голосом; это явное действие, как push-to-talk.

### 6.2 Чипы и запрос

- Всё, что LINK добавляет в Chat, — элементы context stack со своим типом и меткой: заметка проекта (`ProjectNote`,
  бывшие `ProjectState` и «Current task»), приложение и окно (`Application`), авто-кадр (строка Sees). Убрать на один
  вопрос — общий механизм (сегодня он есть у состояния проекта: убирается на один запрос и возвращается после ответа).
- «Only my text» = сегодняшний Direct: только текст и приложенное пользователем, без строк LINK, подсказки уровня и
  авто-кадра. `RequestRoute.Direct` остаётся внутренним намерением снимка (перенаправление «Only my text» им и
  пользуется), из выбора маршрута уходит; сохранённый `Route: Direct` грузится как Chat.
- Заметка проекта: `ProjectState` хранит весь текст; `Normalize()` переносит непустой `CurrentTask` первой строкой и
  очищает его; старые `projects.json` грузятся.

### 6.3 Запись задачи

- `AgentTaskRecord` в `Projects\<id>\agent-tasks.json` (20 последних, `AtomicJsonFile`): id, цель (заголовок), бриф —
  текст, который LINK отдал первым, рабочая папка, создана, статус (`Running`, `NeedsYou`, `Done`, `CheckFailed`,
  `Stopped`, `Finished`), прогоны (агент, модель, уровень, доступ, session id, начало, длительность, итог, цифры),
  лента (время, вид: `Brief`, `Correction`, `Queued`, `Run`, `AgentSaid`, `Check`, `HandOff`, `ModelSwitch`,
  `Limit`, `Stopped`, `Finished`; текст), изменённые файлы за всю задачу, последний план агента, последние 40 шагов
  Activity.
- Все прогоны задачи пишут в одну запись: Run, Reply, Correct, After this, Start over, Plan → Run the plan, возвраты
  проверки, передачи и смены модели. Новая задача — только из карточки (Run).
- `agent-sessions.json` → задачи из одного прогона (миграция при чтении, файл остаётся до следующей записи).
  AGENT SESSIONS в панели уходят: History показывает задачи.

### 6.4 План агента

- Claude Code: `TodoWrite` (`todos[{content, status, activeForm}]`); в бинарнике 2.1.286 есть и `TaskCreate` /
  `TaskUpdate` (флаг `CLAUDE_CODE_ENABLE_TASKS`) — разобрать оба, что встретится в `-p`, по живой фикстуре.
- Codex: элемент `todo_list` (`items[{text, completed}]`) в `item.started/updated/completed`.
- Новый `AgentEventKind.Plan`; в Task — список с отметками и счёт «2/4»; в записи задачи — последний план.

### 6.5 Уровни и модели

- `AgentLevel { Light, Standard, Deep }` → (модель, effort) у каждого агента в Settings → Agents; значения — из
  списков, которые LINK уже читает (у Claude — Opus 5.5, Fable 5.1, Sonnet 5.5, Haiku 4.5; у Codex —
  `models_cache.json`, сейчас gpt-6-astra, gpt-5.6-sol / terra / luna, gpt-5.5). Значения по умолчанию предложить
  пользователю в начале этапа 5. Карточка и Task показывают уровень вместе с моделью и effort (`Deep · Opus 5.5 ·
  high`).
- Смена модели в той же сессии: Claude `--resume <id> --model <m>`, Codex `exec resume` с моделью через `-c`/`-m`
  (проверить `--help`); в ленте — строка `ModelSwitch`; один промах кэша — честно в подсказке.
- Plan first идёт на Deep, Run the plan продолжает ту же сессию на Standard (как `opusplan`, но у обоих агентов);
  настройка, по умолчанию включена.
- Escalate: после двух красных возвратов проверки или метки петли — та же сессия на Deep. Сам LINK не начинает дёшево.
- Свои ответы LINK — карта, skill, заметка Start over — на Light по умолчанию.

### 6.6 Usage и лимиты

- Токены прогона — как сейчас (`AgentStats`); у задачи — суммы по агентам. Codex при resume отдаёт итог всей сессии:
  LINK хранит прошлый итог сессии и считает разницу.
- Окна подписки:
  - Claude Code в stream-json присылает `{"type":"rate_limit_event","rate_limit_info":{…}}` при смене данных
    (в 2.1.286: `status`, `resetsAt`, `rateLimitType` — `five_hour`, `seven_day`; `isUsingOverage`;
    `utilization` — если есть). Поля сверить по живой фикстуре.
  - Codex пишет в журнал сессии `~/.codex/sessions/YYYY/MM/DD/rollout-*-<session>.jsonl` строки `token_count` с
    `rate_limits` (`limit_id: "codex"`, `primary` и `secondary`: `used_percent`, `window_minutes`, `resets_at`).
    LINK после прогона читает из журнала своей сессии только последнюю такую строку — ни текста, ни копий.
- Последнее известное — `%LocalAppData%\Link\agent-limits.json` с временем; показ: Usage в Task, подсказка пилюли,
  Settings → Agents, карточка задачи перед Run. Старые данные помечены временем («at 14:02»).

### 6.7 Бриф передачи

- Из записи задачи: цель и бриф; все поправки пользователя по порядку; последний план агента (сделано, осталось);
  изменённые файлы с `+/-` (`git diff --numstat` от «до задачи»; без git — список); последняя проверка (команда,
  итог, ~20 последних строк); последние слова агента; указатели: `docs/map.md`, skills, `.mcp.json`; правило
  «сначала посмотри изменения, сделанное не переделывай». Бюджет ~1,5k токенов: сокращать шаги, а не цель и
  поправки.
- Превью: Hand off → карточка с брифом (правится), агент и уровень получателя, кнопка Hand off.
- Return to Claude: `--resume` его сессии со сводкой того, что сделал второй (файлы, проверка, его последние слова).
- Continue at 15:45: таймер до `resetsAt` + 1 мин в живом LINK, отменяемый; в ленте — `Limit`.

### 6.8 Chat ↔ Agent

- `→ Agent task` на ответе ChatGPT: бриф = выделенный текст, или блок `link-task`, если он есть, или весь ответ; плюс
  вопрос («From the discussion: …») и чипы снимка. Карточка задачи показывает бриф целиком и даёт его править, чипы —
  с ×.
- Блок `link-task` в инструкциях ChatGPT (`docs/harness/chat-instructions.md`, по-английски): когда обсуждение пришло
  к работе для агента — в конце ответа fenced-блок `link-task` с Title, Goal, Decisions, Done when, Where (если
  известно). Рендерер ответа рисует его карточкой с кнопкой `Give to agent`.
- Итог задачи (`Done`, `CheckFailed`, `Stopped`) сам ложится чипом `Task result` в следующий вопрос Chat: цель, итог,
  файлы с `+/-`, проверка, что осталось. Discuss in chat добавляет по желанию diff (до ~30 КБ, иначе — `--stat` и
  пометка). ChatGPT в подписке — дешёвый ревьюер; агент — руки.

### 6.9 Поправки без остановки (этап 6)

- Claude Code: hook `PostToolUse` через `--settings` (JSON строкой; есть в 2.1.286): команда печатает
  `{"hookSpecificOutput":{"hookEventName":"PostToolUse","additionalContext":"…"}}`, если для прогона лежит файл
  поправки, и удаляет его. Проверить, какой оболочкой Claude Code на Windows запускает hooks и сколько это стоит на
  каждый вызов инструмента.
- Codex: `codex app-server` (JSON-RPC по stdio) вместо `exec --json`: `thread/start` или `thread/resume`,
  `turn/start`, события → те же `AgentEvent`, `turn/steer {threadId, input, expectedTurnId}` для поправки,
  `turn/interrupt` для Stop (kill — запасной), лимиты из уведомлений вместо журнала. Путь `exec` остаётся запасным за
  настройкой, пока app-server не проверен.

## 8. Правила для агентов этапов

- Прочитать `CLAUDE.md`, этот план (разделы, указанные в этапе) и `PROJECT_CONTEXT.md` (только нужные разделы).
- Перед работой — `git status`, `git log --oneline -20`: шаги с коммитами `[N.x]` уже сделаны, продолжить с первого
  несделанного. Коммит на шаг: `[N.x] …`, явные пути, сообщение по-английски, `git commit -F -` из Bash.
- `dotnet build Link.sln -c Release` — 0 warnings, 0 errors; тесты — `tests/Link.Desktop.Tests` (без фреймворка,
  консольный раннер); пока Link пользователя открыт — сборка и тесты в scratchpad (skill `rebuild-link`).
- Живые прогоны `claude` и `codex` тратят лимиты пользователя: только с его слова, 1–2 коротких на агента для
  фикстур. Иначе — фикстуры и фейковый `.cmd` CLI в scratchpad; данные пользователя (`%LocalAppData%\Link`) — только с
  точной копией и возвратом.
- UI проверяет пользователь: этап кончается отчётом (коммиты с SHA, сделано и нет, цифры) и коротким чеклистом.
  Своих UI-проверок — до ~10 минут, тестовой копией в scratchpad (свой корень данных, свой mutex, необычные hotkeys,
  без заголовка окна в промпте).
- Подписи UI — по-английски, как сейчас; README и PROJECT_CONTEXT — по-русски, только принятое и видимое
  пользователю. Рисунки README (`docs/images/*.svg`) обновлять skill'ом `preview-svg`.
- Не раздувать layered-карточку: новое — в панель; анимаций не добавлять.

## 9. Риски

- Эксклюзивный fullscreen может остаться чёрным и для WGC — честное сообщение и путь голосом, а не хуки в игру.
- Форматы CLI меняются (`rate_limit_event`, инструменты плана, журналы Codex, app-server): разбор терпимый к пропускам,
  фикстуры, тесты; не нашлось — не показывать, а не ломаться.
- Названия моделей меняются: только списки самих CLI, ничего зашитого, кроме значений по умолчанию.
- Смена модели в сессии стоит один промах кэша; бриф передачи может оказаться длиннее бюджета — замер в этапе 5.
- Карточка разрастается: каждый этап держит её высоту и число кнопок не больше, чем сейчас.
